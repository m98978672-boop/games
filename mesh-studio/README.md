# MESH STUDIO — наш редактор 3D-моделей

Раздел `mesh-studio/` — это редактор моделей, который работает на **нашем**
движке `ratcore` и не требует ни установки, ни интернета, ни видеокарты.
Открывается как обычная страница, в том числе с `file://`.

Это не «ещё один просмотрщик»: геометрию считает движок, а вы управляете
сценой — добавляете формы, красите, отменяете действия и сохраняете проект.

## Что умеет

**Семь примитивов.** Куб, сфера, цилиндр, конус, тор, плоскость и крыша.
Каждый — отдельный инструмент движка `build.primitive`, поэтому модель сразу
проходит проверку меша и попадает в сцену движка через `build.placeEntity`.

**Тело вращения.** Вы задаёте профиль `x, y; x, y; …` — редактор крутит его
вокруг вертикальной оси через `build.lathe`. Так получаются вазы, колёса,
стаканы, купола — всё, что имеет ось симметрии.

**Экструзия.** Контур `x, y; …` выдавливается на нужную высоту через
`build.extrude` с триангуляцией методом ear clipping. Контур самопроверяется:
вырожденный (все точки на одной прямой) движок отвергает с кодом `RC-201`.

**Воксельные слои.** Слоёная запись движка: `(0;0)H1()` — один воксель,
`(0;0)h3(1,0;0,1)` — наклонный слой из трёх ячеек. Заглавная `H` — строго
вертикальный слой, строчная `h` — наклонный. Редактор проверяет правило
«число пар смещения = число слоёв − 1» заранее, чтобы ошибка была понятной,
а не в виде кода `RC-303`.

**Сцена и история.** Модели видны списком, выбираются нажатием, дублируются,
перекрашиваются и удаляются. Отмена и повтор — до 60 шагов; история хранит
копии сцены, а не мутирует модели.

**Кадр.** Рисует движок: `look.at` наводит камеру, `look.capture` отдаёт
пиксели, редактор переносит их на холст. Поэтому 3D работает даже там, где
нет WebGL, — на слабых машинах и в старых браузерах.

**Сохранение.** Кнопка «Скачать проект» отдаёт JSON со всеми моделями,
цветами, позициями и операциями. Его хватает, чтобы восстановить сцену:
каждая модель описана операцией движка и её аргументами.

## Управление

| Действие | Мышь | Клавиатура |
|---|---|---|
| Вращение камеры | перетащить по сцене | — |
| Масштаб | колесо | — |
| Вид спереди / сбоку / сверху / сброс | кнопки справа сверху | `1` / `3` / `7` / `0` |
| Отменить / повторить | кнопки панели | `Ctrl+Z` / `Ctrl+Shift+Z` |
| Дублировать | кнопка панели | `Ctrl+D` |
| Удалить выбранную | кнопка панели | `Delete` |

На телефоне те же действия: перетаскивание одним пальцем вращает камеру,
двумя — масштабирует. Кнопки увеличены под палец, панели уходят под сцену.

## Как это устроено

```
mesh-studio/
├── index.html          разметка: сцена, панели, экспорт
├── studio.css          оформление, тёмная тема, мобильная раскладка
├── studio.js           интерфейс: камера, выбор, кнопки, сохранение
├── studio.bundle.js    собранный одной строкой скрипт (для file:// и Pages)
├── core.js             операции над сценой и история (без DOM и движка)
├── engine-adapter.js   мост к движку: build.*, move.*, look.*
└── tests/
    ├── core.mjs        ядро: имена, история, разбор ввода, рецепт
    ├── engine.mjs      стык: формы, геометрия, сцена, кадр, экспорт
    └── browser.mjs     собранный бандл на минимальной странице
```

Три уровня разделены намеренно:

1. **`core.js`** ничего не знает про движок и DOM. Это чистая логика сцены:
   имена без дублей, неизменяемые операции, история с ограничением глубины,
   разбор пользовательского ввода. Тестируется в Node без заглушек.
2. **`engine-adapter.js`** знает движок, но не знает интерфейс. Он превращает
   «создай тор» в `build.primitive({kind:'torus'})` и разворачивает ответ.
   Ошибки инструмента (`ok: false`) превращает в обычные исключения с текстом.
3. **`studio.js`** только связывает кнопки и состояние. Геометрию не считает.

Благодаря такому разделению 140 проверок идут без браузера: 53 на ядре,
63 на стыке с настоящим движком, 24 на собранном бандле.

## Три ошибки движка, найденные при сборке редактора

Редактор показал то, что витрина скрывала. Все три исправлены в
`ratcore/src/assets/mesh-builder.js`.

**1. Тор был сферой.** `build.primitive({kind:'torus'})` не имел своей ветки и
проваливался в код сферы: возвращал 144 треугольника с габаритами шара
1.2 × 1.2 × 1.2. Внешне это «работает» — просто вместо кольца шар. Теперь тор
настоящий: 320 треугольников, габариты 1.56 × 0.34 × 1.56.

**2. Плоскость была сферой.** То же проваливание: `kind:'plane'` возвращал
шар. Теперь плоскость — два треугольника с нормалью вверх, высота ровно ноль.

**3. Неизвестный вид молча становился сферой.** Опечатка в `kind` давала шар
вместо ошибки. Теперь движок отказывает с кодом `RC-202` и перечисляет
доступные виды. Молчаливая подмена хуже падения: её не видно.

Отдельно поймана ловушка в самом движке: `look.capture` возвращает **тот же
буфер** пикселей при каждом вызове, поэтому следующий кадр затирает
предыдущий. Адаптер копирует пиксели сразу — иначе сравнение кадров всегда
давало бы «ноль различий», а сохранённый кадр — чужую картинку.

## Запуск и проверки

```bash
# страница: любой статический сервер из корня репозитория
python3 -m http.server 8901
# открыть http://localhost:8901/mesh-studio/

# тесты
cd mesh-studio && npm test        # ядро + стык с движком
node mesh-studio/tests/browser.mjs   # собранный бандл

# пересобрать бандл после правок studio.js
cd mesh-studio && npm run build
```

Тесты редактора входят в общий прогон `.github/workflows/validate.yml`,
поэтому сломанный стык с движком не пройдёт проверку.

## Что не сделано

Честно, чтобы не создавать ложных ожиданий:

* **Нет экспорта в OBJ.** Движок намеренно не отдаёт буферы наружу: закрытое
  хранилище мешей не даёт подсунуть неподписанную геометрию (`RC-101`).
  Обходить это ради файла `.obj` — значит ломать защиту. Сохраняется проект
  в JSON: модели, операции и аргументы, по которым сцена восстанавливается.
* **Нет редактирования по вершинам.** Вершины и рёбра не тянутся мышью:
  движок работает операциями (`build.*`), а не правкой буфера. Следующий шаг
  — операции над уже собранным мешем (`build.combine`, булевы), а не
  произвольное перемещение вершин.
* **Нет материалов и текстур.** Цвет задаётся один на модель. У движка есть
  `build.texGenerate`, но привязка текстур к граням ещё не сделана.
* **Нет импорта проекта.** JSON сохраняется, но обратное чтение пока не
  подключено к интерфейсу: операции восстанавливаются вручную.

## Связь с движком

Редактор — не отдельная поделка, а ещё один потребитель `ratcore`. Он
подключён по закону репозитория: `../shared/engine.js` до своих скриптов,
`engine-bootstrap.js` после, запись в `shared/engine-registry.json`. Проверка
покрытия (`game-base/tests/engine.mjs`) видит его наравне с играми.
