# Предложение для будущей связи с RatCore

Основание: документация RatCore из PR [#250](https://github.com/m98978672-boop/games/pull/250), commit `139e2a6b018af3c69b33d6b2c3deb748305b1d97`, `ratcore/BRIDGE.md`, `TOOLS.md` §13, `AI_CONTRACT.md` и `ALGORITHMS.md` F-63–F-65. Документы — проект, не исполняемая реализация. Они могут измениться до соединения. Не копировать файлы чужой ветки и не менять чужую ветку без отдельного решения.

## Предлагаемая граница

1. RatCore через свой будущий разрешённый интерфейс предоставляет read-only, версионированный снимок навигационной информации: узлы, допустимые направленные переходы, стоимость, метаданные проходов и единицы координат. Формат такого экспорта **ещё не утверждён**. Не читать сырые внутренние структуры и не обходить ToolGuard/BridgeGuard.
2. Адаптер, реализованный и протестированный после появления API, преобразует снимок в `createSnapshot`. Преобразование координат и размеров фиксируется явно; у RatCore в документации X на восток, Y на север, высота отдельно, у Frontline ось Y симуляции направлена вниз. В прототипе узлы пока только ID, а геометрия и перевод координат остаются задачей хоста.
3. Маршрутизатор возвращает данные маршрута и ожидаемое действие. Это не разрешение изменять мир. Хост валидирует актуальность, права, геометрию и, если надо, вызывает официальные `RatCore.tools.*`/bridge RPC. На текущем этапе ни RPC, ни рукопожатие, ни проверка прав, ни подписи или хеши не реализованы.
4. Версия включает изменения геометрии, проёмов и правил доступа. Pending-обновления делают прежний снимок невалидным ещё до завершения перестройки. Должна быть определена семантика повторов, сбоя сообщения и потери соединения. Состояние дверей перепроверяется и во время исполнения маршрута; результат поиска не является гарантией безопасного перемещения.
5. Если позднее потребуется совместимость с `nav.findPath { grid, from, to, algo, smooth } → { found, path, cost, lengthM }` из RatCore `TOOLS.md`, понадобится адаптер grid/координат, выбор алгоритма, вычисление метрической длины и проверенное сглаживание. Текущий графовый API имеет **другой контракт** и не поддерживает `jps`, `smooth` или `lengthM`.

## Минимальные условия приёмки

- Контракт согласован с реальной версией RatCore; тесты не используют подмену вместо интеграции.
- Экспорт копии/снимка и вызовы действий проходят фактическую проверку разрешений; не передаются сырые защищённые данные в обход мостов.
- Интеграционные тесты: закрытая/открытая/разрушенная дверь, изменение мира во время поиска и во время перехода, два направления, несколько агентов и обе фракции, смена цели, гибель, сохранение.
- Хост проводит непрерывную проверку столкновений с телами и стенами и обеспечивает протокол ожидания/разъезда. Только после этого можно измерять поведение и производительность в реальной игре; путём по графу эти свойства не гарантируются.
