# ARCHITECTURE — Frontline: Command

Документ описывает устройство проекта по §36 ТЗ: структура, единый Command API,
источники приказов, директивы, правила If→Then, режим «ИИ против ИИ» и то, что
отличается у фракций (и что не отличается).

> Принцип: **одна симуляция, одни правила, один путь приказа**. Игрок, автопилот и
> ИИ врага не имеют отдельных «лазейных» API. Если действие нельзя выразить
> приказом — значит, его не делает никто.

## 1. Слои и структура

```
index.html            страница: canvas + HUD + оверлей меню
style.css             оформление (импорт ../shared/theme.css)

  core/               инфраструктура, не знает про войну
    mathx.js          clamp/lerp/dist/углы/гексагональная математика

    eventbus.js       pub/sub: on / off / emit

    audio.js          WebAudio: синтез SFX по audio.json, позиционное затухание

    skills.js         дерево навыков + эквивалент прокачки для ИИ (techMods)

    ai_squad.js       FSM отряда: фазы стратегий, формации, отступление

data/                 17 JSON-конфигов (весь баланс — только здесь)

```

Правила зависимостей:

* `core/*` не импортирует `sim/*`, `render/*`, `ui/*`.
* `render/*` и `ui/*` читают состояние, но не мутируют его (кроме выбора/камеры).
* Системы симуляции не вызывают друг друга напрямую: связь через `Game` и `EventBus`.
* Один класс — одна ответственность; ни один файл не «знает всё».

## 2. Command API

Все приказы — игрока, автопилота, ИИ врага, правил и системных триггеров — идут
через `CommandAPI.issue()`.

### 2.1 Схема приказа

```js
{
  id: number,
  source: 'player' | 'autopilot' | 'enemyAI' | 'rules' | 'system',
  type: 'move' | 'attack' | 'hold' | 'capture' | 'retreat' | 'patrol' | 'escort'
      | 'build' | 'repair' | 'supply' | 'resupply' | 'recon'
      | 'directive' | 'stance' | 'disband'
      | 'create_squad' | 'reinforce' | 'place_build' | 'demolish'
      | 'build_profile' | 'produce' | 'set_autopilot' | 'upgrade',
  faction: 0 | 1,
  squadIds: number[],         // исполнители-отряды
  unitIds: number[],          // либо отдельные юниты
  target: { x, y, pointId?, sectorId?, unitId? } | null,
  params: { ... },            // специфичные для типа
  priority: number,           // 1 обычный, 2 важный
  reason: string,             // человекочитаемая причина (в журнал и в ленту)
  issuedAt, delay, deliverAt, status, accepted, result, doneAt
}
```

### 2.2 Очередь, задержка, ответ

1. `issue()` создаёт приказ со статусом `queued` и считает задержку:
   `delay = clamp(dist(исполнитель, цель) / radio.speedPxPerSec + radio.baseReaction × difficulty.reaction + rng(0..0.4), 0.2, radio.maxDelay)`.
   Правила (`source: 'rules'`) получают ×0.8 — они «заранее прописаны» в штабе.
2. `update()` каждый тик доставляет приказы, у которых наступил `deliverAt`.
3. Доставка = `Squad.receiveOrder()` или `Game.executeCommand()`.
4. Ответ всегда один из: `accepted` / `refused` / `cancelled`.
   Причина отказа попадает в `result`, в журнал и в ленту событий.
5. Любой приказ можно отменить до доставки: `cancel(orderId, by)` — статус `cancelled`.

### 2.3 Причины отказа (примеры)

| Причина | Условие |
|---|---|
| «нет живых бойцов» | у отряда не осталось юнитов |
| «нет боеприпасов» | `ammoRatio < 0.05` для атаки/захвата |
| «отряд отступает и не готов атаковать» | состояние `retreat` и HP < 50% |
| «мораль N: отказались выполнять» | мораль < 40, шанс `1 − morale/100` |
| «лимит отрядов: X/Y» | превышен лимит (растёт от городов и навыков) |
| «не хватает ресурсов: …» | нет материалов/боеприпасов/топлива |
| «здесь вода или препятствие» | точка постройки занята |
| «нет исполнителей» | приказ без отрядов/юнитов и без обработчика |
| «нет своего склада» | снабжение при отсутствии склада/базы/фабрики |

Все отказы видны игроку: тост, лента событий, журнал приказов.

### 2.4 Журнал приказов

`CommandAPI.journal` — последние 240 записей:

```js
{ t, orderId, source, sourceLabel, type, label, faction, result, reason, delay, actors }
```

HUD показывает журнал целиком: кто приказал, кому, что, принято ли и с какой
задержкой. Это же используется в тестах (`tests/logic.mjs`).

## 3. Источники приказов

| Источник | Кто отдаёт | Отличия |
|---|---|---|
| `player` | игрок через HUD/мышь/клавиши | задержка радио как у всех |
| `autopilot` | `Autopilot` для сфер игрока | включается/выключается по сферам |
| `enemyAI` | `StrategicAI` второй фракции | те же лимиты и та же задержка |
| `rules` | `RulesEngine` (If→Then) | задержка ×0.8 |
| `system` | внутренние триггеры (пополнение, сдача) | без бонусов |

В режиме «солдат» все сферы автопилота принудительно включены
(`autopilot.soldierModeForcesAll: true`) — иначе армия без командира встанет.

## 4. Директивы

Директива — приказ типа `directive`, который отряд выполняет сам:

```js
api.issue({
  source: 'player',
  type: 'directive',
  faction, squadIds,
  target: { x, y, pointId? , sectorId? },
  params: {
    goalType: 'capture' | 'hold',   // что считать выполненным
    strategy: 'rush' | 'cautious' | 'flank' | 'encircle' | 'defend' | 'screen',
    after: 'hold' | 'defend' | 'return' | 'patrol',  // что делать после
    behavior: 'attack' | 'defend' | 'hold' | 'recon',
  },
});
```

* Фазы и их условия берутся из `data/strategies.json` (`phases[].until`):
  `contact`, `losses`, `ammo`, `suppression` — данные, не код.
* `SquadAI` ведёт фазу, формацию, укрытия и отступление; `Squad.directiveId`
  помнит активную директиву, чтобы стратег не выдавал её повторно.
* Завершение директивы: `after` превращается в объектив (`hold`/`defend`/`return`/`patrol`).
* Каждый шаг директивы — обычные приказы в журнале (видно, кто и когда отдал).

## 5. Правила If→Then

`data/rules_presets.json` — пресеты, `RulesEngine` — исполнение.

```json
{
  "id": "hold_the_line",
  "if": { "hpBelow": 0.5, "ammoBelow": 0.3, "enemyWithin": 900 },
  "then": { "order": "retreat", "to": "nearest_own_depot", "priority": 2 },
  "cooldown": 45
}
```

* Условия: `hpBelow`, `ammoBelow`, `moraleBelow`, `enemyWithin`, `sectorLost`,
  `pointLost`, `supplyBelow`, `timeAfter`, `unitsBelow`.
* Действия: `order` (любой тип приказа), `setStance`, `directive`,
  `set_autopilot`, `build_profile`, `produce`.
* Правила применяются к обеим фракциям одинаково и видны в журнале с источником
  `правило`. Число активных слотов растёт от навыков/технологий.

## 6. Три уровня ИИ

| Уровень | Файл | Частота | Что решает |
|---|---|---|---|
| Стратегический | `ai_strategic.js` | 4–7 с | какие сектора/точки брать, кому дать директиву, где оборона |
| Отрядный (FSM/GOAP-подобный) | `ai_squad.js` | 0.5 с | фаза стратегии, формация, якорь, отступление, пополнение |
| Солдат (Behavior Tree) | `ai_soldier.js` | 1–10 Гц (LOD) | цель, укрытие, огонь, мораль, паника, лечение, ремонт |

Логика стратега — полезность, а не скрипт:

```
attack(sector) = value × 1.2 − distance × 0.9 − threat + weakness
value          = w.hq×3 + w.city×1.5 + w.factory×1 + w.depot×0.8 + w.bridge×0.7 + w.farm×0.4
weakness       = tanh(свои_силы / (враг_в_секторе + 1))
```

Перед атакой стратег собирает группу: суммарная сила отрядов ≥ 1.25 ×
(сила врага в секторе + 1), иначе атака не начинается. Персоналия фракции
(`aggressive`/`balanced`/`cautious`) меняет только веса из `ai_weights.json`.

## 7. Режим «ИИ против ИИ» и метрики

* Запуск: главное меню → «Демонстрация: ИИ против ИИ» или
  `new Game({ aiVsAi: true })`. `playerFaction = null`, туман войны отключён,
  оба стратега активны.
* `tests/symmetry.mjs` гоняет 4 прогона (2 сида × стороны местами) по 20 минут
  игрового времени и печатает: длительность, победителя, убийства, захваты,
  доставки, живые юниты.
* Критерии приёмки теста:
  1. нет исключений и зависаний;
  2. в каждом прогоне есть убийства и захваты (война «живая»);
  3. ни одна сторона не выигрывает больше 80% решённых войн;
  4. обе стороны способны победить (проверяется сменой сторон через `swapSides`).
* Метрики пишутся в консоль и в `docs/TEST_PLAN.md` (таблица последнего прогона).

## 8. Что отличается у фракций, а что нет

| Отличается (данные) | Одинаково (код) |
|---|---|
| название, короткое имя, цвет акцента (`factions.json`) | все юниты, оружие, HP, разброс, дальность |
| персоналия ИИ: веса атаки/обороны (`personaWeights`) | Command API, задержка радио, лимиты приказов |
| источник модификаторов: у игрока — дерево навыков, у ИИ — `techMods(время)` | мораль, паника, зрение 110°, слух, память |
| позиция на карте (но карта симметрична поворотом на 180°) | экономика, снабжение, стройка, захват точек |

Сложность (`difficulty.json`) меняет **только** `reaction` и `accuracy`
(скорость реакции штаба и точность оценки обстановки). Это единственное
разрешённое отличие, и оно не даёт скрытых бонусов к урону/HP.

## 9. Детерминизм и производительность

* `RNG` с сидом: одинаковая последовательность при одинаковых вводах.
* Никаких полных переборов юнитов в кадре: `SpatialHash` + LOD (`thinkInterval`).
* Навигация: сетка 64 px, массивы `openArr`/`costArr` считаются один раз при
  изменении мира (`world.navVersion`), поле строится A* и переиспользуется
  отрядом 1.2–1.5 с; одна и та же сетка делится между всеми юнитами отряда.
* Замер (`tests/perf.mjs`): 392 юнита, 500 шагов — средний тик ≈ 2.2 мс,
  куча ≈ 22 МБ. Бюджет 60 FPS — 16 мс на всё, у симуляции запас >7×.
