# Локальный помощник для двух сторон — эксперимент

## Статус

Добавлен **отдельный экспериментальный пункт меню** «Эксперимент: общий помощник ИИ» в веб-версии. Обычная игра и стандартная демонстрация автоматически модель не загружают. В эксперименте штатный стратегический ИИ, бой, перемещение и логистика остаются включены; помощник добавляет ограниченные предложения, а не заменяет весь ИИ. Базовый стратегический профиль обеих сторон выставлен в `balanced`, сложность одинакова.

Добавлен второй отдельный пункт «Эксперимент: помощник со знаниями». Он использует ту же исходную модель и те же изолированные сводки, но добавляет обеим сторонам одинаковый текст о движении солдат, проходимости стен и проёмов, танках, инженерах, снабжении и радио. Это **текст в контексте, а не обучение весов**. В обычном эксперименте системная инструкция не изменилась. Модель по-прежнему не видит карту, координаты, стены, танки или противника и не управляет движением напрямую. Она может лишь предложить разрешённые приказы; путь и физику выполняет игра.

Модель **не дообучена для этой игры**, её ответы и качество командования ещё не проверены. Она не реализует физическую разгрузку грузовика; см. `COOPERATIVE_AI_STATUS.md`. Экспериментальные мост Yuka/ORCA и расширенная карта также не включены здесь автоматически.

Дополнительный текст увеличивает длину запроса. Точное число токенов для максимальной сводки с этой библиотекой и ограничением модели `cs1k` пока не измерено; реальная генерация в новом режиме не проверена. Если модель выдаст ошибку (в том числе из-за переполнения контекста), помощник отключается для обеих сторон и игра продолжает работать со штатным ИИ. Выигрыш или улучшение стратегии не доказаны.

## Установка из ZIP

В меню «Хранилище модели ИИ» выберите оригинальный ZIP из [релиза](https://github.com/m98978672-boop/games/releases/tag/frontline-qwen35-0.8b-0ec1389) кнопкой «Подключить архив». Не распаковывайте его. Игра проверяет размер и Dropbox content hash всего архива, затем сохраняет требуемые файлы в Cache Storage текущего браузера под адресами закреплённой версии WebLLM. После успешного сообщения вернитесь и выберите эксперимент. Операция не получает файл из Dropbox автоматически: его нужно скачать и выбрать вручную. Архивы другого содержимого отклоняются.

Это локальный кэш сайта, а не общедоступное хранилище: он не переносится между браузерами/устройствами, может быть очищен браузером и требует свободного места. При первом запуске WebLLM всё равно требуется загрузить WebGPU-библиотеку из GitHub; shader-f16 и достаточная видеопамять обязательны. Успешный импорт файлов не означает успешный запуск модели.

## Как работает

- При выборе пункта браузер запускает отдельный Web Worker с WebLLM 0.2.87 и моделью Qwen3.5-0.8B q4f16. Нужно безопасное соединение и WebGPU, по оценке WebLLM — около 1,6 ГБ видеопамяти, плюс ресурсы игры. При первом запуске сеть загружает примерно 400 МБ весов с Hugging Face и WebGPU-модуль с GitHub; ресурсы могут кэшироваться браузером. Возможны ограничения сети, WebGPU, оборудования или памяти. Веса не включены в репозиторий.
- Ссылки на веса и библиотеку WebGPU закреплены на конкретные ревизии. Весовые файлы и системный WebGPU-модуль загружаются у внешних поставщиков; при загрузке поставщики видят стандартные сетевые данные, например IP. Сводки игры внешним серверам не отправляются: инференс предполагается внутри браузера.
- Сводка каждой стороны содержит только её собственные отряды, состояние боеприпасов/здоровья/морали и инженеров, собственные точки и чертежи. В модель не передаются названия фракций, реальные ID, позиции, сведения об отрядах противника, сводка другой стороны, время игры или результаты её прошлого ответа. Числа целей в ответе — это временные индексы только в своей сводке. Списки упорядочены относительно домашней стороны. Модель может сделать догадки из общего контекста и своих предобученных знаний: абсолютную невозможность что-то «понять» гарантировать нельзя.
- Один и тот же экземпляр модели последовательно обрабатывает две отдельные сводки с одинаковыми инструкциями, параметрами и seed. Перед и после каждого запроса вызывается WebLLM `resetChat()`; история ответов между запросами не передаётся. Очерёдность сторон на каждом раунде меняется. Проверка контракта с подменным движком есть, но реальная изоляция Qwen на конкретном оборудовании пока не проверена.
- Разрешены только `hold` своей точки, `supply` отряда с боезапасом ниже 70%, `build` собственного чертежа силами отряда с инженером, либо `none`. Чужие ID, другие действия, лишние поля и неверный JSON отклоняются. Реальные приказы идут через обычный Command API с радио-задержкой, отказами и правилами игры; инженеры должны физически добраться и построить.
- Результаты проверяются и выдаются **только парами**: ошибка, устаревшие данные (старше 45 игровых секунд), изменившееся состояние, неверный ответ или `none` только одной стороны отменяет оба предложения. Если обе выбрали `none`, приказов нет. Если модель зависла, не загрузилась или возникла ошибка, отключается весь помощник и обе стороны остаются на штатном ИИ. Результат прошлого боя не применяется к новому. Интервал — 25 игровых секунд после ответа; загрузка и генерация ограничены тайм-аутами.
- Парность не гарантирует равного эффекта: разные ситуации, отряды, задержки радио, решения и отказы могут дать разные последствия. Радио-приказы обрабатываются штатными правилами отдельно; модель не имеет доступа к обеим сводкам в одном запросе. Отклонение всей пары может лишить помощи сторону, которой помощь нужна.

## Проверено

- `node tests/neutral-commander.mjs`: отсутствие данных чужих юнитов в сводке, парная валидация, недопустимые/односторонние/устаревшие результаты, сбой и опоздавший ответ, чередование очереди, сборка/снабжение и реальные радио-приказы обеих фракций, в том числе с переставленными сторонами.
- `node tests/neutral-worker-contract.mjs`: реальный код worker с **подменным** runtime — одинаковые сообщения-инструкции и параметры в обоих режимах, статические факты в новом режиме, сброс до и после запросов, отсутствие чужой сводки в каждом запросе, отсутствие частичного результата при ошибке.
- `npm run test:neutral-commander:browser`: Chromium загружает веб-игру и bundled worker; при запрете внешней сети включается штатный ИИ и игра продолжает идти. Отдельный прогон с подменным worker проверил, что парные приказы доходят обеим сторонам. **Это не проверка реальной модели.**
- `node tools/neutral-commander-scripted-war.mjs`: 2 пары боёв, до 180 игровых секунд с реальным `Game.step`, подменный скриптовый источник решений без задержки. Он выдал по 4 и 3 приказа каждой стороне; все 14 были приняты. Сценарий без реального инференса и без обучения не измеряет интеллект модели или равенство пользы. Данные — `NEUTRAL_COMMANDER_SCRIPTED_WAR.json`.
- `npm test`: функциональные тесты, симметрия и дуэль прошли, но финальный тест производительности не прошёл: стены 0,566 мс/кадр против порога 0,5. При отдельном повторе тест остановился на средней симуляции 16,18 мс/тик против порога 16. Это изменчивые замеры, не доказательство причины; производительность настоящей модели они не измеряют. Контракт worker был добавлен в набор после запуска полного теста и отдельно прошёл.
- `npm run test:browser`: дымовой тест jsdom прошёл; дополнительно прошёл указанный выше Chromium-тест эксперимента.

Исходный worker — `src/ai/commander-worker-entry.js`, собранный модуль — `src/ai/commander-worker.bundle.js` для статического сайта; пересборка `npm run build:neutral-commander` после `npm ci`.
