# Frontline: Command — подробный разбор всей игры

## Что означает этот документ

Здесь собраны **известные проблемы и непроверенные требования**, а также то, что уже работает или частично реализовано. Для каждой из 40 систем есть три пункта: «Что так», «Что не так» и «Итог». Далее отдельно разобраны управление, изображения, звук, проверяющие инструменты и весь репозиторий.

**Честное ограничение:** невозможно гарантировать перечисление вообще всех возможных ошибок игры, не проверив все состояния, устройства и сценарии. Отсутствие упоминания не означает отсутствия дефекта. Отдельно различаются:

- **Воспроизведённый дефект** — есть конкретная проверка и измеренный провал.
- **Не реализовано / не обнаружено** — в исследованном коде не найдена требуемая система; это не обязательно поломка похожей старой механики.
- **Не подтверждено** — нужной полной проверки нет или доказательств недостаточно; нельзя утверждать ни полную исправность, ни то, что каждый элемент сломан.
- **Частично работает** — есть реализация и/или локальный тест; это не приёмка всей системы.

### Общий итог проверок

Повторный полный запуск `npm run audit:all --silent` на текущем рабочем дереве: **NOT_ACCEPTED**. Полный обычный `npm test` внутри него прошёл, но блок 1 не принят: **21 блокирующая запись**. Общий игровой аудит показал **67 замечаний и неподтверждённых пунктов**, среди них **0 из 40 алгоритмов имеют подтверждённую полную приёмку**. Это не означает, что 40 механик полностью не работают: у многих есть старая или частичная реализация, но отсутствуют обязательные флаги, отдельные полные сценарии или их доказательства.

Проверено 149 PNG из манифеста Frontline: **0 структурно повреждённых**. Это проверка сигнатуры, структуры, CRC и распаковки, а не художественного качества, полноты анимации или лицензии. Статический обзор всего репозитория охватил на момент запуска 960 файлов, 87 JSON, 452 JS/MJS/CJS, 208 PNG и 22 HTML; по своим ограниченным правилам замечаний не выявил. Он **не запускал и не принял все игры**, не проверял их механику, внешний вид, лицензии и безопасность. Другие игры репозитория здесь подробно не оценены.

Данные: `ALL_AUDIT_CURRENT.json`, читаемый вывод `ALL_AUDIT_CURRENT.md`; это снимок на момент запуска, не вечная гарантия. Данные могут измениться после правок. Версия игры в `package.json` — 0.11.0. Рабочая ветка `arena/26da737d-games`, последнее исследованное состояние содержит незакоммиченные изменения. Опубликованная игра https://m98978672-boop.github.io/games/frontline-command/index.html не включает последние локальные изменения; её поведение нельзя автоматически приравнивать к этому отчёту.

### Как запускать

В каталоге `frontline-command`, после `npm ci`:

```sh
npm test                         # существующий набор, НЕ вся приёмка
npm run audit:all:human          # полная проверка Frontline + статический обзор репозитория
npm run audit:game:human         # Frontline, включая блок 1
npm run audit:block1:human       # только блок 1
npm run audit:all:quick:human    # быстрая диагностика, НЕ приёмка
npm run test:inspector:browser   # F8 в настоящем headless Chromium
npm run test:easystar:browser    # загрузка и работа EasyStar в Chromium
```

Полная команда длится несколько минут, потому что заново запускает тесты и браузерные сцены; реальный 30-минутный soak пока отсутствует. `npm run test:browser` в текущей среде сообщает **пропуск**, поскольку не установлен jsdom; код выхода 0 у пропуска не означает пройденный тест. Коды 500–539 соответствуют ALG-01…40. «Флаг отсутствует» ниже означает, что требуемого флага нет в реестре; это само по себе не доказывает отсутствие всех похожих механик.

## I. Все 40 систем: что так, что не так и итог

### 01. Снабжение и доставки — ALG-01 / код 500

- **Что так:** существуют заявки, грузовики, общий запас фракции, погрузка/разгрузка и отдельные тесты сохранения рейсов. Две изолированные поездки при включённом экспериментальном безопасном режиме прошли по геометрии карты; по умолчанию этот режим выключен.
- **Что не так:** в штатной старой логике отказ пути может засчитаться разгрузкой вдали от цели; запрос может попасть нескольким машинам, а пустая завершившая рейс машина не всегда повторно используется. Расписание прибытий, перевозка отдельных ящиков и полный учёт грузов по контракту не подтверждены. `safe_logistics_v2` исправляет часть ошибок, но выключен: в 9 коротких сценах за 60 игровых секунд было 0/0 фактических доставок. Это не доказывает, что рейсы не завершатся позже.
- **Итог:** отдельные механизмы есть, но доставка и бухгалтерия не надёжны и не приняты. Нужны фактическое прибытие, резервы, отмены, угрозы, потери и проверка обеих фракций. Код: `src/sim/logistics.js`; `docs/LOGISTICS_ROUTING_EXPERIMENT.md`.

### 02. Баллистика и попадания — ALG-02 / код 501

- **Что так:** есть оружие, попадания, проверка стен/лучей и вероятности пробития; старые геометрические тесты стен проходят в общем наборе.
- **Что не так:** в историческом обзоре не обнаружены полная физика рикошетов, требуемая классификация AP/кинетических снарядов и отдельный случайный поток для баллистики; полный контракт не испытан.
- **Итог:** базовая стрельба существует, но баллистика по полному ТЗ не подтверждена. Нужны симметричные тесты углов, материалов, взрывов, пределов и RNG. Код: `src/sim/units.js`, `src/sim/walls.js`.

### 03. Строительство и ремонт — ALG-03 / код 502

- **Что так:** есть проверка места, чертежи, очередь, приоритеты, инженеры, расход и возврат материалов; исправлено списание больше доступного при шаге взаимодействия игрока. `tests/build-material-budget.mjs` проверяет паузу и возобновление для обеих сторон. Исправлены отдельные ошибки автопланирования и выбора точки.
- **Что не так:** не доказаны доставка материалов на стройку, весь жизненный цикл заданий, безопасный подход техники, ремонт техники и отсутствие забытых чертежей. Расширение радиуса приоритета в `nearestWork` отсекается ранней проверкой базового радиуса. Флаг боевого приоритета инженера выключен из-за ухудшения результата дуэли при пробном включении.
- **Итог:** основная стройка существует, конкретный перерасход исправлен, но система не принята целиком. Нужны реальные сценарии инженеров, врага, путей и доступности. Код: `src/sim/build.js`, `src/sim/ai_soldier.js`.

### 04. Поиск пути — ALG-04 / код 503, также 101 и 116

- **Что так:** есть общие навигационные поля, проверка стен и дверей; восемь типов одиночных проходов в последнем полном стенде прошли по 200/200. Локально подключён EasyStar.js под выключенным `smart_route_v2`: одиночные искусственные U-сцены при включении дали 18/18 и 216/216.
- **Что не так:** штатные флаги дают 8/18 в исходной U-ловушке и 64/216 в расширенной; пехота и техника могут не обойти стену и отказаться от пути. EasyStar не показал устойчивого отсутствия регрессий на нагрузке, а максимальный измеренный поисковый срез был 9,492 мс. Его успехи не относятся к штатному режиму.
- **Итог:** движение для простых проходов есть, надёжный общий обход препятствий не принят. Нужны геометрия с учётом радиуса, динамические стены, отмена пути, массовая нагрузка и реальный бюджет. `src/sim/nav.js`, `units.js`, `walls.js`; `docs/EASYSTAR_INTEGRATION.md`.

### 05. Обзор, туман и обнаружение — ALG-05 / код 504

- **Что так:** есть восприятие бойца, проверки линии видимости и отрисовка тумана; отдельные взаимодействия стен с LOS проверялись.
- **Что не так:** нет полной приёмки памяти контактов, передачи информации и отсутствия знаний о скрытом враге. Стратегический ИИ использует данные силы секторов и общее число вражеских юнитов; из одного просмотра кода ещё нельзя утверждать, какие конкретно сведения доступны вопреки правилам тумана.
- **Итог:** зрение и туман реализованы частично; честность информации ИИ требует специальных сценариев обеих фракций. `src/sim/units.js`, `world.js`, `ai_strategic.js`, `src/render/renderer.js`.

### 06. Огневые позиции — ALG-06 / код 505

- **Что так:** существующие функции подбирают укрытия и точки возле стен, ИИ использует позиции.
- **Что не так:** полная проверка достижимости точки, линии огня, дружественных бойцов, бронирования мест и гистерезиса не подтверждена; отдельный требуемый флаг и приёмочный стенд отсутствуют.
- **Итог:** выбор укрытия есть, но нельзя обещать, что позиция всегда достижима и безопасна. `world.bestCover`, `walls.coverSpotsNear`, `ai_soldier.js`.

### 07. Мораль — ALG-07 / код 506

- **Что так:** код учитывает мораль, панику, командира и укрытие.
- **Что не так:** не проведены все проверки порогов, восстановления, влияния на поведение и симметрии; требуемый отдельный флаг отсутствует.
- **Итог:** мораль частично работает, полный баланс и все эффекты не подтверждены. `src/sim/ai_soldier.js`, `data/ai_weights.json`.

### 08. Захват территорий — ALG-08 / код 507

- **Что так:** существуют прогресс захвата, смена владельца и гистерезис влияния.
- **Что не так:** не подтверждён весь контракт спорных/нейтральных точек, обеих сторон и поведения при смене сил; отдельный обязательный сценарий отсутствует.
- **Итог:** базовый захват реализован, крайние ситуации и симметрия требуют полной проверки. `src/sim/influence.js`.

### 09. Штурм — ALG-09 / код 508

- **Что так:** отряды и бойцы могут атаковать укрепления, есть включённый `assault_forts`.
- **Что не так:** полная зачистка комнат, вход парами через пролом и организованный отход не подтверждены; общего сценария S6 нет.
- **Итог:** простой штурм есть, надёжная тактика зачистки и взаимодействие с дверями не приняты. `src/sim/ai_squad.js`, `src/sim/ai_soldier.js`.

### 10. Оборона — ALG-10 / код 509

- **Что так:** стратегический ИИ назначает оборону угрожаемых секторов и поддерживает профили обороны и отступление.
- **Что не так:** покрытие секторов огня, размер и использование резерва, контратака и заявки снабжения не доказаны в полном наборе ситуаций.
- **Итог:** оборонительные назначения существуют, качество и устойчивость обороны не гарантированы. `src/sim/ai_strategic.js`, `data/build_profiles.json`.

### 11. Фронт и карты влияния — ALG-11 / код 510

- **Что так:** подсчитываются силы и влияние секторов, используются соседи и показатели угрозы.
- **Что не так:** полный набор требуемых карт расстояний/угроз и временной бюджет на их пересчёт не подтверждены; карта влияния не доказывает реальную проходимость и линии снабжения.
- **Итог:** базовая модель фронта есть, точность и стоимость расширенной модели не приняты. `src/sim/influence.js`, `ai_strategic.js`.

### 12. Стратегический ИИ — ALG-12 / код 511

- **Что так:** существующий Utility AI оценивает сектора, группирует отряды, атакует, обороняется и запрашивает снабжение; доступны настроенные стратегии и стадии.
- **Что не так:** полноценная проверенная цепочка планирования по требованиям, адаптация при дефиците и баланс на не менее 20 войнах не подтверждены. Текущее поведение — правила и веса, не доказанное самообучение.
- **Итог:** противник действует, но его стратегию и справедливость ещё нельзя считать полноценно проверенными. `src/sim/ai_strategic.js`, `ai_squad.js`, `data/strategies.json`.

### 13. Отряды и формации — ALG-13 / код 512

- **Что так:** есть составы, командиры, формации, подкрепление и управление отрядами.
- **Что не так:** штатная колонна у двери проваливает строгий тест 0/200; полное автоматическое перестроение и слияние отрядов не доказаны. Командир обычного отряда не является отдельным главнокомандующим всей войны.
- **Итог:** отряды существуют, но групповое прохождение и некоторые механики командования требуют доработки и проверки. `src/sim/squads.js`, `ai_squad.js`.

### 14. Медики — ALG-14 / код 513

- **Что так:** медик может лечить и поднимать раненых, в игре есть связанные состояния.
- **Что не так:** полный триаж, эвакуация, местный расход медикаментов и приоритеты в опасной обстановке не подтверждены всеми тестами.
- **Итог:** базовая медицинская помощь есть; нельзя считать проверенной всю систему эвакуации и ресурсов. `src/sim/ai_soldier.js`, `units.js`.

### 15. Экономика и бухгалтерия — ALG-15 / код 514

- **Что так:** ведутся общие запасы ресурсов и действует производство/расход; конкретный отрицательный остаток при стройке исправлен.
- **Что не так:** исторический аудит не обнаружил полной модели распределённых складских ящиков и журнала транзакций; нулевое расхождение при всех потерях, доставках и сохранениях не доказано.
- **Итог:** базовая экономика есть, строгая сохранность ресурсов между всеми системами не принята. `src/sim/logistics.js`, `src/sim/build.js`.

### 16. Возрождение и прибытие — ALG-16 / код 515

- **Что так:** существуют смерть/возрождение игрока и пополнение войск.
- **Что не так:** полные требуемые очереди прибытий, ограничение общей численности и прибытие по расписанию не подтверждены; в браузерном нагрузочном стенде штатный спавн увеличивал число бойцов выше цели.
- **Итог:** отдельные способы пополнения есть, полноценная система очередей и лимита требует работы. `src/sim/game.js`, `src/sim/autopilot.js`.

### 17. Урон и разрушения — ALG-17 / код 516

- **Что так:** есть HP бойцов/построек, некоторые повреждения техники и разрушение стен; отдельные тесты геометрии и материалов выполняются.
- **Что не так:** единая полная таблица зон повреждений, отдельные зоны грузовика, все стадии руин и их сохранение по контракту не подтверждены.
- **Итог:** базовый урон работает, полная модель техники и разрушенных объектов не принята. `src/sim/units.js`, `world.js`, `walls.js`.

### 18. Планировщик задач и производительность — ALG-18 / код 517

- **Что так:** присутствуют интервалы обдумывания, упрощение дальних объектов и пространственный хэш; стандартный тест производительности симуляции выполняется.
- **Что не так:** индекс после движения бывает устаревшим; полный бюджет отдельных задач и точность упрощений не доказаны. Последний браузерный headless-замер: средний примерно 16,03 FPS на целевой сцене 400 и 15,53 FPS на 500, при превышении фактической численности. Это конкретная программная среда, не характеристика GPU пользователя.
- **Итог:** оптимизации есть, заданный браузерный бюджет не пройден и причины нужно профилировать. `src/sim/game.js`, `src/core/spatial.js`, `tests/acceptance/block1-browser-fps.mjs`.

### 19. Встречные пробки — ALG-19 / код 518, также 420, 422 и 112

- **Что так:** есть локальный anti-stuck; диагностический `alg_deadlock` может считать сбросы, но выключен. При встречной паре оба бойца дошли в 200/200 проверенных сценах.
- **Что не так:** дошли с наложением: строго 0/200, 1200 кадров с наложением и 160 превышений контрольного шага. Отдельных полных проверок встречных машин, колонн и доков нет. Превышение 1,5× не доказывает телепорт.
- **Итог:** приход к цели ещё не означает правильный разъезд; общая система очередей и встречного движения не принята. `tests/acceptance/block1-deadlocks.mjs`, `docs/BLOCK1_DEADLOCKS.md`.

### 20. Звук и оповещения — ALG-20 / код 519

- **Что так:** WebAudio синтезирует звуковые события и музыку; есть журнал предупреждений и частично проверенное приглушение звука стенами.
- **Что не так:** в реестре звук и музыка отмечены как временные; не подтверждены все события прибытия/гибели колонны и дедупликация. Проверка конфигурации не заменяет прослушивание, совместимость браузеров и баланс громкости.
- **Итог:** базовый звук есть, полнота, качество и доступность не приняты. `src/core/audio.js`, `data/audio.json`, `docs/ASSETS_CREDITS.md`.

### 21. Сохранения — ALG-21 / код 520, также 206

- **Что так:** игра сохраняет состояние в localStorage. Под выключенным `alg_save` добавлено частичное сохранение ID, RNG, игрока, отрядов, приказов, чертежей, структур и текущих рейсов; отдельные тесты ловят повреждённые и повторно выданные ID.
- **Что не так:** полная миграция старого формата, все данные подсистем, ссылки и одинаковое продолжение войны не доказаны. Самый старый формат может просто не содержать нужной информации; восстановление нельзя выдумать. Полный приёмочный тест отсутствует.
- **Итог:** сохранение не отсутствует, но на точное продолжение всей сложной игры пока нельзя полагаться как на доказанный replay. `src/core/save.js`, `docs/SAVE_*.md`, `tests/save-*.mjs`.

### 22. Повтор и баланс войн — ALG-22 / код 521, также 207 и 209

- **Что так:** существуют headless AI-vs-AI, дуэль и симметричные прогоны. В последнем обычном `npm test` дуэль завершилась 6:2 и формально прошла имеющийся короткий тест; зеркичный набор дал 2:2.

## II. Подробно о наиболее опасных воспроизведённых проблемах

### 1. Устаревший пространственный индекс бойцов — код 117

**Что это:** для быстрого поиска ближайших юнитов мир делится на клетки. При движении боец должен находиться в индексе той клетки, где он реально стоит. Проверка сравнила действительную позицию с индексом после 60 игровых тиков для нескольких seed.

**Факт:** несовпадений 83 при seed 5, 107 при seed 7, 79 при seed 11; перемещения между клетками действительно происходили. Из-за такого расхождения поиск соседей и потенциально системы, которые используют индекс, могут получать устаревший список. Как именно это влияет на каждый отдельный промах, столкновение или поиск — ещё нужно доказывать отдельными тестами.

**Что так:** ошибка обнаруживается повторяемым `npm run audit:unit-grid`. Предложенное немедленное обновление устраняло измеренные несовпадения, но было откатано: в том сравнении дуэль дала 7:1 и нагрузка ухудшилась в 6/9 коротких сцен. Это корреляция, а не доказательство единственной причины.

**Итог:** проблема индекса подтверждена, безопасного принятого исправления пока нет. Нужны правильный момент обновления, защита от изменений порядка обработки и повторная проверка боя, симметрии, логистики и нагрузки. `docs/UNIT_GRID_DIAGNOSIS.md`.

### 2. Движение отряда через дверь — коды 110–112

**Факт:** восемь разновидностей одиночного прохода через двери прошли по 200/200. Но штатная колонна из десяти бойцов не прошла строгий критерий ни разу в 200 сценах: все десять доходили лишь в 89/200; зафиксированы 27 378 кадров наложения и 12 превышений контрольного шага. Фракция 0 полностью дошла в 89/100, фракция 1 — в 0/100. Измерение сделано на конкретных сценах, не на всех картах.

**Что так:** отдельные юниты могут входить и выходить через проверенные проёмы. Эксперимент `crowd_nav_v2` при включении прошёл 200/200 этих колонн и 180/180 вариантов.

**Что не так:** этот эксперимент провалил 20/20 встречных пар из-за наложений и нарушений контрольного шага и выключен по умолчанию. В штатном варианте колонна может затормозить, сгрудиться и не пройти; выигрыш одиночного A* не решает координацию группы.

**Итог:** проблему двери нельзя объявлять исправленной только по проходу одного бойца или выключенному эксперименту. Нужны очередь/резервация узкого прохода и проверка встречных направлений, типов юнитов, фракций и нагрузки. `docs/BLOCK1_DOORS.md`, `docs/CROWD_NAV_EXPERIMENT.md`.

### 3. Бойцы и техника в U-ловушке — коды 101 и 116

**Факт:** по умолчанию 8 из 18 стандартных и 64 из 216 расширенных сцен прошли. В расширенном наборе провалены 48 сцен пехоты, 56 грузовика и 48 танка. Единица может не решиться временно отойти от цели ради обхода стены.

**Что так:** EasyStar под выключенным флагом на том же наборе прошёл 18/18 и 216/216; настоящая загрузка его ESM в Chromium и отдельный обход стены проверены. Лицензии EasyStar и heap включены в `src/vendor/`.

**Что не так:** одиночный обход не подтверждает двери, групповое движение, стабильный бюджет и полную игру. Из 9 коротких нагрузочных сравнений с EasyStar 5 улучшились, 2 ухудшились, 2 остались равны; отдельный максимальный срез около 9,492 мс превышает целевые 2 мс. Нельзя утверждать, что доказан общий бюджет.

**Итог:** причина отказа в искусственных ловушках воспроизводима, перспективная библиотека есть, но включать её всем игрокам до закрытия регрессий рано. `docs/EASYSTAR_INTEGRATION.md`.

### 4. Браузерная производительность — коды 301–304

**Факт последнего общего аудита:** Chromium 153, headless, программный рендеринг. На стенде с целью 400 живых реально было 402–422; средний FPS **16,03**, 1% low **1,06**. С целью 500 было 502–522; средний FPS **15,53**. Заданные пороги: средний 60 и 1% low 45 для 400, средний 45 для 500.

**Что так:** замер настоящий в указанном окружении, спавн не скрыт и отклонение численности отражено как отдельная ошибка стенда.

**Что не так:** это не корректная точная нагрузка на 400 и 500 и не проверка с аппаратным GPU пользователя. Нельзя переносить эти числа на его устройство или обещать заданный FPS. Причина низкой производительности пока не установлена только этим замером.

**Итог:** текущая браузерная приёмка провалена; сначала нужен точный контроль числа живых, затем профилирование JS, навигации и отрисовки и повторные тесты на указанном железе. `docs/BLOCK1_BROWSER_FPS.md`, `tests/acceptance/block1-browser-fps.mjs`.

### 5. Перерасход стройматериалов — подтверждён и локально исправлен

Ранее при остатке 0,65 и шаге 1,2 с могло списываться 0,66, то есть запас уходил в минус. Код теперь проверяет полную стоимость шага и недопустимый `dt`; ремонт может возобновиться после пополнения. `node tests/build-material-budget.mjs` включён в прошедший `npm test`.

**Итог:** конкретный обнаруженный перерасход закрыт в рабочем дереве. Это не означает, что вся экономика, доставка и все случаи стройки исправлены; в опубликованной версии это изменение ещё не появилось. `docs/BUILD_MATERIAL_FIX.md`.

### 6. Победа при полном паритете — действующее правило требует решения

`resolveByPoints()` сравнивает ключевые города, точки, живых и силу; при полном равенстве возвращает победу фракции 0. Это видно в коде и даёт одной стороне преимущество в конкретном граничном случае. Отдельно текущие условия городов/таймера расходятся с ранее записанным контрактом.

**Что так:** у конца войны есть явная причина и результат. **Что не так:** нет принятого симметричного разрешения полной ничьей и единого подтверждённого решения о правилах завершения. **Итог:** уточнить требуемое правило и проверить одновременные события обеих сторон, а не менять тай-брейк без согласования.

## III. Дополнительные области всей игры

### ИИ противника и «память навыков»

- **Что так:** противник уже использует Utility AI, оценивает сектора, силу, угрозу, задачи отрядов и снабжение. Игрок может включать автопилот по направлениям. Есть игровые навыки/опыт игрока и отдельные сериализуемые метаданные; это не равняется обучению противника.
- **Что не так:** настоящий постепенно обучающийся в ходе игр бот с надёжным сохранением его выученных навыков и проверкой новых стратегий не реализован/не доказан. `data/ai_movement_experience.json` — журнал офлайн сравнений одной группы искусственных U-сцен; история не применяется в игре как веса. Нет автоматической синхронизации между игроками и обучения на браузерных матчах. Текущих результатов недостаточно, чтобы утверждать, что ИИ стал умнее в реальной войне.
- **Не проверено:** реальная обучаемость, защита от вредных данных, качество поведения после многих войн, баланс между сторонами. Облачный сбор потребовал бы отдельной безопасной серверной архитектуры и решения пользователя.
- **Итог:** обычный ИИ существует, долговременное самообучение остаётся отдельной нерешённой задачей. `docs/AI_MOVEMENT_EXPERIMENT.md`, `src/sim/ai_strategic.js`.

### Экспериментальные переключатели

Согласно `data/feature_flags.json`, `smart_route_v2`, `crowd_nav_v2`, `safe_logistics_v2`, `engineer_combat_priority_v2`, `alg_save` и `alg_deadlock` выключены по умолчанию. Исследовательские результаты, полученные при включении, **не описывают обычную опубликованную игру**. `pathing_v2` включён, но его наличие не означает прохождения U-ловушек. Перед изменением любого флага нужны парные тесты и отсутствие регрессий; их отключённость — защитная мера, а не завершённое исправление.

### Анимации, изображения и лицензии

**Что так:** растровые спрайты по направлениям, тайлы и эффекты существуют; проектный файл утверждает, что оригинальные визуальные и звуковые материалы созданы внутри проекта. Проверены структура и распаковка PNG, отдельные браузерные проверки загрузки.

**Что не так:** реестр обозначает графику и звуки как `PLACEHOLDER_REPLACE`. Нет полной покадровой проверки ходьбы, направления, прозрачности, швов, совпадения картинки и коллизии, разрушаемых стадий и доступности всех изображений в игровых ситуациях. Проверяющий обнаруживает рисуемые линиями стены; по коду используются четыре направления, дополнительные диагонали не подтверждены. Отдельная независимая проверка происхождения и прав каждого ресурса не выполнялась; утверждение проекта об авторстве не является таким аудитом. Оценка красивости и качества требует просмотра, а не одного парсера.

**Итог:** картинки технически читаются, но визуальная готовность и полный комплект не доказаны. Игра двухмерная: прежде чем заказывать «меши», нужно согласовать, нужны ли ей 3D-объекты или двухмерные спрайты. Новые ресурсы не следует называть готовыми.

### Управление, интерфейс и доступность

**Что так:** существуют режимы солдата и командира, приказы, настройки, камера, HUD и кнопка/F8 для инспектора; тест инспектора в Chromium прошёл. **Что не так:** полный интерактивный путь игрока от запуска до конца войны, все режимы ввода, размеры экранов, тач-устройства, доступность, сообщения об ошибках и конфликт ручного/автоматического приказа не приняты. Тест `test:browser` пропущен из-за отсутствующего jsdom; другой тест Chromium этого не подменяет. **Итог:** интерфейс есть и локальные проверки есть, но все элементы управления и платформы не подтверждены.

### Звук

**Что так:** WebAudio синтезирует музыку, эффекты и оповещения; есть данные настройки и ограничение пула голосов. **Что не так:** звуки помечены временными, по настройкам нельзя определить, слышно ли их корректно при включении, блокировке автовоспроизведения, перегрузке пула и на разных устройствах. **Итог:** рабочая звуковая система частично присутствует, но полноценное звучание и совместимость не приняты.

### Сохранение, старые версии, повторы

**Что так:** есть локальное сохранение и отдельные тесты нескольких категорий данных. **Что не так:** полное состояние всех подсистем, перенос старых сохранений и повтор по входам/RNG с контрольными суммами не доказаны. Результат может отличаться из-за очередей и порядка обновления даже при одинаковом seed. **Итог:** локальный сейв нельзя приравнивать к точному возобновлению и детерминированному replay. Необходимо проверять чистый профиль, повреждённые файлы, миграции и продолжение по контрольным точкам.

### Тесты и проверяющие

**Что так:** есть обычный `npm test`, выборочные браузерные тесты, F8-инспектор и fail-closed аудиты. В свежем общем запуске обычный тест прошёл. **Что не так:** полноценного интеграционного стенда всех S1–S10 нет; отсутствуют специальные обязательные стенды карточек ALG-04/18/19/21/22, сравнение застреваний на 3 seed и 100/300/400 юнитах с целью снижения ≥70%, бюджет навигации ≤2 мс, полный save/replay и настоящий 30-минутный soak. `S1` — дом, `S8` — 400/500, `S9` — длительный soak, `S10` — старый сейв; блок 1 отдельно требует именно эти интеграции. Отсутствие теста — не доказательство поломки соответствующей функции.

**Итог:** имеющиеся тесты полезны и ловят регрессии, но не позволяют объявить игру принятой. F8 тоже лишь снимок: коды 700–712 относятся к его ограниченным проверкам, а не к полному длительному тесту. `TESTS.md`, `data/game_audit_contract.json`, `docs/GAME_AUDITOR.md`.

### Весь репозиторий и публикация

**Что так:** статический аудитор прошёл известные ему проверки файлов всего репозитория без обнаруженных нарушений; локальная версия запускает ряд тестов. Публичная игра существует на GitHub Pages.

**Что не так:** статистическая проверка файлов не проверяет игровые механики других игр, все форматы, визуальные проблемы, лицензии или сторонние сервисы. Изменения в текущей ветке и результаты этого документа не опубликованы в ссылке на Pages: опубликованная версия относится к более раннему слиянию `ab02583b30072066ab6876bb572205c23652da1d`. Деплой после последних правок в этом ходе не проводился.

**Итог:** повреждённых файлов по имеющимся статическим проверкам не обнаружено; работоспособность всех игр репозитория не доказана. Локальные исправления не следует выдавать за уже опубликованные.

## IV. В каком порядке исправлять

1. **Зафиксировать правила победы и обязательный контракт.** Уточнить, какие виды победы и спорные требования действительно нужны, без подмены реальной ошибки изменением теста.
2. **Восстановить корректность мира:** пространственный индекс и геометрия, затем индивидуальные маршруты, проходы, координация групп и встречные пробки. Проверять одновременно обе стороны, классы юнитов, бой и нагрузку.
3. **Доставка и стройка:** фактическое прибытие, резервы/отмена, честная бухгалтерия, подход инженеров, расход и безопасность проездов; потом отдельные расширенные экономические системы.
4. **Бой, ИИ и симметрия:** видимость, выбор укрытий и целей, приказы, оборона/штурм, 20 и более симметричных войн и расследование перекосов. Выученный опыт внедрять только после безопасной оценки и сохранения, не смешивая с обычными навыками игрока.
5. **Сохранения и устойчивость:** миграция, полные ссылки и задания, replay/RNG, непрерывная длительная игра и последствия перезагрузки.
6. **Профилирование браузера:** точное количество юнитов, фиксированные сценарии, отдельно CPU/GPU, средний FPS и 1% low; не скрывать спавн и не снижать пороги ради зелёной отметки.
7. **Полный набор приёмочных проверок:** S1–S10, конкретные карточки и интеграции, автоматический честный fail-closed отчёт.
8. **Финальная графика и звук:** после устранения блокирующих ошибок — утверждённый визуальный формат, замена заглушек, направления/анимации, лицензии и браузерные снимки; затем новые примерно 100 ресурсов по согласованному перечню.
9. **Публикация:** после проверки изменений разместить обновлённую игру на Games и проверить именно развёрнутую версию. Одного локального отчёта недостаточно.

## V. Источники и ограничения

- Свежий полный машинный снимок: `docs/ALL_AUDIT_CURRENT.json` и `docs/ALL_AUDIT_CURRENT.md`. Полный аудит — `tools/audit-all.mjs`, `tools/game-auditor.mjs`, `tools/block1-auditor.mjs`.
- Контракты и наборы: `ALGORITHMS_SPEC.md`, `TESTS.md`, `data/game_audit_contract.json`, `data/feature_flags.json`. Описания в старых таблицах — исторические, поэтому факты сопоставлены с текущими тестами и кодом, а отсутствие отдельной проверки обозначено прямо.
- Детали блока 1: `docs/BLOCK1_FULL_PROBLEM_DESCRIPTION.md`, `docs/UNIT_GRID_DIAGNOSIS.md`, `docs/BLOCK1_DOORS.md`, `docs/BLOCK1_DEADLOCKS.md`, `docs/BLOCK1_BROWSER_FPS.md`. Прежний `BLOCK1_AUDIT_CURRENT.md` — предыдущий замер, цифры FPS могут отличаться.
- Эксперименты и исправление: `docs/EASYSTAR_INTEGRATION.md`, `docs/CROWD_NAV_EXPERIMENT.md`, `docs/LOGISTICS_ROUTING_EXPERIMENT.md`, `docs/AI_MOVEMENT_EXPERIMENT.md`, `docs/BUILD_MATERIAL_FIX.md`.
- Графика/звук и происхождение: `docs/ASSETS_CREDITS.md`, `assets/manifest.json`; визуальные и юридические выводы требуют самостоятельной проверки.
- Код игрока, ИИ, мира, стен, UI и сохранений находится в `src/`; используемые конкретные пути указаны в соответствующих пунктах.

**Общий вывод:** игра содержит много работающих базовых механизмов, и один конкретный перерасход материалов в рабочей версии исправлен. Однако подтверждены серьёзные дефекты навигации, индексирования, группового движения и приёмочного браузерного замера; логистика, победа, ресурсы, сохранение, ИИ, интерфейс и визуальная часть не удовлетворяют всему требуемому контракту или ещё недостаточно проверены. Ни полную исправность, ни готовность всех ресурсов, ни обучающегося бота, ни публикацию последних изменений утверждать нельзя.
