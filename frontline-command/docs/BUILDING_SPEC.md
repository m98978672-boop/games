# BUILDING_SPEC — строительство под управлением командира (0.10.0)

> Всё строительство идёт одним путём: приказ через Command API. Игрок, автопилот и ИИ врага
> пользуются одними и теми же типами приказов и одними же проверками. Никаких «тихих»
> постановок в обход API нет: это проверяет `tests/build.mjs` (пункт 9).

## 1. Режимы в интерфейсе

Панель «Стройка» (горячая клавиша `B`) получила переключатель инструментов, профиль,
приоритет и живой список очереди.

| Инструмент | Как ставить | Что уходит в API |
| --- | --- | --- |
| **Один** | ЛКМ по карте | `place_build` |
| **Линия** | ЛКМ и протянуть; шаг секций = размер постройки | `build_line` (`params.from`, `params.to`) |
| **Зона** | ЛКМ и протянуть рамку; постановка по профилю обороны | `build_zone` (`params.poly`, `params.profile`) |
| **Шаблон** | ЛКМ, `R` — поворот на 45° | `build_template` (`params.template`, `params.rot`) |

Профиль и приоритет берутся из панели и передаются в приказе (`params.profile`,
`params.priority`). ПКМ отменяет режим; если идёт протяжка — сначала отменяет протяжку.

Под курсором показывается призрак: для линии — цепочка секций с зелёными/красными
рамками по результату проверки, для зоны — рамка и предпросмотр плана (пересчитывается
раз в 0.3 с, чтобы не грузить кадр).

## 2. Коды причин

`validate()` возвращает `{ ok, code, reason, warn[] }`. Коды одинаковы в подсказке под
курсором, в журнале приказов и в счётчике `build.lastReject`.

| Код | Значение | Запрет? |
| --- | --- | --- |
| `OK` | можно ставить | — |
| `TERRAIN` | вода, препятствие, постройка не помещается | да |
| `OVERLAP` | пересечение со строением или другим чертежом | да |
| `RANGE` | за границей карты | да |
| `SKILL` | нужен навык (например, «Бункеры») | да |
| `CATEGORY` | этот тип нельзя ставить вручную | да |
| `LIMIT` | достигнут лимит построек типа (`buildings.json → limit`) | да |
| `FOG_BEHIND` | точка вне зоны контроля фракции | да |
| `RESOURCES` | не хватает материалов | мягкий: чертёж ставится, стройка ждёт |
| `BLOCKS_PATH` | чертёж перекрывает узкий проход | нет, предупреждение |
| `ENEMY_NEAR` | рядом противник (≤ 320 px) | нет, предупреждение |
| `ACCESS` | нет инженера в радиусе 900 px | нет, предупреждение |

Причины простоя в очереди — отдельный набор: `NO_MATERIALS`, `NO_ENGINEERS`, `DANGER`,
`UNREACHABLE`, `paused`. Панель стройки показывает их рядом с прогрессом.

## 3. Профили обороны и зоны

Профиль в `data/build_profiles.json` описывает не только состав, но и глубину:

```json
"medium": {
  "items": [{ "type": "trench", "count": 4 }, { "type": "mg_nest", "count": 2 }],
  "echelons": [{ "name": "front", "depth": 80, "share": 0.45 },
               { "name": "main", "depth": 170, "share": 0.35 },
               { "name": "rear", "depth": 280, "share": 0.2 }],
  "density": 14, "threatWeight": 1.0, "budget": 520,
  "dedup": 96, "maxFortsPerPoint": 4
}
```

Как строится план зоны:

1. Кандидаты — сетка 40 px внутри рамки, только проходимые клетки.
2. Для каждого кандидата считается **угроза** сектора (близость вражеской территории,
   давление соседей, линия фронта) и проекция на направление угрозы (`front` → `rear`).
3. Элементы профиля раскладываются по эшелонам: тяжёлое — к фронту, тыловое — назад.
4. Кандидаты сортируются по полезности, ставятся **сначала дешёвые** секции: экономика
   важнее «сразу самое сильное».
5. `dedup` не даёт лепить новые укрепления рядом с уже стоящими — иначе повторный приказ
   после каждого захвата превращает оборону в лес бетона.
6. Бюджет профиля ограничивает суммарную стоимость плана.

`maxFortsPerPoint` — политика ИИ: если у узла уже стоит столько укреплений, повторный
профиль считается выполненным (`skipped: true`).

## 4. Очередь, приоритеты, отмена

- Приоритеты: `urgent` (2), `normal` (1), `low` (0). Очередь сортируется по приоритету,
  затем по времени создания; приоритетные чертежи «дотягивают» строителей с большего
  радиуса.
- `set_build_priority` — сменить приоритет, `cancel_build` — снять чертёж.
  Возврат материалов: 100 % если не начат, 60 % если в работе, 40 % если уже построен снос.
- `queueInfo(faction)` отдаёт данные для панели: тип, прогресс, приоритет, причина простоя.

## 5. Политика ИИ (одинакова для автопилота игрока и ИИ врага)

`buildWanted(faction)` из `data/ai_weights.json → build`:

| Параметр | Значение | Смысл |
| --- | --- | --- |
| `minArmy` | 24 | не строим, пока армия меньше — производство важнее |
| `reserveMaterials` | 150 | не трогаем последние материалы |
| `cooldownSeconds` | 25 | один приказ стройки за интервал |
| `maxOpenBlueprints` | 10 | предел незавершённых чертежей |

`autoPlan(faction)` раз в 5 с выбирает самый угрожаемый свой узел (город, склад, штаб,
завод) и отдаёт `build_zone` с профилем `light`/`medium` по величине угрозы. Приказ идёт
через Command API с радиозадержкой и попадает в общий журнал.

## 6. Приказы Command API

| Тип | Параметры | Обработчик |
| --- | --- | --- |
| `place_build` | `buildType`, `priority` | `build.place` |
| `build_line` | `buildType`, `from`, `to`, `priority` | `build.placeLine` |
| `build_zone` | `poly` или `radius`, `profile`, `budget`, `priority` | `build.placeZone` |
| `build_template` | `template`, `rot`, `mirror`, `priority` | `build.placeTemplate` |
| `set_build_priority` | `blueprintId`, `priority` | `build.setPriority` |
| `cancel_build` | `blueprintId` | `build.cancel` |
| `demolish` | `x`, `y` | `build.demolish` |
| `build_profile` | `profile`, `pointId` | `build.planProfile` (зона вокруг точки) |

## 7. Штурм укреплений

Постройки разрушаемы стрелковым огнём: `tryShootBuilding()` в `src/sim/units.js` бьёт по
вражескому форту в пределах дальности оружия (90 % урона, снаряды — обычный взрыв).
Ветка в `src/sim/ai_soldier.js` включается, когда отряд наступает и впереди есть вражеский
форт: юнит подходит на дистанцию огня (по возможности через укрытие) и стреляет.
Флаг `assault_forts` отключает поведение целиком.

## 8. Как это проверить руками

1. Открыть игру, `B` — панель стройки.
2. Выбрать «Линия», протянуть от фланга к флангу — появятся секции с зелёными рамками.
3. Выбрать «Зона», профиль «Средний», растянуть рамку у фронтового города — план покажет
   эшелоны: окопы ближе к противнику, мешки и вышка — глубже.
4. Выбрать «Шаблон» → «Опорный пункт», `R` — поворот, ЛКМ — постановка.
5. В очереди внизу панели видны прогресс и причины простоя; поднесите инженера — простой
   сменится на «в работе».
