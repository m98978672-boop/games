# Бот-инспектор F8 и обзор репозитория

## В игре

Нажмите **F8** или кнопку **«Инспектор · F8»** в меню или во время войны.
Откроется отчёт в стиле инспектора из `last-shore/src/bot.js`: для каждой
проверки видны название, код, ожидание и факт. «Проверить снова» снимает
новый снимок; «Скопировать отчёт» копирует текст для передачи разработчику.
Если браузер запрещает буфер, выделите текст вручную. Крестик или F8 закрывают
панель. Игра при открытии не ставится на паузу и её состояние не изменяется.

Инспектор адаптирован к нашей 2D-игре. В отличие от робота Last Shore, он не
добавляет видимого юнита, не ходит и не изменяет сцену: проверяет живое
состояние без вмешательства. Это **снимок**, а не автономный ИИ, не полный
проход войны и не приёмка. В меню проверки игрового мира отмечены как
непроверенные. Ошибки выводятся, только когда измеренное значение нарушает
конкретную проверку; отсутствие достаточных данных обозначено отдельно.

| Код | Проверка снимка |
|---|---|
| 700 | Наличие запущенной игры |
| 701 | Canvas и параметры камеры |
| 702 | Загрузка базовых тайлов, зданий, интерфейса, эффектов и 4 направлений моделей двух фракций |
| 703 | Данные живых бойцов и техники |
| 704 | Взаимные ссылки живых бойцов и отрядов |
| 705 | Числовые данные точек и живых построек |
| 706 | Четыре запаса каждой фракции |
| 707 | ID, фракция и время ожидающих приказов |
| 708 | Размеры мира и навигационной сетки |
| 709 | Параметры звуковых событий, без воспроизведения |
| 710 | Наличие HUD, без проверки взаимодействий и вёрстки |
| 711 | Границы снимка и непроверенные области |
| 712 | Наблюдение смещения за 5 игровых секунд — эвристика, не доказательство застревания |

Пока панель открыта, бот сравнивает позиции подходящих бойцов без боевого
контакта с совпавшей целью на двух выборках через минимум 5 игровых
секунд; пауза не учитывается. Смещение менее 6 px выводится для исследования,
а не объявляется неисправностью: поведение между выборками не видно.
Смена цели или войны исключает такое сравнение.

По одному снимку нельзя установить правильность ходьбы во времени, сложных
алгоритмов, баланс, работоспособность сохранений, качество графики и звука,
лицензии или поведение на других устройствах. Браузер не даёт странице читать
произвольные файлы Git-репозитория. Поэтому для файлов и более долгих
приёмочных проверок используются отдельные команды ниже.

## Все файлы Git-репозитория

Из каталога `frontline-command`:

```sh
npm ci
npm run audit:all:human    # репозиторий + полный аудит Frontline
npm run audit:all:quick:human # быстрый обзор, не приёмка
npm run audit:repo:human   # только репозиторий, человекочитаемо
npm run audit:repo         # JSON
npm run audit:game:human   # отдельно полная приёмка Frontline, включая блок 1
npm run test:inspector:browser
```

`audit:repo` берёт у Git список **всех** отслеживаемых и новых
неигнорируемых файлов всего репозитория `games`, не только Frontline. Он
проверяет чтение JSON, синтаксис JS/MJS/CJS через `node --check` частичную
структуру PNG (сигнатура, блоки, CRC, распаковка), а также буквальные
относительные ссылки `script`, `link` и `img` в HTML. В отчёте для каждой
найденной проблемы указан путь и устойчивый код:

| Код | Проверка репозитория |
|---|---|
| 800 | Некорректный путь за пределами репозитория |
| 801 | Файл из списка Git отсутствует или недоступен |
| 802 | Файл JSON не читается или не разбирается |
| 803 | Файл JS/MJS/CJS не проходит проверку синтаксиса Node |
| 804 | PNG не читается или не проходит частичную проверку структуры |
| 805 | Отсутствующий локальный ресурс в проверенной буквальной ссылке HTML |
| 806 | Не удалось выполнить обзор репозитория |
| 807 | Не удалось выполнить аудит Frontline |

Это не означает, что проверены все форматы или поведение каждой игры. SVG,
остальной HTML, CSS, документы, скрипты других языков, символические ссылки,
игнорируемые зависимости и содержимое бинарных файлов не анализируются.
Синтаксис не запускает код, а структура PNG не проверяет внешний вид.
Команда возвращает 0, если *в этих проверках* не обнаружено ошибок, 1 при
обнаруженных проблемах, 2 если обзор не удалось запустить; 0 **не** означает
полную исправность репозитория. Доступные тесты игры и приёмка блока 1 —
отдельная команда `audit:game`, её условия не ослаблены. Единый `audit:all` запускает оба обзора и не
показывает PASS, пока аудит репозитория остаётся частичным.

`REPOSITORY_AUDIT_BASELINE.json` и `REPOSITORY_AUDIT_REPORT.md` — результат
конкретного запуска; после изменений обзор следует запустить заново.
Другие коды (001–599), а также их ограничения см. в `GAME_AUDITOR.md` и
`BLOCK1_AUDITOR.md`. Свободные номера не заполняются вымышленными ошибками.
