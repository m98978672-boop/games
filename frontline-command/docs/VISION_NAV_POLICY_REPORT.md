# Выбор движения по обзору и малая группа

## Смысл и границы

Для этого эксперимента «2−» означает одного или двух бойцов, «2+» — трёх и более. Добавлены два независимых, выключенных по умолчанию флага:

- `vision_nav_policy_v1`: пехотинец локально проверяет видимых союзников и врагов в радиусе до 220 пикселей с проверкой прямой видимости. Контакт из имеющегося восприятия также осторожно блокирует мирные манёвры. Выбирается режим одиночки, пары, группы или боевого контакта; дополнительное короткое наблюдение препятствия использует прежний датчик до 32 пикселей. Это не полная тактическая оценка карты и не новое обучение.
- `group_nav_3to5_v1`: расширяет существующее экспериментальное групповое прохождение на 3–5 союзных пехотинцев с одной и той же целью в здании и подходящим строем. Для него также нужен `crowd_nav_v2`. При выключенном новом флаге прежний минимум — 6.

Выбор режима сам не включает другие экспериментальные флаги: без отдельно включённого алгоритма используется обычное движение. Для пары доступен прежний манёвр пары, если он включён; при включённом правиле уступания используется оно, чтобы не обходить приоритет выхода. Для группы применяется групповой проход, если выполнены его условия и он включён; иначе остаётся обычный маршрут, а при подходящем препятствии — отдельно включённый экспериментальный поиск. В боевом режиме селектор не навязывает групповой или дверной манёвр и отменяет принадлежащий бойцу экспериментальный поиск; непосредственно стрельбу и выбор цели он не заменяет. Физические коллайдеры также остаются под собственным флагом.

Для решения проверяется реальная видимость союзников, правило уступания в выбранном режиме не получает скрытого напарника. Это не доказывает отсутствие всех недостатков LOS: игровая тайловая проверка имеет известные ограничения. Индекс юнитов при `Game.step` создаётся в начале тика, поэтому решение не обещает независимости от порядка действий. Автоматически переключается только пехота с целью, без ручного управления; транспорт здесь не охвачен. Наличие группы поблизости не означает, что у всех одинаковые приказы: групповой проход включается только при собственных условиях.

Данные: `VISION_SMALL_GROUP{,_STEP,_AUTOPILOT}.json`, `VISION_POLICY_{DOORS,GAME_STEP,GAME_STEP_ISOLATED,COLUMN,U,U_GROUP}.json`.

## Бой, откат, производительность

В 20 парных 30-секундных AI-vs-AI сценах селектор off/on с одинаковыми включёнными прежними экспериментами дал 514→486 выстрелов и 664→644 выборочных контакта. В отдельной серии расширение групп 3–5 off/on при включённом селекторе дало 486→512 выстрелов и 644→718 контактов. Убийств и завершённых войн не было. Общий генератор случайных чисел после различных действий расходится: это не полноценная оценка баланса, не 100 законченных войн и не доверительный интервал. `VISION_POLICY_COMBAT.json`, `VISION_SMALL_GROUP_COMBAT.json`.

Среднее инструментированное Node-время одной 30-секундной боевой сцены при сравнении селектора составило примерно 2,9 с off против 4,6 с on, при параллельных тестах и разных последующих действиях. Это шумный признак возможной дополнительной стоимости проверки видимости, **не FPS браузера и не тест эталонного устройства**. Производительность под нагрузкой необходимо отдельно проверить; включать флаг по умолчанию нельзя.

Оба флага выключены в конфиге. Сравнение графов off с предварительными снимками: 20 seed × 61 снимок, совпадение 1220/1220 для селектора с выключенным расширением, отдельно 1220/1220 при включённых прежних экспериментах, и 1220/1220 для расширения малой группы при включённых селекторе и старом crowd-nav. Из нового тестового конфига удалялись лишь добавленные записи. Покрытие графа не включает полноценно замыкания, глобалы, прототипы, идентичность буферов и некоторые поля времени; это не доказательство побитового совпадения всей игры. `VISION_POLICY_OFF_COMPARE.json`, `VISION_POLICY_OFF_PRIOR_ON.json`, `VISION_SMALL_GROUP_OFF_COMPARE.json`.

Unit-тесты выбора режима, реальной стены, видимого и скрытого противника, переключений и отмен, отключения флагов и 3–5 бойцов прошли для обеих фракций. `npm test` завершился с кодом 0 (`VISION_POLICY_NPM_TEST.log`), отдельный Chromium-тест обоих флагов и живого игрового тика, общий браузерный smoke и `git diff --check` прошли. Испытания не доказывают корректность всех ситуаций, сохранение баланса, полный replay или прохождение блока 0. Изменения не опубликованы и не включены в opt-in preview.

## Дополнение: причины 109 отказов и новые эксперименты

Диагностика `VISION_GROUP_FAILURE_DIAGNOSIS.json` воспроизвела все 109 прежних провалов: у 182 из 449 бойцов фиксировались и прибытие, и последующий `pathFailed`, ещё 194 действительно не добрались. В 62 сценах около первого застрявшего находилась техника; в 66 были пересечения с внешними юнитами на границах тиков. Отключение подсистем изменяет ход симуляции и расход RNG, поэтому это признаки причин, а не независимое доказательство виновности каждого механизма.

Добавлены **выключенные по умолчанию**:
- `arrival_stuck_guard_v1`: не помечает успешно достигнутую цель как застревание, но устаревший `arrived` не маскирует недостигнутую цель.
- `crowd_slot_avoid_v1`: при неподвижном внешнем блокере пробует другое безопасное достижимое место внутри имеющегося радиуса прибытия, с учётом зарезервированных мест. Уже прибывших и собственную группу не перетасовывает; телепорта нет.
- `group_nav_pair_v1`: для двух союзных входящих с общей целью может назначить согласованные места при видимом выходящем через ту же дверь; требует селектор, `crowd_nav_v2` и уступание. Это не общая очередь. Контакт отменяет мирный манёвр.
- `vision_nav_fast_v1`: не проводит ненужное наблюдение препятствия в бою и при стабильном групповом движении, а при уже известном контакте пропускает и поиск соседей. Необследованное препятствие помечается `null`, не «путь свободен»; выбор цели и стрельба не меняются этим кодом.

Критерий сцен включает прибытие, пересечение, отсутствие столкновения со стеной/превышения скорости/внутригруппового наложения в точках проверки. Для автопилота метрика внешних пересечений дана отдельно; начальное появление техники может уже создавать пересечение. Между обновлениями отдельных юнитов пересечения не охвачены, проверка промежуточных рёбер маршрутов через стены не реализована. Диагностические скрипты возвращают код 1, когда строгие случаи остались неуспешными. Подробные пары: `CROWD_FIXES_AUTOPILOT.json`, `CROWD_FIXES_ISOLATED.json`, `CROWD_SLOT_COLUMN.json`, `GROUP_PAIR_{MIXED_DOORS,AUTOPILOT,COLUMN}.json`, `VISION_FAST_{MIXED_DOORS,AUTOPILOT,COLUMN}.json`.

### Стоимость и ограничения

20 парных коротких боёв с полным набором экспериментов и fast off/on дали одинаковые 502/502 выстрела, 696/696 выборочных контактов, 0 убийств и 0 завершённых войн (`VISION_FAST_COMBAT.json`). При fast в этих сценах зафиксировано 3643 пропуска полного локального поиска при известном контакте и 20074 пропуска датчика препятствий в других подходящих вызовах; это **число пропущенных вызовов, не доказанный прирост FPS**. Бои короткие, сохранение баланса и 100 завершённых войн не проверены.

Отдельная последовательная Node-нагрузка с чередованием порядка, 3 seed, 30 тиков прогрева и 120 тиков измерения: при стартовых 400 среднее время тика 43,82 → 44,59 мс, при 500 — 68,57 → 67,67 мс. Численность к концу выросла до 422/522; выстрелов не было, поэтому это не боевая FPS-проверка. Из-за малого числа прогонов и шума ускорение общего тика **не доказано**. Chromium software/headless не заменяет измерение на пользовательском GPU. `VISION_FAST_LOAD.json`.

Откат каждого из slot/pair/fast при выключенном новом флаге проверен относительно соответствующего предварительного снимка: по 20 seed × 61 снимок графа совпали; добавленные записи конфигурации удалялись только в тестовой копии. Граф не покрывает полноценно замыкания, глобальные переменные, прототипы и идентичность разделяемых буферов. `CROWD_SLOT_OFF_COMPARE.json`, `GROUP_PAIR_OFF_COMPARE.json`, `VISION_FAST_OFF_COMPARE.json`.

Вывод: заметное частичное улучшение есть, но 46 сцен автопилота, внешние пересечения, 37 сцен двух выходящих, полная очередь и проверка всех рёбер остаются открытыми. Флаги не включены по умолчанию; публикации не было.

Отдельно сравнен пакет guard + slot + pair + fast off/on при включённых в обоих вариантах селекторе, группе 3–5, обходе, crowd, уступании и коллайдерах: в 20 парных 30-секундных столкновениях 512 → 502 выстрела и 718 → 696 выборочных контактов, 0 убийств/завершённых войн, `pathFailed` 0 → 0 (`CROWD_FIXES_COMBAT.json`). После изменения поведения одинаковый seed не гарантирует одинакового расхода RNG; это описательные наблюдения, не оценка баланса.

После этих изменений прошли полный `npm test` (`CROWD_FIXES_NPM_TEST.log`), `npm run test:browser`, `npm run test:vision-policy:browser` и `git diff --check`. Снимки исходного кода для off-сравнений были временными в `/tmp`; JSON сохраняет хэши использованных файлов, но для повторения нужен соответствующий исходный снимок.
