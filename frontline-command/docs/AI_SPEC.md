# AI_SPEC — три уровня ИИ

## 1. Обзор

```
StrategicAI (4–7 с)  →  директивы и приказы через Command API
        ↓
SquadAI (0.2–0.5 с)  →  фазы, формации, якорь, отступление
        ↓
Soldier AI (1–10 Гц) →  цель, укрытие, огонь, мораль, лечение, ремонт
```

Частота солдата — LOD: near (< 800 px) 10 Гц, mid (< 1600 px) 4 Гц, far 1 Гц.
Между «мыслями» каждый кадр обновляются движение, перезарядка, огонь и таймеры.

## 2. Стратегический уровень (`ai_strategic.js`)

1. **Оценка секторов.** Влияние + присутствие юнитов + близость к своим точкам.
2. **Угрозы.** Сектора, где враг сильнее, и очередь на оборону: сначала HQ,
   затем города, затем фабрики/склады.
3. **Атака.** `attack = value × 1.2 − расстояние × 0.9 − угроза + слабость`,
   порог из `ai_weights.json` (`attackThreshold`).
4. **Сбор группы.** Перед атакой стратег берёт отряды, пока их суммарная сила
   не достигнет 1.25 × (сила врага + 1). Нет сил — атака не начинается.
5. **Директивы.** До `directiveLimit` одновременных; каждая запоминается в
   `assignments`, повторно на ту же цель — не раньше 25 с.
6. **Захват HQ.** Когда у врага остаётся мало городов/сил, вес HQ (3.0) выводит
   его в первые цели; к нему идёт до 3 отрядов.
7. **Персоналия.** aggressive/balanced/cautious меняют только веса из конфига.

## 3. Отрядный уровень (`ai_squad.js`)

* Якорь отряда = цель (или точка удержания): отряд не «ползёт» отдельным
  якорем, а идёт общей задачей по одному потоковому полю на весь отряд.
* Фазы стратегии: `probe → suppress → press` (осторожно), `charge` (натиск),
  `fix → turn` (фланг), `spread → close` (окружение).
* Условия перехода — из `strategies.json`: контакт, потери, боеприпасы, подавление.
* Формации: линия, клин, свободная; интервал из `ai.squad.formationSpacing`.
* Отступление: потери > 50% или HP отряда < 35% → `retreat` к `retreatPoint`
  (свой склад/HQ), при восстановлении — `regroup` и возврат к задаче.
* Снабжение: при БК < 22% — `resupply` к ближайшему своему складу/HQ/фабрике.

## 4. Солдат (`ai_soldier.js`)

Приоритеты Behavior Tree:

1. **Паника** (мораль < 20): бежать к рубежу/командиру, искать укрытие рядом.
2. **Ранен** (`downed`): ждать медика.
3. **Контакт:** огонь по ближайшей цели; если далеко — сближение до 0.7 дальности;
   смена укрытия при подавлении.
4. **Слышал выстрел / помнит врага:** проверить направление.
5. **Приказ отряда:** двигаться в свой слот формации через потоковое поле.
6. **Инженер:** чинить/строить ближайший чертёж.
7. **Медик:** поднимать раненого.
8. **Нет БК:** идти к своему складу.

Мораль (0–100): командир в 420 px → `commanderPerSec`, иначе `noCommanderPerSec`;
укрытие → `inCoverPerSec`; подавление → штраф; нет контакта и отряд не отступает →
`+1.0/с` восстановление (иначе отряды навсегда застревали в панике).

## 5. Восприятие

* Конус зрения ≈110°, радиус из `units.json` (пехота 500, танк 600).
* LOS блокируют только бункеры и лес (плюс сам рельеф для зрения).
* Слух: выстрел в радиусе 620 px даёт «направление», не позицию.
* Память: 6 с после потери видимости.
* Обнаружение вблизи (120 px) — без учёта конуса.

## 6. Общие правила
* ИИ и игрок пользуются одним Command API и одинаковыми лимитами.
* ИИ не получает бонусов к урону/HP; сложность меняет реакцию и точность оценки.
* Все пороги — в `data/ai_weights.json`, ни одного магического числа в коде.

## 8. Обновления алгоритмов в 0.10.0

Каждое изменение включается флагом в `data/feature_flags.json`; числа — в `data/*.json`,
не в коде. Замеры «до/после» — в `PERF_BASELINE.md`.

### 8.1 Карта угроз (`build.refreshThreat`)
Раз в 5 с для каждой фракции считается угроза сектора: близость вражеской территории
(до 1.2 вклада), давление соседей (0.25 за вражеского соседа), сила врага в секторе
(0.35) и близость к линии фронта (до 1.6). Значение сглаживается (0.85 от прошлого).
Флаг `ai_auto_plan`. Метрика: 0 тайм-аутов из 80 войн (было 4/80).

### 8.2 Гистерезис захвата (`influence.updateCapture`)
Порог старта 1.35, порог удержания 1.0, пауза 10 с после смены флага, терпение 3 с при
паритете, спад 0.2 за тик. Флаг `capture_hysteresis`. Метрика: средняя длительность
317 → 290 с, мерцание флага в журнале исчезло (проверяется вручную по журналу).

### 8.3 Политика стройки (`build.buildWanted`)
Строим, только если армия ≥ 24, материалы ≥ 150, с кулдауном 25 с и пределом 10 открытых
чертежей. Флаг `ai_auto_plan` (общий с планировщиком). Метрика: армии на 100-й секунде
10–19 → 25–31 бойцов, длительность 398 → 317 с.

### 8.4 Дедупликация укреплений (`planZone` + `maxFortsPerPoint`)
Повторный профиль у уже укреплённого узла пропускается; позиции ближе `dedup` (96 px) к
стоящим укреплениям не планируются. Метрика: 25–30 % меньше фортов за войну, 19/20 → 36/40
решённых войн.

### 8.5 Штурм укреплений (`tryShootBuilding`)
Юнит, у которого нет живой цели и который наступает, идёт к ближайшему вражескому форту в
радиусе оружия (через укрытие) и стреляет: 90 % урона, снаряды — взрыв. Флаг
`assault_forts`. Метрика: форты сносятся (14 → 17 построек у обороняющегося за 200 с),
19/20 → 19/20, но 18/20 без флага при той же настройке.

### 8.6 Измор (`game.resolveByPoints`)
После 900 с войны побеждает сторона с большим числом ключевых городов, затем точек, затем
живой силы. Флаг `sudden_death`. Метрика: 80/80 финалов, 0 тайм-аутов (было 76/80).

### 8.7 Выбор строителя (`build.scoreBuilder`)
Полезность = расстояние + безопасность + навык + приоритет чертежа − занятость; веса в
`ai_weights.json → buildWeights`. Флаг `build_builder_utility`. Метрика: длина очереди
между приказами 22 → 16, приоритетные чертежи достраиваются первыми (тест `tests/build.mjs`).

### 8.8 Что не сделано
Резерв обороны отдельными отрядами (`defense_reserve`) и разделение армии на эшелоны
(авангард/основные/резерв) не реализованы: флаг удалён из `feature_flags.json`, чтобы не
обещать несуществующее. План — в `OUTLINES.md` §«План на следующую версию» (этапы 1–2).
