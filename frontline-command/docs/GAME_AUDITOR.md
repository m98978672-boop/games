# Общий проверяющий всей игры

`npm run audit:game` запускает проверяющий **всей игры**, а не только первого
блока, и печатает JSON. `npm run audit:game:human` выдаёт человекочитаемый
отчёт. Варианты `audit:game:quick` и `audit:game:quick:human` выполняют
частичные проверки и **не могут** принять игру. Ненулевой код процесса означает,
что приёмка не пройдена; это не числовой код конкретной ошибки.

Коды 001–499 принадлежат проверяющему блока 1 (`BLOCK1_AUDITOR.md`). Для всей
игры также используются:

| Коды | Значение |
|---|---|
| 500–539 | Полная приёмка ALG-01…40 соответственно не подтверждена. Код 500 — ALG-01, код 539 — ALG-40. |
| 580 | Не подтверждены интеграционные сценарии S1–S10 всей игры. |
| 590–591 | Ошибка манифеста либо структурно повреждённый/отсутствующий PNG. |
| 592 | Реестр помечает графику как заглушки. |
| 593 | В функции отрисовки игровых стен обнаружены линии Canvas. |
| 594 | Не подтверждены согласованные дополнительные предрисованные направления спрайтов. |
| 595–596 | Не удалось прочитать реестр происхождения или рендерер. |
| 597 | Не подтверждена регрессия скриншотов в настоящем браузере. |
| 598 | Не подтверждены происхождение и допустимые права отдельных изображений. |
| 599 | Не удалось прочитать все 40 алгоритмов или их контракт. |

000 зарезервирован для отсутствия ошибок, остальные неиспользуемые номера не
заполнены вымышленными ошибками. Одна причина может относиться к нескольким
алгоритмам; количество замечаний — не количество подтверждённых дефектов.

## Что действительно проверяется

1. Читается историческая таблица `ALGORITHMS_SPEC.md`, проверяется наличие всех
   40 строк и каждого требуемого флага в текущем конфиге. Для каждого алгоритма
   показаны исторические замечания **с пометкой об их происхождении**, состояние
   текущего флага и наличие отдельного приёмочного сценария. Историческое
   описание может устареть: оно не выдаётся за заново подтверждённый дефект.
2. `data/game_audit_contract.json` задаёт минимальные обязательные случаи для
   каждого ALG, включая симметрию и legacy off. Если файл
   `tests/acceptance/alg-NN.mjs` существует, полный режим запускает его и
   проверяет JSON, код выхода, отдельные случаи и флаг по умолчанию. Быстрый
   режим существующие тесты не запускает. Пустой JSON, фальшивое `passed` без
   случаев, дубликаты или отсутствующий тест не проходят. Список случаев —
   минимум, а не замена полному ТЗ: содержание тестов и доказательств требует
   ревью. Наличие механики, флага или старых smoke-тестов не считается приёмкой.
3. Визуальные файлы из манифеста проверяются на сигнатуру, структуру, CRC,
   читаемость сжатых данных и наличие. Это **не** просмотр картинки, проверка
   правильности всех пикселей, анимации или лицензии. Отдельно анализируются
   реестр заглушек и текущие функции отрисовки стен/направлений. Проект —
   2D Canvas: «модельки» здесь проверяются через растровые спрайты и их
   направления, а не вымышленную 3D-сцену.
4. Отдельные сценарии `visual-regression.mjs`, `asset-provenance.mjs` и
   `game-scenarios.mjs` должны предоставить необходимые доказательства;
   отсутствие или неподходящий результат блокирует приёмку. Проверка структуры
   реестра происхождения не заменяет юридическую проверку внешних лицензий.
5. Запускается прежний проверяющий блока 1, его коды и полный результат
   включаются в общий отчёт. Условия блока 1 не ослаблены. Проверяющий —
   программа, не фоновый агент и не автоматический разработчик.

`GAME_AUDIT_REPORT.md` и `GAME_AUDIT_BASELINE.json` — сохранённый результат
конкретного полного запуска. После изменений нужно запускать проверяющий заново.
`unverified` означает «нет достаточных доказательств», а не обязательно «код не
работает». Состояние текстур, поведение юнитов, браузерный FPS и баланс нельзя
принимать по одной только проверке файлов или по headless-тику симуляции.
