# Near objectives separated by an obstacle

The prior squad logic declared an order reached using only the centroid's distance. A nearby objective across a solid wall therefore triggered `hold` without the squad going around the building. Formation and safe-rest correction could also put the destination back on the mover's side of a wall.

The normal game now requires a clear short final approach to the objective, checked from a living squad member as well as the centroid-distance condition. Infantry arrival uses the same wall/terrain check. An advancing infantry formation slot separated from its anchor, or embedded in a wall, falls back to the clear anchor. Rest-position correction prefers the destination's building side when that destination is itself legally occupiable; ambiguous points inside walls retain the old fallback. Existing pathfinding, doors and collision checks still perform the movement. These checks do not prove a full route exists, nor make every group or vehicle capable of detouring around every obstacle.

`tests/wall-route-arrival.mjs` runs actual radio orders and `Game.step` using the real HQ wall and doors: two factions, entering/exiting, move/hold orders, two seeds (16 trials, with mirrored/repeated geometry). On the pre-change source, 16/16 reported arrival on the wrong side; after the change 16/16 reached the correct side within 3.1–3.8 simulated seconds, with no detected wall crossing or overspeed. This is one tightly controlled obstacle family, not 16 independent battles. `arrival-obstacles.mjs` covers short-range wall and impassable terrain checks, and target-side preservation. Chromium exercised eight of the wall-order cases, the existing synthetic U-detour, and a normal running game without page errors.

Full `npm test` reached its final performance test with other tests, including wall/door navigation, squad orders, symmetry and duel, passing. It failed the 400-unit performance threshold (16.76 ms/tick against 16.67 ms), so the full suite is **not green**. In a separate sequential comparison, pre-change code passed 400 at 16.01 ms and failed 500 at 23.48 ms; new code passed 400 at 16.62 ms and failed 500 at 22.58 ms (limit 22.22 ms). These are noisy Node simulation-only measurements, not browser FPS or a controlled performance equivalence proof. The game previously also failed this stress budget; this change does not fix that capacity limit. A 5px-radius single-unit test also showed an outside-to-inside case not reaching its exact near-wall goal in 60 seconds: the targeted squad fix is not a general solution for all narrow routes or unreachable targets.
