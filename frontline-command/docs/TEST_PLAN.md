# TEST_PLAN — как проверяется игра

## 1. Уровни проверки

| Уровень | Файл | Что проверяет |
|---|---|---|
| Логика | `tests/logic.mjs` | конфиги, Command API, задержка радио, отказы, лимиты, симметрия правил, победа |
| Симуляция | `tests/sim.mjs` | 60 с боя без исключений, приказы, снабжение, влияние |
| Симметрия | `tests/symmetry.mjs` | ИИ против ИИ, стороны местами, метрики исхода |
| Производительность | `tests/perf.mjs` | 392 юнита, 500 шагов, бюджет тика и память |
| Браузер | `tests/browser.mjs` | jsdom: меню, старт, режимы, пауза, скорость, ИИ-ИИ |

Запуск: `npm test` (всё) или `npm run test:fast` (без длинных прогонов).

## 4. Известные проблемы (честно)

1. **Тайм-ауты закрыты, но рецепт хрупкий.** На 40 войнах (сиды 31–50, обе
   ориентации) финалов 40/40. Держится на связке: концентрация сил, резерв
   директив, режим добивания, all-in после `stallSeconds` и капитуляция после
   `surrenderSeconds` без армии. Любой из этих рычагов легко «перекрутить» —
   после правок гонять `node tools/ai-war.mjs --seeds 31-50` и со `--swap`.
   Что уже сделано: концентрация сил (1–2 цели за цикл), резерв директив под
   наступление, режим «добивание», all-in при простое без захватов, аварийная
   сборка отряда из резерва. Рычаги: `ai_weights.strategic.stallSeconds`,
   `allInPowerFactor`, `finishUnitsBelow`, `finishHqBoost`, `capture.seconds`.
   Проверка: `node tools/ai-war.mjs --seeds 31-50 --verbose`.
2. **Летальность боя** выше «реалистичной»: 6×6 пехоты решается за 30–60 секунд.
   Это осознанный выбор ради темпа, но требует плейтестов.
3. **Экономика** позволяет восстанавливать отряды быстрее, чем ИИ успевает
   развить успех (материалы 1400 старт + производство). См. `BALANCE.md`.
4. **Графика и звук — плейсхолдеры** (`PLACEHOLDER_REPLACE`).
5. **Мобильные устройства** не поддерживаются: интерфейс рассчитан на мышь.
6. **Сетка секторов и дороги зеркальны, но держится на данных.**
   `hex.originX/originY` в `data/sectors.json` подобраны так, чтобы зеркало центра
   сектора было центром сектора; при правке `cols/rows/size` тест `tests/symmetry.mjs`
   сразу упадёт — это ожидаемо, пересчитывать origin по формуле
   `originX = (W − 1.5·size·(cols−1))/2`, `originY = (H − √3·size·(rows−1))/2`.
7. **Короткие войны.** 12 из 20 войн решаются быстрее 2.5 минут: прорыв к
   ключевым городам успевает случиться до развёртывания второй стороны.
   Пробовал garrison-правило для ключевых городов — войны наоборот ускоряются,
   нужен аккуратный вариант (резерв одного отряда на ключевой город + запрет
   снимать его в all-in). Второй рычаг — `capture.secondsByType.city`.

## 5. Что проверять руками после каждого изменения

* Старт новой войны (солдат) → `Tab` → выдать директиву → `Tab` обратно.
* Отказ приказа: довести отряд без БК и попробовать атаковать — причина в тосте.
* Стройка: `B` → окоп → `ЛКМ` → инженер достраивает (журнал, прогресс).
* Автопилот: выключить «Бой» → армия перестаёт наступать (только оборона).
* Сохранение: пауза → «Сохранить» → выход в меню → «Продолжить».
* Конец войны: дождаться результата или захватить штаб.
