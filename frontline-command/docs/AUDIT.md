# AUDIT — Frontline: Command, версия 0.10.0

> Аудит перед обновлением: что есть, чем измеряется, где болит. Все числа получены на
> этой машине (Node 22.22.3, без GPU-ускорения), поэтому их можно воспроизвести командами
> из раздела «Как проверить».
>
> Важное отличие от исходного техзадания: проект — браузерная 2D-игра на JS + Canvas 2D,
> без Godot, без 3D-мешей и без физического движка. Пункты ТЗ про Godot (`NavigationServer`,
> `CollisionShape2D`, `.tscn`, импорт из Blender) переведены на наши эквиваленты:
> секторная навигация `src/sim/nav.js`, коллизии по сетке `world.isWalkable`,
> отрисовка `src/render/renderer.js`. Там, где эквивалента нет (запечённые меши-обводы,
> LOD-меши), честно написано «не сделано» — см. `OUTLINES.md`.

## 2. Состояние до обновления (0.9.3, коммит `5687bce`)

**Строительство.** Один режим: одиночная постановка под курсор. Профили обороны
(`data/build_profiles.json`) — плоский список «тип × количество», расстановка дугой вокруг
точки. Отказы возвращали свободный текст («место занято»), а не код, поэтому ни UI, ни
журнал приказов, ни тесты не могли отличить «нет места» от «нет материалов».
Очереди как сущности не было: чертежи лежали списком, инженеры брали ближайший.
В `src/sim/build.js` — 202 строки, никаких линий, зон, шаблонов, приоритетов.

**Захват точек.** Порог `ratio` 1.35 применялся и к старту, и к продолжению захвата:
как только перевес падал до 1.2, прогресс таял со скоростью 0.35 за тик. На практике это
давало «мерцание» флага в позиционных боях: точка переходила из рук в руки по 3–5 раз.

**ИИ.** Автопилот ставил профиль после каждого захвата, без учёта того, что узел уже
укреплён, и без оглядки на экономику: стройка конкурировала с производством отрядов.

**Метрики 0.9.3** (40 сидов, `--seeds 31-70`, обе ориентации, лимит 1200 с):

- решено 76/80, тайм-аутов 4 (5 %);
- длительность: 276 с (без swap) и 340 с (swap), максимум 1200 с;
- стороны: Альянс 37 / Легион 39 из 76 решённых;
- производительность: 2.59–2.98 мс/тик, куча 19–21 МБ;
- дуэль: 5/3, перекос 63 %;
- симметрия: 0 асимметричных секторов, расхождение рельефа 0/16 384.

## 3. Найденные узкие места (по приоритету)

1. **Нет кодов причин.** Нельзя ни объяснить отказ игроку, ни проверить правила тестом.
2. **Нет массовых инструментов.** Оборонительную линию из 20 секций приходилось ставить
   двадцатью кликами; зоны по профилю игрок не мог задать вообще (только приказ ИИ).
3. **Профиль обороны не описывает глубину.** «Окоп ×4, проволока ×4» не говорит, что
   ставить впереди, а что в тылу; ИИ строил всё в одном кольце.
4. **Захват без гистерезиса** → мерцание флага и потеря прогресса при малейшем равенстве.
5. **Стройка без экономической политики** → маленькие армии и затяжные войны
   (в 0.9.3 средняя война 276–340 с при 4 тайм-аутах на 80 прогонов).
6. **Укрепления нельзя было разрушить стрелковым огнём.** Юниты стреляли только по юнитам;
   постройки получали урон лишь от взрывов. Форты были вечными препятствиями.
7. **Технические обводы (§5 ТЗ)** отсутствуют как класс: коллизии считаются по сетке,
   обводы для отрисовки/навигации не генерируются и не валидируются.

## 5. Как проверить

```bash
cd frontline-command
npm test                     # логика, строительство, сим, симметрия, дуэль, перф
node tools/ai-war.mjs --seeds 31-70            # 40 войн
node tools/ai-war.mjs --seeds 31-70 --swap     # 40 войн с обменом сторон
```

Результаты этого прогона — в `PERF_BASELINE.md` и `BALANCE.md`.
