# Слои физики: что и в каком порядке блокирует

Документ фиксирует единственный порядок проверок, чтобы движение, пули, обзор и укрытие
никогда не расходились между собой (частый источник «стреляю сквозь стену, но пройти не могу»).

## 1. Движение

```
water (terrain)            → непроходимо всегда
bridge                     → проходимо (перекрывает воду)
buildings: bunker          → проходим весь прямоугольник (legacy, только при стенах off)
walls: segments blocksMove → проходимо только через door/gate/breach
units                      → расталкивание, не блокирует
```

Проверка на шаг юнита (`units.moveUnit → free(x, y)`):

1. `world.isWalkable()` в 5 точках (центр + 4 угла по радиусу) — тайловая сетка 32 px;
2. `walls.blocksMove(x, y, radius, u)` — точная геометрия сегментов (толщина/2 + радиус);
   для техники дополнительно запрещены `door`, `window`, `embrasure` (только `gate`/`breach`).

Навигация (flow-field 64 px) строится из того же `world.walk[]`: сегменты растеризуются
`_markWallTiles()`, открытые двери/ворота и проломы пропускаются.

## 2. Пули и снаряды

```
выстрел → game.raycastBlocked(x1, y1, x2, y2, weapon)
  1) лес/бункер (losBlock, шаг 20 px — legacy)
  2) walls.bulletRay(...)  ← точный ray-segment, без туннелирования
       segment  → penetrationChance(material, weapon, stage)
                  попал  → damageMult (потеря урона материалом)
                  пробил → пуля идёт дальше
       opening  → door (открыта?) / window (всегда сквозь, но частично) /
                  embrasure (15 %) / breach (сквозь)
```

Пуля **никогда** не проверяет `world.walk[]` — стены и проёмы знают только сегменты.
Луч обрабатывается за один проход по сетке 128 px, без сэмплирования по дистанции.

## 3. Обзор

`world.hasLOS(a, b)`: лес + бункер (legacy) → `walls.blocksVision()`:
сплошной сегмент и закрытая дверь и бойница перекрывают, окно/пролом/открытая дверь — нет.

## 4. Укрытие

`world.bestCover(x, y, threat)`:
1. `walls.coverSpotsNear()` — точки у сегментов с нормалью; оценка направленная
   (нормаль к угрозе лучше) и учитывает класс высоты материала;
2. если стен нет — прежний перебор зданий по `def.cover`.

Урон по цели: `applyDamage()` × `damageMult` от стены, если пуля её пробила.

## 5. Разрушение

```
damageSegment → стадия (intact/damaged/critical/breach) → invalidateCover + queueNavRebuild
queueNavRebuild → walls.update() в бюджете nav_budget.json (≤ 1.5 мс/кадр) → walk[] обновлён
```

Навигация обновляется не позже 1 с после пролома (измерено 0.05 с), LOS/укрытия — мгновенно.

## 6. Инварианты (проверяются тестами)

- Замкнутость контура: разрыв ≤ 0.5 px (`tests/walls.mjs`, тест 1).
- Непроходимость: 1000 из 1000 попыток пересечь сегмент шагом 1 px остановлены (тест 2).
- Туннелирование: луч 2800 px сквозь бетон блокируется и в новом, и в старом коде (тест 4).
- Из-за сплошной стены 0 попаданий для оружия без пробивания (тест 6).
- Никаких телепортов: шаг юнита ≤ 3× скорости за тик, со стенами и без (тест 9).
- Флаг off: стены не влияют ни на что; 60 с симуляции совпадают с эталоном до 0.001 px (тест 12).
