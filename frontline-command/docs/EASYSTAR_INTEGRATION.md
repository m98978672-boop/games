# EasyStar.js в навигации игры

Использована настоящая JavaScript-библиотека [EasyStar.js 0.4.4](https://github.com/prettymuchbryce/easystarjs) (MIT), а не новый собственный поиск. Официальный npm-архив `easystarjs-0.4.4.tgz`; SHA-256 входного `bin/easystar-0.4.4.js`: `f906123a47de14cde70c6467c33e897ca8d28f48d15b174e74a0c674efd1967b`. Библиотека поставляется локально, интернет игроку не нужен. Её исходный bundle сохранён в `src/vendor/easystar.js`, лицензия автора — `src/vendor/EASYSTAR-LICENSE.txt`. В бандл включён `heap` 0.2.6, порт Xueqiao Xu из Python heapq: его PSF-лицензия и уведомление в `src/vendor/HEAP-LICENSE.txt`; изменение относительно Python — портирование heapq на JavaScript. Оригинальный npm-пакет содержит именно версию 0.2.6, а не лицензию более поздней 0.2.7.

Два изменения в библиотеке: ESM-экспорт для браузера и вызов callback сразу после окончания расчёта (вместо `setTimeout`, поскольку тесты и симуляция могут шагать синхронно). При этом `enableSync()` **не** включён: он убирает в оригинале лимит числа итераций. Исходники библиотеки и адаптера различаются; лицензии и ограничения сохраняются.

`src/sim/easystar_route.js` адаптирует библиотеку к нашей карте: заранее собирает локальную сетку 32 px небольшими порциями, учитывает радиус бойца/машины и стены с запасом, запрещает срезание углов, проверяет каждый полученный отрезок по реальной геометрии, отменяет устаревшие задачи при смене цели/карты. Запрос ограничен 16 384 клетками и областью с запасом 512 px; сетка консервативна, поэтому узкий, но проходимый проход может быть отклонён. Это не навигационная сетка Detour и не решение толпы. Вычисление 64 операций/итераций за срез не является гарантией времени в миллисекундах: подготовка, проверка отрезков и `setGrid` тоже стоят времени.

В игровом цикле EasyStar заменил только поиск под уже существующим `smart_route_v2`; этот флаг **по умолчанию выключен**. Повод: нагрузочные прогоны не показали стабильного улучшения, а колонны и встречные пары не решены. Настоящее замещение алгоритма в готовой игре не означает автоматической приёмки.

## Проверки

```sh
node tests/easystar-route.mjs
node tests/smart-route.mjs
node tests/easystar-browser.mjs
node tools/audit-u-trap.mjs --smart-route
node tools/audit-u-variants.mjs --smart-route
SMART_ROUTE=1 node tests/acceptance/block1-doorways.mjs --attempts=25
node tools/audit-baseline.mjs 5 --smart-route
```

* Одиночная U-ловушка: 18/18; расширенные варианты: **216/216**, без измеренных столкновений и телепорта. Штатные выключенные флаги: 8/18 и 64/216. Это не оценка боя или толпы.
* Проходы с одним юнитом: по 50/50 в каждом из восьми направлений; колонна **0/50** без отдельного экспериментального режима колонны. Встречные пары алгоритм A* сам не решает.
* Девять пар 60-секундных сцен (seed 5, 7, 11, по 100/300/400 юнитов): метрика непрогресса снизилась в 5 парах, выросла в 2, совпала в 2. Бой и общий RNG расходятся; это не строгая причинная оценка. p95 измеренного среза 0,104–0,440 мс, максимум 9,492 мс на данной машине в этих прогонах; одновременно работала другая проверка, браузерный FPS не измерялся. Исходные результаты и хеши — `EASYSTAR_INTEGRATION.json`.

## Другие проверенные подходы

[Recast/Detour для JavaScript](https://github.com/isaac-mason/recast-navigation-js) предоставляет navmesh, поиск, симуляцию толпы и временные препятствия. Он требует преобразования нашей 2D-карты и динамических дверей в navmesh/WASM и не подключён. [OpenRA](https://github.com/OpenRA/OpenRA) — полноценная RTS на C# под GPL-3.0-or-later, не совместимая с прямой заменой JS-кода без оценки лицензии и переработки движка. В качестве подхода к replay у [simcore](https://github.com/yasserreslan/simcore) используются фиксированный шаг, запись команд, RNG и проверка контрольных сумм; это не означает, что сохранения нашей игры уже детерминированы.

Проверка EasyStar в настоящем headless Chromium и стандартный `npm test` прошли; `npm run test:browser` отдельно пропускается из-за отсутствия jsdom и не считается успехом. Полный аудитор не запускался после этой замены. Быстрый аудит штатной конфигурации после неё: `NOT_ACCEPTED`, 13 блокеров. Колонна, встречные потоки, массовая нагрузка, логистика, сохранение/replay и отсутствующие стенды остаются открыты. Изменение не опубликовано.
