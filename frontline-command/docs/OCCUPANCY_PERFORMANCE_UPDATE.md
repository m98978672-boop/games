# Оптимизация коллизий юнитов

При первом запуске проверки PR `a29977d` GitHub Actions остановился на производительности: 400 юнитов, 17,40 мс/тик, 57 вместо требуемых 60 FPS **только симуляции**. Следующий запуск более позднего коммита `6544fc8` прошёл, то есть результат зависит от нагрузки и окружения; это не основание игнорировать первый провал.

Для уменьшения цены без изменения правил:

- `Walls.refsInBox` перебирает только ячейки, пересекающие прямоугольник запроса; геометрические ссылки заранее индексируются с учётом толщины стены. Используется для проверки и поиска безопасной точки отдыха. Старый `refsNear` сохранён для других пользователей и заглушек.
- Проверка занятой траектории сначала отбрасывает круги вне ограничивающего прямоугольника всего отрезка с учётом суммы радиусов. Остальные кандидаты проверяются прежней формулой проекции и прежним правилом восстановления существующих наложений.
- Поиск кандидатов группы использует прямоугольный запрос пространственного индекса с тем же последующим точным круговым ограничением.

Проверки:

- `tests/rest-position-broadphase.mjs`: 4000 положений и 500 целей совпадают с прежним консервативным поиском.
- `tests/solid-unit-broadphase.mjs`: 15000 случайных запросов на движение, разные радиусы, касания и исходные наложения совпадают с исходным исчерпывающим вычислением.
- `OCCUPANCY_OPT_PARITY.json`: по 301 снимку в 8 обычных играх (4 seed, режим столкновений off/on) совпали выбранные поля состояния и RNG со снимком исходников коммита `6544fc8`. Это не сравнение полного графа объектов и не гарантия всех возможных ситуаций.
- Повтор `tools/movement-occupancy-door-paired.mjs --seeds=20`: результат 480 пар идентичен `MOVEMENT_DOORS_DEFAULT_ON_CHECK.json`, без наблюдённых пересечений в режиме on.
- Три локальных прогона `node tests/perf.mjs` после оптимизации: 400 юнитов 12,04 / 12,50 / 11,95 мс на тик; 500 — 17,05 / 16,51 / 17,68 мс. До оптимизации локально измерялось 14,34 и 20,15 мс. Прогоны не являются строгим парным бенчмарком, отличаются условия нагрузки; это симуляция, не браузерный FPS. Прохождение порогов на любых машинах не гарантируется.

Старое короткое сравнение браузерной нагрузки в `MOVEMENT_DEFAULT_UPDATE.md` было сделано до оптимизации. Оно не является валидной приёмкой FPS, в частности из-за меняющейся численности и headless software rendering.
