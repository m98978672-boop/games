## 0. Главные законы проекта

- **R-0.1. Закон промта.** Всё, что обсуждено, решено или придумано, обязательно фиксируется в `ratcore/SPEC.md`, `ratcore/AI_CONTRACT.md` и `ratcore/DEVLOG.md`. Если правило существует только в чате — оно считается потерянным.

- **R-0.4. Закон обязательности инструментов (`ToolGuard`).** Ни один ИИ и ни один скрипт сцены не имеет права собирать модельки, меши, текстуры или куски карты вручную «в обход» инструментов `RatCore.tools.*`. Это обеспечивается технической блокировкой в рантайме, контрактом и статическим тестом (см. §2).

## 1. Назначение и ключевая идея `RatCore`

`RatCore` — это собственный **2D/3D AI-Native игровой движок с нуля** с:
1. **Графово-координатным миром** по принципам `РАТГРАД` (`country-atlas`): единая плоскость `(X, Y)`, две высоты `H` и `h`, 64-битный ID грани (`BigInt`), слоевая запись `(X;Y)Hp(...)`, граф точек и связей, процедурная постройка карт и чанки с LOD.
2. **Растровой графикой и тройным рендером на одних данных**:
   - 2D растровый рендер (`Uint32Array` + `ImageData` / `ImageBitmap`),
   - 3D программный растровый рендер (Software 3D + Z-buffer + Object-ID буфер — работает даже без GPU и в Node.js),
   - 3D аппаратный WebGL2-рендер с нуля (без Three.js, с инстансингом и текстурным атласом).
3. **Лёгким построением моделек, мешей и текстур** через высокоуровневые инструменты-рецепты (`extrude`, `loft`, `lathe`, `layer`, `voxels + greedy meshing`, `primitive`, `combine`, `tex.generate`).
4. **Полным набором инструментов на все случаи жизни (36 веток) с 3-уровневым подключением «по выбору» (`Zero-Cost Opt-In`)**:
   - **Ядро (всегда включено, ~28–35 КБ):** `build`, `move`, `remove`, `watch`, `look`, `see`, `input`, `ui`, `save`, `stream` (`CoreGovernor 75 %`), `ToolGuard`;
   - **Стандартные жанровые модули (по жанру):** `anim`, `phys`, `nav`, `env`, `fx`, `ai`, `sim`, `audio`, `hear`, `test`;
   - **14 опциональных пакетов по выбору (`0 Б` RAM/CPU/бандла, пока не включены!):** `pack:multiplayer` (`net`), `pack:destruction` (`destroy`), `pack:narrative` (`story` + `quest`), `pack:mods` (`mod`), `pack:cinema` (`cutscene`), `pack:styles` (`shader`), `pack:voice` (`voice`), `pack:ecology` (`eco`), `pack:companion` (`coopAi`), `pack:assist` (`assist`), `pack:webgpu` (`WebGPU Compute`), `pack:wasm-accel` (`WASM+SIMD < 25 КБ`), `pack:studio` (`RatStudio` + Машина времени + автобалансировщик + экспорт 1 `.html` — только dev!), `pack:ai-team` (`think`, `guess`, `comm`, `bugs`, `bridge`).

Подробный справочник всех **36 усиленных веток инструментов v2.0**, `tools.discover` и таблицы опциональных пакетов — в [`TOOLS.md`](./TOOLS.md), всех **185 формул (`F-01..F-185`) и 125 алгоритмов (`A-01..A-125`)** — в [`ALGORITHMS.md`](./ALGORITHMS.md), архитектура **12-уровневого сжатия RAM/CPU, `ratcore-wire/2`, `Power & Thermal Guard`, `Dynamic Resolution`, `Self-Healing` и `pack:webgpu`/`pack:wasm-accel`** — в [`COMPRESSION.md`](./COMPRESSION.md), архитектура **соединения с другими движками** — в [`BRIDGE.md`](./BRIDGE.md).

## 2. Принудительное использование инструментов ИИ (`ToolGuard`)

Чтобы ИИ **гарантированно** пользовался инструментами движка при построении моделек и мешей, а не генерировал сырые массивы вершин вручную, вводятся **3 уровня защиты**:

### 2.1. Уровень 1 — Закрытая печать происхождения (`Provenance Seal`)
- Внутри `src/core/seal.js` хранится неэкспортируемый `Symbol` / `WeakSet` подписанных артефактов (`SealedMesh`, `SealedTexture`, `SealedMapLayer`).
- Подписать объект имеют право **только** официальные фабрики `RatCore.tools.build.*` и `RatCore.tools.tex.*`.
- Каждый подписанный объект несёт внутри:
  - `provenance.tool` — имя инструмента (`build.extrude`, `build.layer`, …),
  - `provenance.recipe` — точный JSON-рецепт всех шагов построения,
  - `provenance.agentId` — кто вызвал инструмент,
  - `provenance.traceId` и `provenance.tick`.
- При попытке передать в мир, сцену или рендерер неподписанный меш/текстуру:
  - операция жёстко отклоняется кодом **`RC-101` (`RAW_GEOMETRY_FORBIDDEN`)**;
  - возвращается структурированная подсказка с допустимыми инструментами;
  - автоматически пишется запись в `ratcore/reports/audits/` о попытке обхода `ToolGuard`.

### 2.2. Уровень 2 — Рецепто-ориентированный формат (`Recipe-First`)
- Модели описываются и сохраняются как **список операций инструментов** (JSON-рецепт), а не как сырой дамп треугольников:
  ```json
  {
    "modelId": "watchtower_01",
    "ops": [
      { "tool": "build.layer", "args": { "expr": "(0;0)H4(0,0;0,0;0,0)", "tex": "concrete_01" } },
      { "tool": "build.extrude", "args": { "contour": [[-2,-2],[2,-2],[2,2],[-2,2]], "height": 2.4, "bevel": 0.15, "y": 4 } },
      { "tool": "build.lathe", "args": { "profile": [[0,0],[2.6,0],[0.2,1.6],[0,1.6]], "segments": 8, "y": 6.4 } },
      { "tool": "build.validate", "args": { "checkNormals": true, "checkHoles": true, "maxTris": 1200 } }
    ]
  }
  ```
- Повторное воспроизведение рецепта на том же сиде всегда даёт идентичный меш. Любая другая нейросеть может открыть рецепт и безопасно изменить параметр без пересчёта треугольников.

### 2.3. Уровень 3 — Машиночитаемый манифест и статический аудитор
- `ratcore/AI_CONTRACT.md` — обязательный свод правил для ИИ.
- `ratcore/tools-manifest.json` — полная JSON-схема всех инструментов, аргументов, возвращаемых структур и примеров вызовов.
- `ratcore/tests/tool-contract.mjs` — автоматический тест, который проверяет:
  1. попытка добавить сырой меш без печати падает с `RC-101` и оставляет аудит;
  2. попытка пропихнуть поддельную печать извне невозможна;
  3. статический сканер кода сцен/игр на `RatCore` находит прямую сборку вершинных буферов в обход `tools.build.*`.

## 3. Архитектура 7 слоёв движка

### 3.1. Слой 1 — Ядро времени и памяти (`src/core/`)
- **Фиксированный шаг симуляции** (`clock.js`): фиксированный `FIXED_DT` (по умолчанию `1/30` с, макс. 4 подшага за кадр), аккумулятор остатка, интерполяция `alpha` для плавного рендера, игровые часы (сутки, сезоны), пауза и ускорение.
- **Детерминизм** (`math.js`): PRNG с сидом (`mulberry32` / `xoshiro128**`), запрет `Math.random()` в симуляции.
- **Данные в SoA (`TypedArrays`)**: координаты, скорости, флаги и состояния сущностей лежат в плоских типизированных массивах (`Int32Array`, `Float32Array`, `Uint16Array`, `Uint32Array`) с пулами памяти (ноль лишних аллокаций в игровом цикле и zero-copy передача в Web Workers).
- **Floating Origin**: вычисление относительных координат `(X - camX, Y - camY)` в `Float64` перед передачей `Float32` в 3D-рендер — устраняет дрожание геометрии на картах в тысячи километров.

### 3.2. Слой 2 — Графово-координатный мир (`src/world/`, по принципам РАТГРАД)
- **Единая система координат `(X, Y, H, h)`** (`coords.js`):
  - `X` — восток (вправо), `Y` — север (вверх), центр мира `(0, 0)`.
  - `H(X, Y)` — высота поверхности (уровень моря `0`, `< 0` — дно/вода, `> 0` — суша). Высота произвольной точки всегда вычисляется билинейной интерполяцией `F-71` по 4 углам клетки.
  - `h = H + Δ` — мировая высота вершины объекта.
  - Хранение координат в `Int32` (дециметры / сантиметры).
  - Единственная точка проекции в 3D: `scene.x = X`, `scene.y = h`, `scene.z = -Y`.
  - Азимут: `0°` — север (`+Y`), по часовой стрелке (`atan2(dx, dy)`).
- **64-битный ID грани (`BigInt`)** (`face-id.js`):
  - У кубика 1×1×1 м учитываются 5 видимых граней (`0..4`: верх, восток, запад, север, юг; нижняя отбрасывается).
  - Упаковка 6 полей в 64 бита: `s` (3 бита), `i` (16 бит), `j` (16 бит), `k` (13 бит), `t` (12 бит — номер текстуры), `n` (4 бита — слой).
  - Износ и поломка вшиты прямо в поле `t`: `0..2047` — целая текстура, `2048..4094` — повреждённая (`t - 2048`), `4095` — разрушенная/отсутствующая грань.
- **Слоевая запись `(X;Y)Hp(...)`** (`layers.js`):
  - `H` (большая) — строго вертикальный столб, дрейф `D = 0`, смещение координат запрещено и отклоняется валидатором.
  - `h` (маленькая) — наклонный/изогнутый столб, длина вычисляется по вектору `h = √(H² + D²)`, уклон `θ = arctan(D/H)`.
  - Число пар в скобках строго `p - 1` (иначе ошибка записи или явный флаг `carry`).
- **Граф и пространственные структуры** (`graph.js`, `spatial.js`):
  - Универсальные узлы (`Nodes`: поселения, перекрёстки, вершины дорог, здания, порты, маркеры) и связи (`Edges`: дороги, ЖД, маршруты, реки).
  - Маршрутизация `A*` по рельефу (штрафы за уклон и пересечение воды, мосты, паромы); маршруты формата `A → N₁…Nₖ → B`.
  - **Spatial Hash Grid** (поиск в радиусе за `O(1)`), **Чанки + кольца LOD**, **3D DDA-Raycast** по сетке кубиков и рельефу.
- **Конвейер постройки карт** (`mapgen.js`):
  - `Seed → FBM + Ridged + Domain Warp → Priority-Flood + D8-сток (реки/озёра/берега) → Биомы → Поселения и регионы Вороного → Сеть дорог/мостов → Кварталы и дома → Дельта-слой ручных правок`.

### 3.3. Слой 3 — Растровая графика, текстуры и конструкторы мешей (`src/assets/`)
- **Растровый буфер `RasterSurface`** (`raster.js`):
  - `Uint32Array(width * height)` в формате ABGR (`0xAABBGGRR`), работа без DOM (в браузере и в Node.js).
  - Примитивы: пиксели, линии Брезенхэма, залитые полигоны (scanline), круги, альфа-смешивание, светотень (hillshade), палитровое квантование, упорядоченный дизеринг (Bayer 4×4), экспорт в PNG / DataURL / ASCII-карту.
- **Генератор растровых текстур `RatTex`** (`textures.js`):
  - Процедурные слои: `solid`, `noise/fbm`, `voronoi`, `bricks`, `panels`, `windows`, `asphalt`, `grass`, `water`, `wood`, `metal`.
  - Автоматическая генерация **карты нормалей** (Собель) и **повреждённой копии** (`t + 2048`) + упаковка в единый **текстурный атлас**.
- **Конструкторы мешей `MeshBuilder`** (`mesh-builder.js`):
  - `extrude` — 2D-контур точками (Ear Clipping) → выдавливание + фаска (Bevel) + автонормали + UV.
  - `loft` — натяжка поверхности по последовательности сечений.
  - `lathe` — тело вращения по профилю.
  - `layer` / `voxels` — сборка по `(X;Y)Hp(...)` и вокселям с **Hidden Face Culling** и **Greedy Meshing** (слияние соседних одинаковых граней).
  - `primitive` — куб, призма, цилиндр, конус, скатная крыша, арка, сфера.
  - `combine` — объединение/иерархия деталей со смещениями, поворотами и масштабом в один `SealedMesh`.
  - `validate` — проверка вывернутых нормалей, дыр, `NaN`-вершин, бюджета треугольников и опоры на `H(X,Y)`.

### 3.4. Слой 4 — Единая камера и 3 рендерера (`src/render/`)
- **Камера (`camera.js`)**: единая камера `(X, Y, h, zoom, yaw, pitch)` — плавный переход от 2D-вида строго сверху к 3D-перспективе/орбите + Frustum/Viewport Culling.
- **2D Растровый рендерер (`renderer-2d.js`)**: быстрая отрисовка карты высот, светотени, воды, границ, дорог, разметки, городов, иконок, ночного освещения и пиксель-арта.
- **3D Программный растровый рендерер (`software-3d.js`)**: проекция треугольников, Z-buffer, backface culling, плоское/ламбертово/текстурированное затенение, **плюс Object-ID буфер (`Uint32Array`) и Depth буфер (`Float32Array`)** — работает в любом окружении, включая Node.js, и служит «глазами» для `tools.see`.
- **3D WebGL2-рендерер (`renderer-3d.js`)**: чистый WebGL2 без Three.js — VAO/VBO, единый текстурный атлас, инстансинг (`drawElementsInstanced`), направленный свет солнца/луны, туман и опциональная пиксельная постобработка.

## 4. Полный набор инструментов ИИ (`RatCore.tools.*`)

Все инструменты имеют единый формат вызова и единый формат ответа:
```js
{ ok: true | false, data: ..., error: { code, message, hint } | null, tick, costMs, traceId }
```
Каждый вызов логируется в журнал операций (с поддержкой отката и воспроизведения).

### 4.1. Манипуляции миром
1. **`tools.build.*` (Строить)**
   - Модели и меши: `extrude`, `loft`, `lathe`, `layer`, `voxels`, `primitive`, `combine`, `fromRecipe`, `validate`.
   - Текстуры: `tex.generate`, `tex.registerAtlas`, `tex.makeDamaged`.
   - Карта и объекты: `map.generate`, `map.editHeight`, `map.addNode`, `map.connectRoad`, `map.placeEntity`, `map.placeFace`.
2. **`tools.move.*` (Переставлять)**
   - `entity(id, { x, y, h, snapToTerrain, snapToGrid, yaw, scale, allowWater, allowOverlap })`
   - `part(modelId, partIndex, transform)`
   - `node(nodeId, { x, y })` (с пересчётом примыкающих рёбер и высот)
   - `swap(idA, idB)`
3. **`tools.remove.*` (Удалять)**
   - `entity(id)`
   - `face(faceId, { mode: 'delete' | 'break' })` (удаление или выставление `t = 4095`)
   - `node(nodeId)` / `edge(edgeId)`
   - `area({ x, y, radius, filter })`
   - `undo(steps)` / `redo(steps)` (транзакционный откат)

### 4.2. Наблюдение и органы чувств
4. **`tools.watch.*` (Следить)**
   - `subscribe(filter, handler)` — подписка на события (движение, стройка, поломка, износ, коллизия, просадка FPS).
   - `trackEntity(id)` / `watchZone({ x, y, radius })` — запись трека изменений по тикам.
   - `snapshot(label)` — снимок состояния мира.
   - `diff(snapshotA, snapshotB)` — точный список отличий между двумя снимками.
5. **`tools.look.*` (Смотреть)**
   - `at({ x, y, h, pitch, yaw, zoom, mode })` — наведение камеры (`2d` / `3d-webgl` / `3d-raster`).
   - `inspectModel(modelId, views)` — автоматический облёт с 6 ракурсов (`front`, `back`, `left`, `right`, `top`, `iso`).
   - `capture({ width, height, format: 'raster' | 'png' | 'ascii' })` — снимок кадра (в том числе текстовая ASCII-карта для нейросетей без vision).
6. **`tools.see.*` (Видеть — семантическое зрение)**
   - `frame()` — список всех объектов и граней в кадре с расстоянием, экранными координатами и долей площади экрана.
   - `pickPixel(px, py)` — чтение Object-ID буфера: точный `entityId`, `faceId`, сторона кубика, номер текстуры, глубина `depth` и мировые `(X, Y, h)`.
   - `raycast(origin, dir, maxDist)` — проверка прямой видимости через 3D DDA-Raycast.
   - `diagnose()` — автоматический визуальный инспектор дефектов: чёрный/пустой кадр, `NaN`-пиксели, висящий объект (`h > H + tol` без опоры), утопание в склоне (`h < H - 0.05`), вывернутые нормали, клиппинг.
7. **`tools.hear.*` (Слышать — пространственная акустика)**
   - `emit({ sourceId, x, y, h, kind, db, freq, radius })` — публикация звукового события в акустическую шину (и опциональный синтез через WebAudio в браузере).
   - `listen({ x, y, h, minDb, windowTicks })` — всё, что слышно в точке: ослабление по закону обратных квадратов (`-6.02 дБ` на удвоение дистанции), азимут на источник, громкость `dbAtListener`, тип и `sourceId`.
   - `log(filter)` — история звуков за последние `N` тиков (работает в headless Node.js без аудиокарты).

### 4.3. Мышление и прогнозирование
8. **`tools.think.*` (Думать)**
   - `note(topic, text, refs)` — запись шага рассуждения в рабочую память агента.
   - `plan({ goal, steps, invariants })` — регистрация плана с проверяемыми условиями.
   - `checkInvariants()` — проверка ограничений мира (высоты, коллизии, связность графа, бюджет треугольников).
   - `sandboxRun(ops)` — выполнение последовательности инструментов на **изолированном клоне мира** без изменения настоящего состояния; возвращает результат и diff.
9. **`tools.guess.*` (Гадать — гипотезы и прогнозы)**
   - `hypothesize({ claim, assumption, metric, target, horizonTicks, trials, seedBase })` — формулировка и проверка гипотезы:
     - движок клонирует состояние, применяет допущение (`assumption`), прогоняет симуляцию вперёд на `horizonTicks` (или `trials` раз по разным сидам), считает целевую метрику и возвращает вердикт:
       - `verdict`: `'confirmed' | 'refuted' | 'uncertain'`,
       - `confidence`: `0..1`,
       - `evidence`: числа «было / стало / разброс / нарушенные правила».
   - `history()` — журнал всех проверенных гипотез (помогает другим нейросетям не проверять одно и то же дважды).

### 4.4. Мультиагентность: общение и баг-репорты
10. **`tools.comm.*` (Общаться с другими нейросетями через папки общения)**
    - `register({ agentId, role, capabilities })` → запись в `ratcore/comms/registry.json`.
    - `send({ from, to, channel, type, priority, subject, body, attachments, threadId })` → создаёт конверт `.json` + читаемый `.md` в `outbox/<from>/` и доставляет в `inbox/<to>/` или `channels/<channel>/`.
    - `readInbox(agentId, { unreadOnly })` / `ack(agentId, msgId)` / `archive(msgId)`.
    - `createTask({ title, role, spec, constraints })` → `comms/tasks/open/`.
    - `claimTask(taskId, agentId)` → перенос в `comms/tasks/claimed/` с блокировкой владельца.
    - `completeTask(taskId, agentId, result)` → перенос в `comms/tasks/done/`.
    - `handoff({ from, summary, completed, nextSteps, seed, tick, openBugs })` → `comms/handoffs/` для бесшовной передачи работы следующей нейросети.
11. **`tools.report.*` / `tools.bugs.*` (Писать баги и отчёты для других нейросетей)**
    - `bugs.create({ code, severity, title, author, assignee, context, reproOps, evidence })` → создаёт `ratcore/reports/bugs/BUG-XXXX.json` + `BUG-XXXX.md` и обновляет `ratcore/reports/index.json`.
    - `bugs.list(filter)` / `bugs.update(bugId, patch)` / `bugs.verify(bugId, agentId, proof)`.
    - `report.audit({ kind, summary, metrics, findings })` → `ratcore/reports/audits/`.
    - `report.summary({ title, agents, results, recommendations })` → `ratcore/reports/summaries/`.

### 4.5. Соединение с другими движками и системами (ветка 12 — [`BRIDGE.md`](./BRIDGE.md))
12. **`tools.bridge.*` (Соединение с другими движками, инстансами и внешними ИИ)**
    - `bridge.connect({ peerId, target, transport, config })` — рукопожатие (`A-34`), согласование осей (`F-45`) и прав (`BridgeGuard`). Цели: `ratcore`, `threejs`, `godot4`, `canvas2d`, `pereplet`, `external-ai`.
    - Транспорты: `inproc` (0 мс в памяти), `worker` (`Transferable ArrayBuffer`), `broadcast` (вкладки браузера без сервера), `file` (`ratcore/comms/bridges/<peerId>/` для разных процессов, языков и нейросетей), опционально `ws`.

    - `bridge.importRecipe` — приём моделей из других движков **строго в виде рецепта `ops`** с пересборкой через `ToolGuard` (сырые вершины запрещены `RC-605` / `RC-101`).
    - `bridge.syncTick` — дельта-синхронизация и Lockstep между мирами с контролем рассинхрона по `stateHash` (`F-46`, `F-47`, `A-35`).
    - `bridge.rpcCall` / `bridge.serveRpc` — единый JSON-RPC для вызова любого инструмента `RatCore.tools.*` извне (`A-36`).
    - `bridge.attachPereplet` — адаптер для ядра `pereplet-prototype/`.

## 5. Структура папок `ratcore/comms/` и `ratcore/reports/`

```
ratcore/
├── comms/
│   ├── registry.json         — реестр агентов (agentId, роль, статус, последняя активность)
│   ├── inbox/<agentId>/      — входящие сообщения (.json + .md)
│   ├── outbox/<agentId>/     — исходящие сообщения (.json + .md)
│   ├── channels/
│   │   ├── general/          — общие архитектурные решения
│   │   ├── models/           — заказы и приёмка моделек/мешей/текстур
│   │   ├── maps/             — рельеф, дороги, города, слои
│   │   └── qa/               — разбор дефектов и регрессий
│   ├── bridges/<peerId>/     — файловый мост с внешними движками/процессами (in/, out/)
│   ├── tasks/
│   │   ├── open/             — свободные задачи
│   │   ├── claimed/          — задачи в работе (с владельцем)
│   │   └── done/             — завершённые задачи с результатом
│   ├── handoffs/             — передача смены между сессиями/нейросетями
│   └── archive/              — архив закрытых тредов
└── reports/
    ├── index.json            — сводный индекс багов и отчётов
    ├── bugs/                 — баг-тикеты BUG-XXXX.json + BUG-XXXX.md
    ├── audits/               — отчёты ToolGuard, see/hear/FPS проверок
    └── summaries/            — сводные отчёты для других нейросетей и владельца
```

В Node.js драйвер `storage.js` работает напрямую с реальными папками на диске; в браузере — с тем же API поверх виртуальной ФС (`localStorage` + импорт/экспорт пакета JSON).
