# QA «ГАРАЖА» — что проверяется и как не сломать кадр

Короткая памятка для того, кто правит модели, ракурсы и интерфейс. Полное описание
продукта — в [`README.md`](./README.md).

## Быстрый прогон

```bash
npm ci                 # один раз
npm test               # модели + интерфейс + актуальность сборки (~1.5 мин)
npm run build          # после любой правки src/ — иначе сайт покажет старое
```

| Файл | Что проверяет |
|------|---------------|
| `tests/smoke.mjs` | каталог, сборка всех 64 моделей, детализация, **кадр**, дефекты, текстуры |
| `tests/ui.mjs` | 162 проверки интерфейса в jsdom: меню не наезжают, панели на экране, тултипы |
| `tests/bundle.mjs` | `showroom.bundle.js` совпадает с `src/` (иначе сайт крутит старый код) |

## Главный инвариант: ракурс не обрезает модель

`src/lib/fit.js` — единственное место, где решается «что видно в кадре»:

* `boundsOf(root)` — габариты собранной модели;
* `frameFill(...)` — насколько модель вылезает за кадр (1.0 — ровно по кромке);
* `fitView(view, box, aspect)` — если не влезает, сначала расширяет угол обзора
  (до 46° на широком экране, до 62° на вертикальном), потом отодвигает камеру
  от `target`. Направление взгляда не меняется — ракурс остаётся тем же.

Применяется в двух местах:

1. **при сборке модели** (`src/models/index.js`) — под кадр 16:10, чтобы
   сохранённые ракурсы были корректны для десктопа;
2. **в камере при каждом `setView`** (`src/lib/camera.js`) — под фактический
   аспект окна. Плюс `cam.refit()` на `resize`/`orientationchange`: на телефоне
   при повороте кадр пересчитывается.

Что нельзя подгонять: салон (`group: 'interior'`), «место водителя» (`seat`)
и точечный осмотр по анкеру (`id: 'anchor'`) — это намеренные крупные планы.

### Что тест кадра ловит

`tests/smoke.mjs` проверяет каждую модель в каждом наружном ракурсе и **на трёх
аспектах**: десктоп 16:10, планшет 3:4, телефон 9:16. Регрессии, которые уже
были найдены этой проверкой:

| Что было | Симптом | Исправление |
|----------|---------|-------------|
| Котельная с трубой | труба `H + chimney` уходила за верхнюю кромку во всех 5 ракурсах — «котельная без трубы» | высота кадра считается по `topY = H + chimney` |
| B-double, боковой вид | длинная сцепка резалась по обоим краям (до 2.7 % геометрии за кадром) | `fitView` при сборке модели |
| Телефон вертикально | до 306 из 520 наружных кадров обрезали модель по ширине | `fitView` в камере + `refit()` на поворот |

## Визуальная проверка без браузера

```bash
# один ракурс в PNG (софтверный растеризатор, текстуры не читает)
node tools/render.mjs --cat trucks --id atlas-vision --view exterior --out /tmp/p.png

# контактный лист по категории
node tools/montage.mjs --list trucks    --view exterior --out /tmp/trucks.png
node tools/montage.mjs --list trailers  --view side     --out /tmp/trailers.png
node tools/montage.mjs --list buildings --view front    --out /tmp/buildings.png
```

На что смотреть в листах: модель не касается краёв ячейки (значит, влезет и в
узкое окно), колёса стоят на земле, фасады зданий отличаются, у высоких объектов
(труба, вышка, мачта) видна макушка. Помни: растеризатор рисует плоские цвета —
отсутствие текстуры на скриншоте не дефект модели.

## Чек-лист при добавлении модели

1. `id` уникален, категория — одна из четырёх; каталог и счётчики совпадут сами.
2. Есть наружные ракурсы (`group: 'exterior'`) — минимум два.
3. Для тягачей и авто — вид из салона; для прицепов и зданий не требуется.
4. Модель стоит на земле (`minY ≈ 0`), не «висит» и не утопает.
5. `npm test` — кадр на трёх аспектах, детализация выше порога, интерфейс.
6. `npm run build` — иначе `tests/bundle.mjs` завалит прогон.
7. `node tools/montage.mjs --list <категория>` — глазами по контактному листу.

## Остаточные риски

* Растеризатор не показывает текстуры и освещение PBR — часть дефектов видна
  только в браузере.
* `tests/ui.mjs` работает в jsdom без WebGL: проверяется раскладка меню, а не кадр.
* Ориентация: `refit()` срабатывает через 60–180 мс после `resize`; в это время
  кадр ещё старый — это осознанно, иначе гонка с `ResizeObserver` в `stage.js`.
* Сравнение двух моделей (`compare`) подгоняется по габаритам основной модели;
  вторая может слегка вылезать за кадр на узком экране.
