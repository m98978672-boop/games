# KARMAN · «Карман» — карманная Linux-среда на внешнем USB SSD

Дизайн целиком — в [`DESIGN.md`](./DESIGN.md). Здесь — что уже собрано, как это запустить и чего пока нет.

> ⚠️ **Шифрования и пароля нет.** Любой, кто подключит накопитель к любому ПК или телефону, прочитает все файлы, историю, журналы и настройки. Защита только физическая: не терять и не давать чужим.

---

## Что это

Папка `pocket-linux/` — **отдельный продукт** внутри раздела `usb-minipc/`, не связанный с агентом флешек. Это «программа-помощник», которая лежит **на самом накопителе** и запускает Linux-среду:

```
<USB SSD>/
├─ ЗАПУСТИТЬ-КАРМАН.cmd     ← единственный кликабельный файл (Windows) — «как приложение»
├─ ЗАПУСТИТЬ-КАРМАН.sh      ← он же для Linux-хоста
├─ KARMAN-ЧИТАЙ-МЕНЯ.txt
├─ data/                    ← ОБЩИЕ ФАЙЛЫ: видны и без Linux
└─ karman/
    ├─ manifest.json        ← раскладка, пути, хэш образа, политика точек
    ├─ launcher/            ← лаунчер (PowerShell)
    ├─ engine/qemu/         ← портативный QEMU (кладёт пользователь)
    ├─ system/base.qcow2    ← система Linux (только чтение)
    ├─ state/overlay.qcow2  ← изменения сессии; удаление = сброс системы
    ├─ checkpoints/         ← контрольные точки
    └─ logs/                ← журналы сессий
```

Двойной клик по `ЗАПУСТИТЬ-КАРМАН.cmd` открывает меню: **запустить Linux / контрольная точка / проверить / безопасно извлечь / восстановить / сбросить систему**. В Windows при этом ничего не устанавливается — QEMU запускается прямо с накопителя.

Автотесты: `python3 tests/test_prepare_ssd.py` — 15 проверок раскладки, целостности и предупреждений. Логика запуска на Linux прогнана сценариями: штатная сессия, аварийное завершение, восстановление, сброс, подмена образа.

**Чего нет и не будет в этом репозитории:** готового образа Linux и бинарников QEMU. Их нужно положить самому (это десятки гигабайт и сторонние лицензии) — лаунчер честно скажет, чего не хватает, и откажется запускаться.

## Быстрый старт

```bash
# 1. разложить раскладку на накопитель (E:\ — пример для Windows, /media/user/SSD — для Linux)
python3 tools/prepare_ssd.py E:\ --name "Карман" --memory 6144 --cpus 6

# 2. положить движок и систему
#    karman\engine\qemu\   — портативный QEMU (qemu-system-x86_64.exe, qemu-img.exe)
#    karman\system\base.qcow2 — образ Linux

# 3. пересчитать хэш образа в манифесте и проверить накопитель
python3 tools/prepare_ssd.py E:\ --rehash
python3 tools/verify_ssd.py E:\

# 4. запустить (Windows — двойным кликом по файлу в корне накопителя)
```

Флаги `prepare_ssd.py`:

| Флаг | Значение |
|------|----------|
| `--name` | имя накопителя в манифесте и меню |
| `--memory` / `--cpus` | ресурсы для Linux (по умолчанию 4096 МБ / 4 vCPU) |
| `--share-data ro\|rw\|none` | как подключать `data/` к Linux (по умолчанию только чтение) |
| `--verify sha256\|size\|none` | способ проверки целостности образа |
| `--force` / `--rehash` | перезаписать раскладку / только пересчитать хэш |

## Как это работает по шагам

1. Лаунчер читает `karman/manifest.json`, сверяет версию раскладки.
2. Проверяет: на месте ли QEMU, совпадает ли размер и SHA-256 образа, есть ли свободное место, нет ли `session.lock` от аварийной сессии.
3. Создаёт оверлей (если его нет) на базе `base.qcow2`, пишет блокировку и журнал.
4. Запускает QEMU: `q35`, virtio, сеть через NAT хоста, `data/` — только для чтения (по умолчанию).
5. Ждёт выключения Linux **изнутри системы**, снимает блокировку, предлагает контрольную точку и безопасное извлечение.
6. Если процесс завершился с ошибкой — блокировка остаётся, и следующий запуск честно предупредит о возможной потере последних изменений.

## Что где хранится и что считается программой

| Объект | Где | Это данные или программа |
|--------|-----|--------------------------|
| Документы, фото, проекты | `data/` на SSD | данные |
| Настройки и состояние Linux | `state/overlay.qcow2` на SSD | данные |
| Система Linux | `system/base.qcow2` на SSD | образ (данные) |
| Лаунчер | `karman/launcher/` на SSD | **программа**, но переносимая: не устанавливается |
| QEMU | `karman/engine/qemu/` на SSD | **программа**, портативная |
| WSL2, Termux, приложение-компаньон | система хоста / телефон | **устанавливается на устройство** (не на SSD) |

## Безопасность — коротко

- `data/` подключается к Linux **только для чтения**; запись включается флагом `--writable-data` с предупреждением (FAT-мост QEMU экспериментален и может испортить файлы).
- Лаунчер не выходит за пределы накопителя: пути из манифеста с `..` отклоняются.
- Не ставит службы, задачи планировщика и автозапуск; не требует прав администратора; не читает внутренний диск хоста.
- Журналы не удаляются — по ним видно, где и когда использовался накопитель.
- Контрольные точки содержат **только систему**, `data/` в них не входит.
- Восстановление после выдёргивания: возможна потеря последних изменений, **100 % откат не гарантируется**.
- Android: полной виртуальной машины без root не будет; реальный путь — proot-окружение в памяти приложения (DESIGN, раздел 1.3).

## Проверить без настоящего SSD

```bash
mkdir -p /tmp/karman/SSD/karman/system
head -c 8192 /dev/urandom > /tmp/karman/SSD/karman/system/base.qcow2
python3 tools/prepare_ssd.py /tmp/karman/SSD --name "Проверка"
python3 tools/verify_ssd.py /tmp/karman/SSD
bash /tmp/karman/SSD/ЗАПУСТИТЬ-КАРМАН.sh verify
```

Дальше добавляются подставные `karman/engine/qemu/qemu-system-x86_64` и `qemu-img` — и весь цикл (сессия, блокировка, точка, восстановление) прогоняется без виртуализации.

## Ограничения, о которых нужно помнить

- Нужен образ `base.qcow2` с гостевыми драйверами virtio (иначе гость не увидит диск); для `-nographic` в образе нужен `console=ttyS0`.
- Windows: без включённой виртуализации QEMU работает в TCG — загрузка минуты, интерактив медленный.
- exFAT не хранит POSIX-права: пути и права внутри Linux ограничены возможностями образа, а не хоста.
- Android обычно видит только первый раздел накопителя — поэтому базовая схема разметки один раздел exFAT.
- `data/` при подключении к Linux доступен через FAT-прослойку: запись по умолчанию выключена осознанно.
