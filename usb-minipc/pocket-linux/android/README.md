# KARMAN · Android (Termux, userspace)

Здесь лежит **честная** Android-часть: скрипт для Termux, а не APK. Причины и что это меняет — ниже.

> ⚠️ Шифрования нет: содержимое накопителя прочитает любой, кто его подключит. На телефоне это особенно чувствительно — данные лежат в общей папке SAF.

## Почему не приложение «из коробки»

Полноценная виртуальная машина на Android без root невозможна: KVM нет, ядро одно на всю систему. Поэтому Linux работает в **userspace через `proot`**: системные вызовы транслируются, `mount`, `systemd`, `docker` недоступны, часть пакетов не работает.

Вторая стена — **исполнение файлов с USB**. Внешний накопитель монтируется через SAF/FUSE: нет POSIX-прав, нет симлинков, **нет exec**. Значит rootfs нельзя запускать прямо с SSD — он должен лежать во внутренней памяти Termux, а SSD хранит данные, архив системы и точки.

Третья — телефон часто видит **только первый раздел** накопителя, а OTG-порт может не вытянуть автономный SSD по питанию.

Отсюда схема: **накопитель = данные, телефон = среда исполнения**.

## Что установить на телефон (это программы, а не данные)

```bash
pkg update && pkg install python proot-distro rsync
proot-distro install debian          # или другой дистрибутив
termux-setup-storage                 # выдать доступ к накопителю
```

## Что лежит на SSD

```
<USB SSD>/
├─ karman/manifest.json     раскладка и хэш архива системы
├─ karman/system/rootfs.tar архив системы (нужен для первого входа)
├─ data/                    общие файлы — то, ради чего всё это
└─ karman/checkpoints/      точки (в Android-режиме — архивы данных)
```

## Как пользоваться

```bash
bash karman-android.sh check        # проверки: накопитель, rootfs, место, права
bash karman-android.sh start        # копирует data/ в память, входит в Linux
bash karman-android.sh sync-in      # SSD → рабочая папка
bash karman-android.sh sync-out     # рабочая папка → SSD
bash karman-android.sh checkpoint   # архив данных на SSD
```

Внутри Linux файлы с накопителя доступны как `/root/data`. После выхода из сессии скрипт выгружает изменения обратно на SSD и напоминает про безопасное отключение.

Флаги: `--dry-run`, `--distro <имя proot-distro>`, `--ssd <путь>`. Переменные для тестов и нестандартных путей: `KARMAN_SSD`, `KARMAN_WORK`, `KARMAN_ALLOW_ANY=1` (запуск вне Termux).

## Что здесь проверено

- найдёт накопитель в `~/storage/external-*`, `/mnt/media_rw/*` или по `--ssd`;
- сверит `sha256` архива системы с манифестом и откажется входить при подмене;
- синхронизация в обе стороны (rsync, иначе tar) — проверена на реальных файлах;
- контрольная точка данных с честной пометкой `scope: data-only`;
- `--dry-run` показывает план без изменений.

## Чего этот скрипт не делает и что осталось на этап APK

- **не** даёт настоящую виртуальную машину (и не будет обещать);
- **не** автоматизирует `pkg install` — установка программ остаётся за пользователем;
- **не** трогает внутреннюю память телефона за пределами `~/karman` и папки Termux;
- APK-обёртка (свой интерфейс вместо командной строки) — отдельный этап: нужен Android SDK, манифест разрешений `MANAGE_EXTERNAL_STORAGE`/SAF, foreground-сервис с уведомлением для длинных сессий и wakelock. Логика останется той же: проверка манифеста → импорт данных → proot-сессия → экспорт.
- На разных телефонах поведение отличается: проверяй на своём, прежде чем носить единственную копию данных на SSD.
