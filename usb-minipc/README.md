# 💾 USB Mini-PC — флешка, которая ведёт себя как мини-компьютер

Короткий ответ: **программу сделать можно, но «отдельным компьютером» флешка станет только одним из пяти способов** — и не тем, который обычно представляют.

Обычная флешка не может «представиться» Windows как компьютер: класс USB-устройства (mass storage) прошит в её контроллере, а ОС видит только накопитель. Плюс с Windows 7 автозапуск программ с USB-носителей отключён политикой, и `autorun.inf` там ничего не запускает. Поэтому «флешка = мини-ПК» собирается одним из пяти способов ниже: три из них делают её настоящим компьютером, два — эмулируют его на хосте.

В этой папке уже лежит **рабочий код варианта 1** (+ заготовка под вариант 2): агент на ПК, манифест на флешке, шаблон меню и тесты.

## 1. Хост-агент + лаунчер с флешки ✅ реализовано

**Идея.** На ПК работает маленький фоновый агент (≈250 строк PowerShell или Python). Он опрашивает список съёмных дисков; когда появляется новый — ищет на нём `minipc/config.json`. Есть манифест и хэш лаунчера совпал → запускает меню, переданное флешкой.

**Что нужно:** один раз поставить агент на свой ПК. Всё.

**Как это выглядит:**

```
                     Вставили флешку
                            │
                   ┌────────▼────────┐
                   │  агент на ПК    │  опрос раз в 2 с
                   └────────┬────────┘
             нашли E:\minipc\config.json ?
                            │ да
                   ┌────────▼────────┐
                   │ проверка sha256 │──✗──► отказ, запись в журнал
                   └────────┬────────┘
                            │ ок
                   ┌────────▼────────┐
                   │ запуск меню     │  MINIPC_ROOT=E:\
                   │ с флешки        │  MINIPC_NAME=...
                   └─────────────────┘
```

**Плюсы:** работает на любом ПК без перезагрузки, ноль прав администратора, ничего не устанавливается на саму флешку.  
**Минусы:** это не «компьютер», а автоматизация запуска; на ПК без агента флешка ведёт себя как обычная.

## 2. Портативная среда на флешке (рабочее место в кармане)

**Идея.** На флешке лежат portable-сборки программ (браузер, офис, архиватор, Python, VS Code, VLC). Их профили и настройки тоже на флешке — на хосте не остаётся следов. Агент из варианта 1 просто открывает меню этой среды.

**Что нужно:** 16–64 ГБ, USB 3.0, портативные сборки. На хосте — ничего (если запускать вручную через `Start.exe`), либо агент из п. 1.

**Что кладём:**
- [PortableApps.com Platform](https://portableapps.com/) — готовый лаунчер и каталог portable-программ;
- `Python embeddable` + свои скрипты — «мини-сервер» на флешке;
- портативный браузер с профилем — закладки и пароли всегда с собой.

**Плюсы:** ноль установки, ноль прав, легко сделать за вечер; идеально сочетается с п. 1.  
**Минусы:** это не компьютер, а набор программ; скорость флешки ниже SSD; чужие ПК могут блокировать запуск `.exe` с носителей (AppLocker, антивирус).

## 3. Загрузочная флешка — флешка буквально становится компьютером

**Идея.** ПК загружается **с флешки**, и работает система, которая лежит на ней. Хост становится «терминалом», а вся ОС, файлы и настройки — на носителе.

**Три подварианта:**

| Что | Инструмент | Особенность |
|-----|-----------|-------------|
| Мультизагрузка ISO | **Ventoy** | Кидаешь `.iso` файлами на флешку — получаешь меню загрузки; поддерживает Secure Boot |
| Live Linux с сохранением | Ventoy + Linux Mint / Ubuntu / MX Linux + persistence-файл | Настройки и файлы сохраняются между загрузками |
| Windows в кармане | Windows To Go (через Rufus / WinPE) | Официально Windows To Go закрыт с версии 2004, но сборки живут; нужен быстрый USB 3.x SSD |

**Порядок:** записать загрузчик → скопировать ISO (Ventoy) или развернуть систему → загрузиться через Boot Menu (F8/F11/F12/Esc) → при необходимости отключить Secure Boot в BIOS.

**Плюсы:** единственный бесплатный вариант, где флешка **действительно** отдельный компьютер; на чужом ПК не остаётся ничего.  
**Минусы:** нужна перезагрузка и доступ к настройкам загрузки; на корпоративных ПК BIOS часто запаролен; Live-система медленнее SSD.

## 4. Виртуальная машина с флешки — «компьютер внутри компьютера», без ребута

**Идея.** На флешке лежит образ виртуальной машины и портативный гипервизор. Агент (п. 1) запускает гипервизор — и на хосте открывается окно с полноценной ОС, которая «живёт» на флешке.

**Что нужно:** портативный **QEMU** (бесплатно, ~50 МБ) или VMware/VirtualBox Portable, образ `.qcow2`/`.vmdk` на 16–40 ГБ, USB 3.0 (иначе будет медленно), 8 ГБ RAM на хосте.

**Как собрать:**
1. `qemu-img create -f qcow2 mini.qcow2 32G` и поставить туда систему (или взять готовый образ);
2. положить рядом `qemu\qemu-system-x86_64.exe` (portable);
3. в `minipc/config.json` указать `"launch": "minipc/launch-vm.cmd"`, а в нём — команду запуска QEMU с образом;
4. поставить агент из п. 1.

**Плюсы:** полноценный компьютер по щелчку, без перезагрузки и без прав администратора (если хост разрешает виртуализацию).  
**Минусы:** нужен образ на десятки гигабайт; производительность ограничена USB; на некоторых ПК отключена аппаратная виртуализация.

## 5. Настоящий мини-ПК в форм-факторе флешки (железо)

**Идея.** Взять **Raspberry Pi Zero 2 W** (или Pi 3A+/Pi 4 с оговорками) и включить **USB-gadget режим**: плата подключается к ПК как USB-устройство и представляется сетевой картой (RNDIS/CDC-ECM) + накопителем. ПК видит «USB-Ethernet адаптер», а по SSH ты попадаешь **на саму флешку-компьютер** и запускаешь там что угодно. Питание — от того же USB-порта.

**Что нужно:** Pi Zero 2 W, microSD, корутина/пайка под USB-разъём, 30–60 минут настройки `dwc2`/`configfs`.

**Схема:**

```
   ПК                        Pi Zero 2 W (внутри корпуса флешки)
┌────────┐   USB-кабель    ┌──────────────────────────┐
│ USB    │◄───────────────►│ gadget: RNDIS + storage  │
│ порт   │  питание+данные │ Linux, SSH, свои сервисы │
└────────┘                 └──────────────────────────┘
        видно как «сетевая карта» → ssh pi@usb0
```

**Плюсы:** это **физически** отдельный компьютер; ПК видит его как сетевое устройство; можно держать там сервер, базу, бота.  
**Минусы:** цена и возня с железом; на Windows может понадобиться драйвер RNDIS; корпус придётся печатать/клеить.

> Готовая альтернатива без пайки — мини-ПК-стик (MeLE, старые Intel Compute Stick) с питанием от USB: он подключается к монитору и является самостоятельным компьютером.

## ⛔ Чего сделать нельзя (и почему)

1. **Заставить Windows видеть обычную флешку «отдельным компьютером».** Класс устройства задан контроллером; ОС не умеет «запускать ПО с флешки» как с процессора.
2. **Автозапуск с флешки через `autorun.inf`.** С Windows 7 автозапуск с USB-носителей заблокирован (KB971029), и это правильно: иначе любая чужая флешка выполняла бы свой код на вашем ПК.
3. **Скрытый автозапуск через перепрошивку контроллера (BadUSB и подобное).** Технически бывает возможно, но это маскировка устройства под клавиатуру/сеть и типичный признак атаки: антивирусы и EDR такое ловят, а на чужом ПК это ещё и незаконно. В этом проекте такого нет — агент ставится владельцем явно и всё пишет в журнал.

### Быстрый старт на Windows

```powershell
# 1. подготовить флешку (E: — буква вашей флешки)
python tools\prepare_stick.py E:\ --name "Моя флешка"

# 2. поставить агент в автозапуск текущего пользователя
powershell -ExecutionPolicy Bypass -File windows\install-agent.ps1

# 3. проверить, не дожидаясь вставки
powershell -ExecutionPolicy Bypass -File "$env:LOCALAPPDATA\usb-minipc\usb-minipc-agent.ps1" -Once -DryRun
```

Дальше просто вынуть и вставить флешку — откроется меню. Журнал: `%LOCALAPPDATA%\usb-minipc\agent.log`.

### Быстрый старт на Linux / macOS

```bash
python3 tools/prepare_stick.py /media/$USER/USB --name "Моя флешка"
python3 tools/usbmini.py            # следить за /media, /run/media, /mnt, /Volumes
python3 tools/usbmini.py --list     # что видно прямо сейчас
```

### Проверка без настоящей флешки (2 минуты, любая ОС)

```bash
mkdir -p /tmp/usb/media/USB1
python3 tools/prepare_stick.py /tmp/usb/media/USB1 --name "Демо"
python3 tools/usbmini.py --dir /tmp/usb/media --once --trigger-existing --dry-run
```

## 📄 Манифест флешки

`E:\minipc\config.json`:

```json
{
  "name": "Моя флешка",
  "launch": "minipc/launch.cmd",
  "sha256": "a5fd81a4a240248b93a84c311ed22fd9bebdf9c699c9982ae35dfa7bc9f4f1a7",
  "autoLaunch": true,
  "args": [],
  "notes": "Меняешь launch.cmd — пересчитай sha256"
}
```

| Поле | Что значит |
|------|------------|
| `name` | имя устройства в журнале и заголовке меню |
| `launch` | путь к лаунчеру **относительно корня флешки** |
| `sha256` | отпечаток лаунчера; не совпал — запуск отменяется |
| `autoLaunch` | `false` — агент только пишет в журнал, ничего не запускает |
| `args` | аргументы командной строки для лаунчера |

Лаунчер получает переменные окружения:

| Переменная | Значение |
|------------|----------|
| `MINIPC_ROOT` | корень флешки, например `E:\` |
| `MINIPC_DRIVE` | буква диска (`E:`) или путь монтирования |
| `MINIPC_NAME` | `name` из манифеста |
| `MINIPC_LAUNCH` | полный путь к запущенному файлу |
| `MINIPC_AGENT` | версия агента |

## 🛡 Безопасность — почему это не «автозапуск из интернета»

- **Запускается только то, что лежит внутри флешки.** Путь `..\..\Windows\System32\...` отклоняется — проверено тестами.
- **Привязка к хэшу.** Манифест фиксирует SHA-256 лаунчера: подменили файл — агент откажется запускать и запишет отказ в журнал.
- **Явная установка.** Агент ставится в автозапуск только владельцем ПК, видимым скриптом `install-agent.ps1`, и так же удаляется.
- **Без прав администратора.** Всё в профиле пользователя; UAC не обходится.
- **Журнал.** Каждое подключение, запуск и отказ видны в `agent.log`.
- **`autoLaunch: false`** — режим «только уведомить», если не хочется автоматики.

Ставьте агент только на свои машины. На чужих ПК запуск кода с флешки без согласия владельца — не «фича», а вредоносное поведение.

## ⚠️ Ограничения

- **Windows Defender / антивирусы** могут насторожиться из-за автозапуска скрипта по появлению USB — это нормальная эвристика. Агент без обфускации, с открытым кодом и журналом; при желании добавьте исключение или используйте `-StartupFolder` вместо планировщика.
- **`.cmd` с кириллицей** сохранён в UTF-8 и начинается с `chcp 65001` — иначе cmd покажет кракозябры.
- **Картридеры без карты** пропускаются (не готовы к чтению), это не ошибка.
- **Python-агент** определяет съёмные тома по `/media`, `/run/media`, `/mnt`, `/Volumes` — если у вас другая точка монтирования, используйте `--dir`.
- **Windows To Go** официально закрыт с Windows 10 2004 — вариант 3 на Windows считается «на свой страх», Linux-live работает без ограничений.
