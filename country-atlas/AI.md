## Часть I. Кто такой ИИ

ИИ Ратграда — не один «мозг», а **четыре**, плюс наблюдатель. Это сделано специально: если
смешать стратегию и физику в одном месте, получается агент, который «решил повернуть», но
повернул сквозь стену.

| Мозг | Вопрос | Что на входе | Что на выходе | Бюджет |
|---|---|---|---|---|
| **Стратег** | «что важно сейчас» | потребности, окна времени, память, отношения | цель рутины (§32) | 0.02 мс на агента, раз в 0.5–2 с |
| **Навигатор** | «какой маршрут дешевле» | граф дорог, загрузка ρ (§33), ограничения | маршрут и оценка времени | 0.05 мс из кэша, пересчёт ≤ 4 раза в секунду |
| **Физик** | «как именно ехать» | вектор, покрытие, погода, соседи | ускорение, торможение, дистанция | 0.02 мс на точку в тик |
| **Диспетчер** | «кто и по каким правилам» | журнал, приоритеты, тревоги | команды инструментами | 0.1 мс на решение |
| **Наблюдатель** | «не сломалось ли» | инварианты, бюджеты, ошибки | записи в журнал, откат, тревога | ≤ 0.5 мс раз в 0.5 с |

Диспетчер — единственный, кто имеет право менять состояние мира. Остальные трое только
**предлагают**: стратег — цель, навигатор — маршрут, физик — ускорение. Наблюдатель не
командует вовсе, он проверяет.

### 1.1. Что ИИ считает «состоянием агента»

```
agent = {
  id, sym, pos, v, mode, heading,           // §33 — уравнение, не таблица
  needs: { food, rest, money, social, work, health },   // 0…1, 1 — полностью удовлетворено
  mood, fatigue, trust: Map<id, 0…1>,
  memory: Map<placeId, { strength, lastVisit }>,
  goal: { id, U, u, fit, cost, risk, score } | null,
  attention: 0…1, alert: 0…1
}
```

Потребности убывают по F-1, превращаются в срочность по F-3, складываются в полезность цели
по F-7. Настроение — F-5, усталость — F-6, доверие — F-31, память — F-32.

### 1.2. Цикл решения (один такт)

```
1. Наблюдатель: инварианты §33 (конечность, телепорт), бюджеты, «застрял ли» (F-34, F-40)
2. Стратег:  пересчитать потребности (F-1…F-6) → баллы целей (F-7…F-10) → выбрать максимум
3. Навигатор: маршрут (F-8, F-19…F-21) → k лучших в кэш, инвалидация при Δρ > 10 %
4. Диспетчер: превратить выбор в команды инструментами (Часть II), каждая с `why`
5. Физик: шаг уравнения (§33), дистанции (F-17, F-18), торможение
6. Журнал: записать решение, причину и цену; всё, что не объяснено, — ошибка (F-38)
```

## Часть II. Инструменты ИИ

Инструмент — это единственный способ что-то изменить или узнать. Прямые записи в поля
(`point.pos.x = …`) запрещены: такой код не проходит тест.

### 2.1. Чтение (безопасно, можно звать сколько нужно)

| Инструмент | Что возвращает | Цена |
|---|---|---|
| `getState(pointId)` | `{pos, v, mode, heading, t}` | O(1) |
| `getNeeds(agentId)` | `{food…health}`, mood, fatigue | O(1) |
| `getLoad(edgeId, dir)` | `ρ` ребра, `v_eff`, `TI` (F-19) | O(1) |
| `getRoute(from, to, opts)` | маршрут + `G` (F-20) | ≤ 0.05 мс из кэша |
| `probeArea(x, y, r)` | точки, опасности, загрузка в радиусе | O(k), k ≤ 64 |
| `estimateTime(route)` | секунды с учётом ρ | O(длина) |
| `getForecast(edgeId, minutes)` | прогноз ρ и очереди (F-21, F-22) | O(1) |
| `journalTail(n)` | последние n решений с `why` | O(n) |

### 2.2. Действия (только через диспетчера, только с `why`)

| Инструмент | Подпись | Что делает | Ограничение |
|---|---|---|---|
| `setMode` | `(pointId, mode, why)` | `rest/think/move/wait/work/ride/gone` | нельзя `gone` без `despawn` |
| `setTarget` | `(pointId, {x,y}, why)` | ставит цель, направление — к цели | цель внутри мира (§33.8) |
| `assignRoute` | `(pointId, route, edge, why)` | ведёт по маршруту, учитывает загрузку | маршрут из существующих рёбер |
| `reroute` | `(pointId, why)` | отправляет в `think` и заново выбирает | не чаще 1 раза в 5 с на точку |
| `setPriority` | `(pointId, p, why)` | вес точки в загрузке (F-27…F-30) | 0…5, служба ≥ 2.5 |
| `spawn` | `(sym, pos, why)` | создать точку | только в P0/P1, лимит §29.2 |
| `despawn` | `(pointId, why)` | убрать точку из мира | загрузка ребра пересчитывается |
| `alert` | `(kind, pos, severity, why)` | тревога (пожар, ДТП, ЧП) | приоритет по F-25 |
| `budgetAllocate` | `(projects[], limit, why)` | распределить бюджет стройки | доли по F-27, приоритеты по F-26 |
| `buildProject` | `(projectId, why)` | начать стройку (§31.6) | нужны ресурсы и рабочие (F-28) |

### 2.3. Чего у ИИ нет и не будет

- `setPosition` — координату двигает только уравнение (§33), не приказ;
- `setNeed` — потребность нельзя «подкрутить», она убывает и восполняется действиями;
- `forceArrive` — телепорт к цели;
- `setTrust` — доверие только обновляется по F-31, то есть по поступкам.

## Часть III. Законы, которые проверяются тестом

1. **Закон уравнения** — ни одна точка не двигается иначе как шагом §33 (инвариант ±1 см).
2. **Закон скорости** — `|v| ≤ vmax(sym)`, включая службы.
3. **Закон места** — нельзя в воду (`H < 0.5`), в чужое здание, за границу мира.
4. **Закон приоритета** — служба вытесняет обычных, но физику не отменяет.
5. **Закон квоты** — одновременно ≤ 64 «живых» агента в P0, остальные — боты `B` (p = 0.25).
6. **Закон обратимости** — у каждой команды есть обратная; журнал хранит 30 с.
7. **Закон объяснимости** — каждая команда несёт `why`; `E = 1` (F-38), иначе тест красный.
8. **Закон бюджета** — кадр ИИ ≤ 3 мс (F-37); при перерасходе сначала режутся дальние боты.
9. **Закон голода данных** — ИИ не решает по устаревшим данным: `ρ` старше 1 с пересчитывается.
10. **Закон 20 значений** — новая формула допускается в код только с 20 проверками (Часть V).

### 4.1. Как читать формулы

- **Доли** — всегда `[0, 1]`; если формула может выйти за диапазон, она обязана иметь `clamp`.
- **Время** — секунды; `t` в формулах памяти и убывания — игровые секунды, не кадры.
- **Стоимость** — секунды пути; сравнивать можно только величины одной размерности.
- **Выбор** — `argmax S` с ничьей по `id`, `softmax` — только для объяснения, не для решения.

## Часть V. Проверки: почему 20 значений

Правило простое: формула не попадает в ИИ, пока её не прогнали минимум 20 раз с **разными**
значениями. Одинаковые значения не считаются: 20 проверок — это 20 точек на всём диапазоне,
включая края (0, 1, максимум, отрицательные, нули в знаменателе).

`node tests/ai-formulas.mjs` проверяет для каждой формулы:

1. в реестре ровно **20 наборов** аргументов, и они различны;
2. на каждом наборе результат конечен и попадает в объявленный диапазон;
3. выполняется свойство формулы (сумма вероятностей = 1, монотонность, отсутствие деления на ноль);
4. крайние случаи ведут себя предсказуемо (`ρ = 1` не даёт бесконечность, `clamp` держит границы);
5. нет `Math.random` — формулы детерминированы;
6. документ `AI.md` содержит все 40 формул и по 20 значений на каждую (сверка с реестром).

Итого: **40 формул × 20 значений = 800 проверок** только на формулы, плюс свойства, крайние
случаи и интеграционные сценарии — 1 100+ проверок в файле.

Приложение с таблицами по каждой формуле — в конце документа.

## Часть VI. Память и объяснимость

```
decision = {
  t, agentId, cmd, args,
  why: "голоден 0.82, кафе в 240 м, окно 40 мин — успеваю",
  score: 1.24, runnerUp: 0.98,
  cost: { ms: 0.031, formulas: ["F-7", "F-8", "F-9"] }
}
```

- `why` — человеческая строка, а не код ошибки; её видно в «паспорте точки» (§33.11);
- `runnerUp` — второй по баллу вариант: если разница < 0.05, ИИ пишет «выбор на грани»;
- `formulas` — какие формулы участвовали: это нужно, чтобы объяснение не расходилось с кодом.

## Часть VII. Чего ИИ не делает

1. Не двигает точки в обход уравнения, даже если «так быстрее».
2. Не решает по случайности: ГПСЧ только там, где явно сказано (порядок обхода, шум выбора).
3. Не знает того, чего не видит: `probeArea` ограничен радиусом восприятия (F-35).
4. Не забывает мгновенно: память убывает по F-32, и старая обида может всплыть.
5. Не оптимизирует «средний балл» в ущерб безопасности: риск входит в балл с весом μ = 2.
