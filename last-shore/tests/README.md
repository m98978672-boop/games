# Проверки без браузера

Игра проверяется двумя скриптами — это дешевле, чем каждый раз открывать вкладку.

```bash
# 1. Генерация мира, рельеф, ходьба, столкновения, небо, подбор, камера
node tests/smoke.mjs

# 2. Вся игра в jsdom с заглушкой WebGL-рендерера:
#    старт, подбор (E), еда (1/2), сумка (I), пауза, автосейв, погода, смерть
npx esbuild src/main.js --bundle --format=iife --target=es2020 \
  --outfile=tests/.harness-bundle.js \
  --alias:three=./tests/three-stub.js \
  --alias:three/addons/utils/BufferGeometryUtils.js=./node_modules/three/examples/jsm/utils/BufferGeometryUtils.js
node tests/harness.mjs
```

`three-stub.js` — это настоящий Three.js, у которого `WebGLRenderer` заменён заглушкой,
чтобы логика игры работала в Node без видеокарты.

## 2.1. Живность и бой

`node tests/mobs.mjs` — звери в мире, урон по кабану, лук и стрелы, бинт, запрет готовки без костра,
переключение слотов колесом, укус кабана.

## 2.2. Шахта и кузница

`node tests/mine-forge.mjs` — два слоя под землёй, вход через арку, пробивание стены
жилы киркой и добыча, лава в глубинном слое, ковка процедурного предмета с моделью,
заточка кованого (крафтовый нож не точится), установка верстака и точила, панели.

## 2.3. Песочница механик

`node tests/sandbox.mjs` — животные смотрят по ходу движения, хитбоксы по габаритам модели,
зазор 5 см между статикой, копание слоя земли с осыпанием песка и затоплением,
креатив (F2 → F: ∞ предметы, полёт, неуязвимость), ранения по частям тела и бинт,
копание вглубь шахты и выход на поверхность.

## 2.4. Версия 0.13: слои, полёт, F9, бот

`node tests/v013.mjs` — песок/дёрн → камень → пустота шахты, вода только на пляже,
лунка со стенками и дном, полёт (Space/Shift/зависание), F9, все 17 проверок бота.
`node tests/v013-browser.mjs` — то же в настоящем браузере: бот по F8 ходит и ведёт отчёт,
F9 отпускает курсор, копание доходит до пустоты, полёт работает. Нужен сервер на :8080.

## 2.5. Версия 0.13.1: яма в блоках, трава из оттенков, F9

`node tests/v013.mjs` — яма проседает блоком ровно по сетке, стенки и дно по слоям
«земля → камень», вокруг земля цела; трава из разных оттенков (разброс яркости и насыщенности);
вода только на пляже; полёт; F9; 19 проверок бота.
`node tests/v013-browser.mjs` — то же в браузере (бот F8, F9, копание, полёт).

## 3. Реальный браузер (headless Chromium)

`node tests/browser.mjs [url]` — открывает игру в Chromium, жмёт «Начать», проверяет,
что мир собрался без ошибок, добывает дерево, крафтит инструменты, ставит костёр и делает скриншоты
(`tests/shot-*.png`).

В этой песочнице нет системных `libnspr4/libnss3`, поэтому рядом лежат заглушки в `/tmp/nssstub`
(генерируются из списка символов бинарника) и `LD_LIBRARY_PATH` подставляется в `puppeteer.launch`.
На обычной машине с браузером это не нужно.


## 3.1. Первый запуск headless в песочнице

`bash tools/setup-headless.sh` — распаковывает Chromium и собирает заглушки `libnspr4/libnss3/libnssutil3`
в `/tmp/nssstub` (один раз на новую песочницу). После этого работают `tests/browser.mjs`, `tests/covers.mjs`
и скрипты скриншотов.

## 3.2. Скриншоты и шейдеры

```bash
cd last-shore && python3 tools/serve.py 8080 &   # сервер игры
node tests/shaderlog.mjs   # ошибки компиляции шейдеров в консоли
node tests/shots.mjs       # tests/shot-fp.png, shot-forest.png, shot-night2.png
```

## 4. Устойчивость (WebGL, safe-режим, диагностика)

`node tests/robust.mjs` — три сценария в Chromium:
1. обычный запуск,
2. запуск с `?safe=1` (лёгкая графика, без сглаживания и теней),
3. браузер без WebGL — игра должна показать причину, а не молчаливое «не работает».

Плюс проверяется панель диагностики (кнопка на стартовом экране или F1 в игре).
