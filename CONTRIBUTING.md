# Вклад в Games

Спасибо, что хочешь добавить игру. Витрина статическая: после принятого Pull Request GitHub Pages опубликует новую карточку вместе с сайтом. **Прямой загрузки файлов в production через форму нет** — предложения и код проходят проверку до публикации.

Полный визуальный гид: [`developers/index.html`](developers/index.html). Для идеи без готового кода используй GitHub Issue Form **«Предложить игру»**; для готовой игры открой Pull Request.

## Как добавить браузерную игру

1. Сделай fork репозитория `m98978672-boop/games` и создай ветку.
2. Добавь в корень репозитория папку с коротким kebab-case slug, например `my-game/` (на сайте она будет по адресу `/games/my-game/`). В папке должны быть `index.html`, `cover.svg`, `README.md` и файл лицензии/разрешения на размещение. Можно начать с [`game-base/`](game-base/) и [`game-base/TEMPLATE.md`](game-base/TEMPLATE.md).
3. Добавь в `site/community-games.json` одну запись:

```json
{
  "id": "my-game",
  "title": "Название игры",
  "subtitle": "Короткая строка о жанре",
  "description": "Что делает игрок и в чём особенность игры.",
  "version": "v0.1",
  "cover": "../my-game/cover.svg",
  "play": "../my-game/index.html",
  "readme": "../my-game/README.md",
  "features": ["Первая особенность", "Вторая особенность"]
}
```

`id` должен совпадать с названием папки. В `features` можно указать не более четырёх коротких пунктов. Каталог проверяет локальные пути; внешние URL и HTML-разметка в текстовых полях не принимаются.

4. Запусти проверки из корня репозитория:

```bash
node site/tests/community-catalog.mjs
node nika-life/tests/smoke.mjs
node game-base/tests/smoke.mjs
node game-base/tests/logic.mjs
cd cloud-play && npm test
```

5. Открой Pull Request и заполни описание: что добавлено, как запустить/управлять, какие права у игры и ассетов. Запроси ревью у `@m98978672-boop`, чтобы владелец получил уведомление. GitHub Actions запустит тесты и ClamAV-сканирование изменённых файлов. Сканер ищет известные сигнатуры вредоносных файлов, но не гарантирует абсолютную безопасность; ручная проверка остаётся обязательной. После человеческой проверки и принятия PR карточка появится в каталоге сообщества на сайте.

## Требования к игре и материалам

- Игра должна запускаться в современном браузере на компьютере и телефоне без скачивания исполняемых файлов.
- Загружай только код, изображения, аудио, шрифты и другие материалы, права на которые у тебя есть. Для сторонних материалов укажи источник, лицензию и обязательную атрибуцию.
- В репозитории пока нет общей лицензии. Не предполагай, что код других игр автоматически разрешено копировать. Укажи лицензию своей игры и неэксклюзивное разрешение на её размещение в каталоге.
- Не добавляй пароли, API-ключи, приватные адреса, скрытую аналитику, вредоносный код или сетевые запросы без ясной необходимости и описания.
- Сохраняй авторство в игре и README. Не используй названия, логотипы, музыку или обложки чужих коммерческих игр без разрешения.
- Кратко опиши управление, требования и ограничения. Для онлайн-игры сообщи, какие данные передаются и какой сервер нужен.

## Помощь проекту и оплата

Можно предложить идею, тестирование, доступность, локализацию, документацию или код через Issue Form **«Предложить помощь»**. Оплата за помощь заранее не обещана: условия нужно обсудить до начала работы, и не стоит начинать её в ожидании оплаты. Публиковать собственную игру можно без вступления в команду.

Пожалуйста, не публикуй в Issues личные адреса, пароли, токены и иные секреты.

## Сообщить об ошибке и получать уведомления

Внизу сайта есть кнопка **«Сообщить об ошибке»**. Она открывает публичную GitHub Issue Form с полями для шагов воспроизведения и окружения. Новые Issues и Pull Requests можно получать по почте, если включить подписку на репозиторий; подробная настройка, включая Google Sheets, описана в [`docs/notifications.md`](docs/notifications.md).
