# PLAYBRIDGE — единый концепт установки и облачной игры

PLAYBRIDGE объединяет **два способа доступа к одной библиотеке**:

1. **Установка на свой компьютер.** Сначала можно предложить встроенную передачу файлов Steam между устройствами в одной локальной сети. Если подходящего локального источника нет — остаётся официальный CDN Steam. Собственный edge-кэш игровых файлов допустим только при соответствующих разрешениях Valve и правообладателей.
2. **Облачный запуск.** Игра запускается на удалённом GPU-сервере; игрок получает видеопоток и отправляет управление обратно. Для этого нужны игровая инфраструктура, низкая задержка, совместимый официальный клиент, поддержка конкретной игры и отдельная правовая схема.

## Открыть макет

Открой `index.html` напрямую или запусти из корня репозитория:

```bash
python3 -m http.server 8080 --bind 0.0.0.0
```

Затем открой `http://localhost:8080/cloud-play/`.

## Что работает в прототипе

- адаптивный интерактивный макет на чистом HTML/CSS/JavaScript;
- демонстрационная библиотека из четырёх вымышленных игр;
- поиск и фильтры;
- сценарий маршрута установки с LAN → официальный Steam CDN → только разрешённый партнёрский кэш;
- имитация экранов запуска облачной сессии, выбора региона и качества;
- экран объяснения подключения и приватности.

**Это только фронтенд-прототип:** Steam OpenID не настроен, список игр демонстрационный, никаких файлов не скачивается, GPU-сессия и видеопоток не запускаются. Макет намеренно не просит пароль Steam и не имитирует подтверждённую авторизацию.

## Предлагаемая архитектура реального продукта

```text
Веб/desktop-клиент
  ├─ вход: Steam OpenID → проверка ответа на backend → SteamID
  ├─ библиотека: только разрешённые Steam API/партнёрские способы; уважать privacy-настройки
  ├─ установка: локальная передача Steam в LAN или официальный Steam CDN
  │             партнёрская edge-доставка — только с письменным разрешением
  └─ облачная игра: оркестратор GPU-сессий → официальный клиент/игра → WebRTC-поток
```

- Steam OpenID подтверждает идентификатор аккаунта, но не выдаёт игровые файлы и сам по себе не гарантирует доступ к закрытому списку библиотеки.
- Не собирать и не сохранять пароль Steam. Любой реальный поток авторизации нужно проектировать по официальным требованиям Steam; секреты и проверку OpenID держать на сервере, не во фронтенде.
- Не копировать игровые депо и не строить общий CDN для контента без разрешения Valve и правообладателей. В обычном режиме Steam остаётся источником загрузки и лицензии.
- Облачный запуск требует отдельной проверки условий использования Steam и конкретных издателей, античита, способа входа в Steam-клиент, защиты сессии и очистки виртуальной машины после завершения.
- Сохранения можно считать синхронизированными только там, где это поддерживает сама игра/Steam Cloud; это не универсальная гарантия.

## Следующий реалистичный MVP

1. Уточнить, с кем можно легально интегрироваться: Steam/издатели/облачный провайдер. Без этого не подключать игровые файлы и коммерческий облачный запуск.
2. Сделать безопасный вход и лишь показывать метаданные библиотеки, которые реально разрешено получать.
3. Выпустить desktop-компаньон, который помогает найти Steam-устройство в той же LAN и объясняет, как включить встроенную передачу файлов Steam; не подменять Steam-клиент.
4. Для облачного режима сначала проверить одного партнёра и несколько разрешённых игр; добавить изолированные сессии, контроль задержки и WebRTC.
5. Лицензированный edge-кэш рассматривать отдельным поздним этапом, а не базовым источником файлов.

PLAYBRIDGE — независимый концепт и не связан с Valve или Steam.
