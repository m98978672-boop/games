# YouTube Bot — первая версия

Панель для подключения одного YouTube-канала и загрузки готовых видео с публикацией по расписанию. Она **не генерирует видео/сценарии**, не отвечает на комментарии и не является постоянно размещённым сервисом: процесс работает, пока запущен на вашем компьютере или сервере. Загруженные материалы по умолчанию отправляются на YouTube приватно с будущим временем публикации.

## 1. Создайте OAuth-клиент Google

В [Google Cloud Console → Google Auth Platform](https://console.cloud.google.com/auth/overview):

1. Убедитесь, что выбран тот Cloud project, где включён [YouTube Data API v3](https://console.cloud.google.com/apis/library/youtube.googleapis.com).
2. Заполните **Branding / App information** (название приложения и контактный адрес).
3. В **Audience** для личного тестирования выберите **External** и добавьте свой Google-аккаунт как **Test user**. Для аккаунта организации можно выбрать **Internal**, если это доступно и подходит.
4. В **Data Access** добавьте только необходимые этой версии разрешения:
   - `https://www.googleapis.com/auth/youtube.upload`
   - `https://www.googleapis.com/auth/youtube.readonly`
5. Создайте OAuth client типа **Web application**.
6. Добавьте Authorized redirect URI **в точности**:
   `http://localhost:8765/oauth2callback`
7. Скачайте JSON OAuth client. Не присылайте этот файл в чат и не добавляйте его в Git.

Официальные руководства: [настройка OAuth consent screen](https://developers.google.com/workspace/guides/configure-oauth-consent) и [OAuth для веб-серверных приложений](https://developers.google.com/identity/protocols/oauth2/web-server).

> Для первого локального теста используйте именно `localhost`, как в настройке redirect URI. При публикации бота на сервере с HTTPS нужно будет добавить фактический HTTPS callback URI в Google Cloud и настроить `PUBLIC_BASE_URL` на тот же адрес.

## 2. Запустите локально

Из каталога репозитория выполните в терминале:

```bash
cd youtube-bot
python -m venv .venv
```

Активируйте виртуальное окружение:

```bash
# Windows PowerShell
.venv\Scripts\Activate.ps1

# macOS / Linux
source .venv/bin/activate
```

Установите зависимости и задайте путь к скачанному OAuth JSON:

```bash
python -m pip install -r requirements.txt
```

Скопируйте скачанный OAuth-файл в `youtube-bot/client_secret.json`. Для дополнительного Google Cloud project ID в обычном web-client JSON ничего редактировать не нужно. Запустите сервер:

```bash
uvicorn app:app --host 127.0.0.1 --port 8765
```

Откройте в своём браузере [http://localhost:8765](http://localhost:8765), нажмите **Подключить Google / YouTube**, выберите аккаунт-владельца канала и проверьте разрешения, прежде чем нажать **Разрешить**. Вернитесь в панель и убедитесь, что показан правильный канал.

Если используете PowerShell и другой порт, сначала поменяйте порт в `PUBLIC_BASE_URL`, а затем добавьте соответствующий URI в OAuth-клиент в Cloud Console.

## 3. Запланируйте тестовую публикацию

1. Подготовьте короткое тестовое видео, на которое у вас есть права.
2. В панели заполните видеофайл, название, описание, категорию и вопрос «Для детей?».
3. Выберите время публикации хотя бы через 15 минут. Время вводится в часовом поясе браузера.
4. Нажмите **Загрузить и запланировать**. Не останавливайте сервер и не закрывайте страницу, пока большой файл передаётся.
5. Проверьте результат в списке задач и в [YouTube Studio → Контент](https://studio.youtube.com/). Убедитесь, что запланировано правильное видео и время.

Публикация по расписанию поддерживается YouTube через поле `status.publishAt`; ролик загружается приватным и должен стать публичным в заданное время. Если API вернёт ошибку — не повторяйте загрузку вслепую: сначала проверьте Studio, чтобы не создать дубликат.

## Безопасность и ограничения

- `client_secret.json`, `data/token.json`, `data/queue.json` и `data/media/` содержат конфиденциальные данные или ваши видео. Они исключены локальным `.gitignore`; не удаляйте это правило и не загружайте `data/` в публичное хранилище.
- Для временного HTTPS-предпросмотра установите длинный `APP_ACCESS_PASSWORD`: панель потребует пароль, а изменения требуют same-origin запрос. В долгоживущем развёртывании задайте и стабильный случайный `APP_SESSION_SECRET`, настройте HTTPS и резервное хранение секретов.
- Не помещайте секреты в чат, исходный код, скриншоты, `.env` в Git или публичные логи. OAuth-токен позволяет действовать в рамках выданных вами разрешений.
- На тестовой аудитории Google OAuth может потребовать повторное подключение; публичное/широкое использование может требовать дополнительных шагов в Google. Следуйте актуальным требованиям, показанным в Cloud Console.
- На случай остановки приложения оно хранит очередь локально, но сервер должен быть запущен во время загрузки файла. После загрузки YouTube хранит расписание у себя.
- Эта версия не умеет генерировать ролики, создавать канал, изменять миниатюры, модерировать комментарии или вести аналитику. В ней нет автоматического выбора тем. Эти функции требуют отдельной разработки и дополнительных разрешений.
- В панели выбран режим без ручной проверки каждой публикации: после того как вы добавите задачу, приложение автоматически отправит видео в YouTube. Сначала протестируйте на ролике, который готовы опубликовать.
