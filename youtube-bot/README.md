# YouTube Bot — первая версия

Статическая версия приложения опубликована вместе с сайтом Games: [открыть YouTube Bot](https://m98978672-boop.github.io/games/youtube-bot/). Она остаётся браузерным загрузчиком готового видео и планировщиком публикации. Облачный Actions-автопилот отдельно выпускает русскоязычные обзоры внешних игр: кандидатов и факты берёт из публичных Steam Store/Reviews API, ссылки на источники помещает в описание YouTube, а кадры Steam помечает как исходные материалы. Локальная Qwen формирует обзор; речь синтезируется локальной Russian Piper-моделью, без hosted inference API. Код проверяет готовый MP4: не ниже 1080p и 50 fps. Расписание нацелено на два Shorts ежедневно и один 3–10-минутный видеообзор ежедневно.

Для авторизации статическому сайту нужен только публичный OAuth client ID, который встроен в `index.html`; **client secret не используется и никогда не должен добавляться в Pages**. API токен остаётся в памяти вкладки.

## Настройка статической версии GitHub Pages

1. В [Google Auth Platform → Clients](https://console.cloud.google.com/auth/clients) откройте используемый Web OAuth client.
2. В **Authorized JavaScript origins** добавьте строго origin без пути:
   `https://m98978672-boop.github.io`
   Не добавляйте `/games`, `/youtube-bot/` или завершающий `/` в это поле.
3. Сохраните client, оставьте scope `youtube.upload` для браузерного загрузчика; Google-аккаунт добавьте в **Test users**, пока приложение в режиме тестирования.
4. Откройте [YouTube Bot](https://m98978672-boop.github.io/games/youtube-bot/), подключите Google и проверьте название канала.

Для этого браузерного варианта **Authorized redirect URI не используется**. Существующий redirect URI можно оставить для локальной FastAPI-версии ниже. OAuth client ID публичен; не публикуйте client secret.

## Локальная FastAPI-версия

Её можно запускать локально для другого режима интеграции. Она использует OAuth client JSON и локальный callback.

## 1. Создайте OAuth-клиент Google

В [Google Cloud Console → Google Auth Platform](https://console.cloud.google.com/auth/overview):

1. Убедитесь, что выбран тот Cloud project, где включён [YouTube Data API v3](https://console.cloud.google.com/apis/library/youtube.googleapis.com).
2. Заполните **Branding / App information** (название приложения и контактный адрес).
3. В **Audience** для личного тестирования выберите **External** и добавьте свой Google-аккаунт как **Test user**. Для аккаунта организации можно выбрать **Internal**, если это доступно и подходит.
4. В **Data Access** добавьте только необходимые этой версии разрешения:
   - `https://www.googleapis.com/auth/youtube.upload`
   - `https://www.googleapis.com/auth/youtube.readonly`
   - `https://www.googleapis.com/auth/yt-analytics.readonly` (локальный цикл оптимизации)
5. Создайте OAuth client типа **Web application**.
6. Добавьте Authorized redirect URI **в точности**:
   `http://localhost:8765/oauth2callback`
7. Скачайте JSON OAuth client. Не присылайте этот файл в чат и не добавляйте его в Git.

Официальные руководства: [настройка OAuth consent screen](https://developers.google.com/workspace/guides/configure-oauth-consent) и [OAuth для веб-серверных приложений](https://developers.google.com/identity/protocols/oauth2/web-server).

> Для первого локального теста используйте именно `localhost`, как в настройке redirect URI. При публикации бота на сервере с HTTPS нужно будет добавить фактический HTTPS callback URI в Google Cloud и настроить `PUBLIC_BASE_URL` на тот же адрес.

## 2. Запустите локально

Из каталога репозитория выполните в терминале:

```bash
cd youtube-bot
python -m venv .venv
```

Активируйте виртуальное окружение:

```bash
# Windows PowerShell
.venv\Scripts\Activate.ps1

# macOS / Linux
source .venv/bin/activate
```

Установите зависимости и задайте путь к скачанному OAuth JSON:

```bash
python -m pip install -r requirements.txt
```

Скопируйте скачанный OAuth-файл в `youtube-bot/client_secret.json`. Для дополнительного Google Cloud project ID в обычном web-client JSON ничего редактировать не нужно. Запустите сервер:

```bash
uvicorn app:app --host 127.0.0.1 --port 8765
```

Откройте в своём браузере [http://localhost:8765](http://localhost:8765), нажмите **Подключить Google / YouTube**, выберите аккаунт-владельца канала и проверьте разрешения, прежде чем нажать **Разрешить**. Вернитесь в панель и убедитесь, что показан правильный канал.

Если используете PowerShell и другой порт, сначала поменяйте порт в `PUBLIC_BASE_URL`, а затем добавьте соответствующий URI в OAuth-клиент в Cloud Console.

## 3. Запланируйте тестовую публикацию

1. Подготовьте короткое тестовое видео, на которое у вас есть права.
2. В панели заполните видеофайл, название, описание, категорию и вопрос «Для детей?».
3. Выберите время публикации хотя бы через 15 минут. Время вводится в часовом поясе браузера.
4. Нажмите **Загрузить и запланировать**. Не останавливайте сервер и не закрывайте страницу, пока большой файл передаётся.
5. Проверьте результат в списке задач и в [YouTube Studio → Контент](https://studio.youtube.com/). Убедитесь, что запланировано правильное видео и время.

Публикация по расписанию поддерживается YouTube через поле `status.publishAt`; ролик загружается приватным и должен стать публичным в заданное время. Если API вернёт ошибку — не повторяйте загрузку вслепую: сначала проверьте Studio, чтобы не создать дубликат.

## Безопасность и ограничения

- `client_secret.json`, `data/token.json`, `data/queue.json` и `data/media/` содержат конфиденциальные данные или ваши видео. Они исключены локальным `.gitignore`; не удаляйте это правило и не загружайте `data/` в публичное хранилище.
- Для временного HTTPS-предпросмотра установите длинный `APP_ACCESS_PASSWORD`: панель потребует пароль, а изменения требуют same-origin запрос. В долгоживущем развёртывании задайте и стабильный случайный `APP_SESSION_SECRET`, настройте HTTPS и резервное хранение секретов.
- Не помещайте секреты в чат, исходный код, скриншоты, `.env` в Git или публичные логи. OAuth-токен позволяет действовать в рамках выданных вами разрешений.
- На тестовой аудитории Google OAuth может потребовать повторное подключение; публичное/широкое использование может требовать дополнительных шагов в Google. Следуйте актуальным требованиям, показанным в Cloud Console.
- На случай остановки приложения оно хранит очередь локально, но сервер должен быть запущен во время загрузки файла. После загрузки YouTube хранит расписание у себя.
- Статический сайт не генерирует ролики и не ведёт аналитику. Отдельная команда `autopilot.py` ниже — старый локальный мульт-пилот; облачный Steam-обзорный pipeline описан в следующем разделе.
- В панели выбран режим без ручной проверки каждой публикации: после того как вы добавите задачу, приложение автоматически отправит видео в YouTube. Сначала протестируйте на ролике, который готовы опубликовать.

## Экспериментальный автономный цикл (локально)

Для полноценного цикла с озвучкой нужны Python-зависимости из `requirements.txt`, системный `espeak-ng` и шрифт DejaVu Sans. FFmpeg берётся из системы или пакета `imageio-ffmpeg`. В OAuth-токене должны быть разрешения YouTube upload/read и YouTube Analytics read. После добавления Analytics scope переподключите Google в локальной панели, чтобы выдать обновлённое согласие. Видео учитываются в оптимизаторе только если у них есть тег `bot-topic:<topic-id>`; посторонние ролики канала не смешиваются с пилотными данными. Комментарии читаются только для грубого подсчёта запросов в памяти, исходный текст и имена авторов не сохраняются и не передаются Qwen.

Проверить именно рендеринг без OAuth, скачивания модели и системного eSpeak можно командой из `youtube-bot`:

```bash
python autopilot.py --demo
```

Она делает 15-секундный **немой** мульт-ролик с речевыми облачками и сохраняет MP4 в `data/episodes/demo-short.mp4`; это тест рендера, не результат генерации Qwen.

Для настоящего цикла с подключёнными Google API и локальной Qwen запустите из `youtube-bot`:

```bash
python autopilot.py
```

Цикл пишет `data/episodes/<id>/script.json`, `short.mp4` и `result.json`. По умолчанию результат остаётся `rendered_review_required`; автоматическая загрузка выключена. Для явного включения владельцем задайте `AUTOPILOT_AUTO_PUBLISH=true`, `YOUTUBE_MADE_FOR_KIDS=true` или `false` (не угадывайте классификацию аудитории) и `AUTOPILOT_PUBLISH_AT` — ISO-8601 дату со смещением, минимум за 15 минут в будущем. Тогда валидированный ролик попадёт в локальную очередь существующего uploader, будет загружен приватным и запланирован YouTube на заданное время. Сам цикл не работает постоянно: его запуск по расписанию должен обеспечить владелец на постоянно работающем сервере. Не выкладывайте `data/`, OAuth JSON или токены в GitHub.

## Автопилот игровых Shorts в GitHub Actions

Shorts workflow запускается дважды в сутки; отдельный long-form workflow создаёт один 3–10-минутный обзор ежедневно. Оба формата берут игры из публичных Steam Store/Reviews API на русском языке, пропуская игры без русскоязычного описания. Локальная Qwen выбирает факты и пишет текст; локальная Piper-модель `ru_RU-irina-medium` озвучивает русский текст. В описание YouTube добавляются копируемые ссылки на страницу игры и сводку Steam. Скриншоты берутся со страницы Steam и обозначаются как исходный материал; видео не выдаётся за личное прохождение. MP4 проходит проверку ffprobe: 1080p и минимум 50 fps, Shorts — вертикальные, длинные выпуски — 16:9. Загрузка идёт напрямую из runner через YouTube resumable API; MP4 не проксируется через Supabase Edge Function.

- Аудитория канала по явному выбору владельца установлена в `false` («не предназначено преимущественно для детей»). Это значение используется и для расписания, и как значение по умолчанию ручного запуска; ввод `true` остаётся явным переопределением. Переменная GitHub `YOUTUBE_MADE_FOR_KIDS` больше не нужна.
- Runner проходит OIDC-проверку, просит Supabase зарезервировать слот публикации и получает короткоживущий OAuth access token только с правом YouTube upload. Он маскируется и не печатается в журнал. Refresh token остаётся зашифрованным в Supabase.
- Сетевой фильтр разрешает только фиксированные HTTPS endpoints Supabase, GitHub Actions OIDC endpoints на поддоменах `actions.githubusercontent.com` и проверенный Google resumable-upload host/path. Redirect с bearer-токенами запрещены; runner token не отправляется на посторонний host.
- Видео отправляется кусками по 256 КиБ. При тайм-ауте или временных ответах `429/5xx` клиент сначала спрашивает у YouTube подтверждённый offset и продолжает с него; он не повторяет вслепую уже принятые байты. Повторы ограничены и используют backoff.
- Для одного времени публикации действует уникальная бронь в базе. Если результат неоднозначен, задача остаётся заблокированной от дублирующей загрузки; сначала проверяются задача и YouTube Studio.
- Qwen выбирает игру только из полученной Steam-выборки; фактические плюсы/платформы/релиз/сводка отзывов привязаны к ID источника. Неподтверждённые сведения не подставляются из каталога Games.
- Для Shorts озвучиваемые реплики должны содержать русскую кириллицу; Steam-кандидаты без достаточно русского описания пропускаются. В Actions используется локальная Piper-модель; неверный/английский текст блокируется до записи аудио.
- Кадры рендерятся с интерполяцией 25→50 fps и проверяются через ffprobe; публикация останавливается, если итоговый MP4 ниже 1080p/50 fps. Long-form сценарий — 10 глав, минимум 3 минуты и только с привязкой к источникам.
- Источники добавляются в описание ролика обычными HTTPS-ссылками, которые зритель может скопировать; API-публикация комментариев не требуется.

## Размещение backend для настоящего сайта

GitHub Pages остаётся фронтендом; отдельная OAuth/загрузка функция развёртывается в подключённом Supabase-проекте. Она хранит только зашифрованный refresh token в закрытой таблице и после согласия Google отправляет демонстрационный ролик как **private**. Для реального OAuth добавьте в Google Auth Platform → Clients в используемый Web client этот Authorized redirect URI:

```text
https://cuhfnzgytndyntpbnbda.supabase.co/functions/v1/youtube-bot/oauth/callback
```

Это не Arena preview. Публичный сайт содержит кнопку автономного приватного теста; опубликованная страница обновится после слияния PR. Удаление OAuth-доступа доступно через Google Account → Security → Third-party connections.

## Игровой автопилот: быстрый слой рефлексов

Модель Qwen осталась «медленным советником», а кадры разбирает отдельный быстрый слой: восприятие 800×600 укладывается в 300 мс (замер: p95 ≈ 8 мс, в 2.7–3.6 раза быстрее первого варианта, `benchmark_reflex.py --compare`), решение — в 2 с, найденные кнопки превращаются в точки клика, а удачные связки «экран → действие» кэшируются в SQLite. Профили ввода покрывают клавиатуру, стрелки и экранный d-pad, а пейсер действий держит движение непрерывным: пока слой думает, в мост уже отправлена очередная пачка нажатий, окно сокращается при зависаниях кадра и растёт при запасе. Живой прогон на настоящем Docker-мосте — `.github/workflows/reflex-live-smoke.yml`: два прохода, пошаговый и настоящий real-time, где модель считает в отдельном потоке, а ввод продолжается (`paused_during_inference: false`). Подробности и ограничения — в [INSTRUCTIONS_RU.md](./INSTRUCTIONS_RU.md#быстрый-слой-рефлексов-видеть-за-030-с-думать-до-2-с).

```bash
cd youtube-bot
python -m gameplay.reflex_cli bench      # скорость восприятия на этой машине
python -m gameplay.reflex_cli skills     # что уже выучено
python -m gameplay.reflex_cli budget     # контракт по времени
python -m gameplay.reflex_cli model      # карта экранов, выученная агентом
```

Поверх скорости добавлено понимание: `screen_recognizer.py` относит кадр к типу `menu / gameplay / text / quiet`, `tracker.py` ведёт объекты по предсказанной позиции и считает упреждение, а `world_model.py` хранит карту «экран + действие → экран» и планирует маршрут к неизученному экрану. Цена — около `0.03 мс` на тик, польза измерима: на синтетической игре из 60 экранов планировщик доходит до 80 % экранов за 77 шагов против 123 у случайного перебора.
