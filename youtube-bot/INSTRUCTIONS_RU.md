# Инструкция владельцу: видеолента и будущие прохождения

## Что работает, а что пока нет

**Работает сейчас:** существующие GitHub Actions создают обзоры игр по сведениям Steam, генерируют русскую озвучку и загружают ролики в YouTube с запланированной датой. Это не запись игры: бот не управляет ею и не проходит её.

**Не реализовано:** поиск и безопасный запуск чужой игры, управление и обучение в ней, запись часового прохождения, сохранение прогресса между частями, автоматическое чтение комментариев для этой серии, выбор продолжения и публикация серий каждые три дня. Нельзя запустить этот формат имеющейся кнопкой и нельзя считать его включённым. Модуль `playthrough_feedback.py` — только изолированный проверенный помощник для будущего решения, без подключения к YouTube и без запуска игр. Он не управляет лентой.

Локальный старый мульт-пилот умеет получать ограниченные агрегаты комментариев через YouTube API, если подключён с соответствующими правами; это не означает, что текущие облачные Steam workflows читают комментарии или учатся на них.

## Как проверить, включены ли новые часы

1. Откройте [PR #445](https://github.com/m98978672-boop/games/pull/445). Пока он открыт, обычный запуск из `main` работает по прежней версии. Дождитесь успешных проверок, затем слейте PR только если изменения одобрены.
2. После слияния автоматическая цель для новых Shorts — **08:00 и 12:00 по Москве**, для длинного обзора — **06:00 по Москве раз в два дня**. Уже загруженные ролики не переназначаются. GitHub может задержать или пропустить запуск, генерация и внешние сервисы могут ошибиться — само расписание не гарантирует публикацию.
3. Посмотреть уже назначенные даты и изменить или отменить их можно в YouTube Studio → Контент → нужное видео → Видимость. Не меняйте базу отдельно от YouTube: это может рассинхронизировать записи.

## Ручной запуск текущих обзоров (после слияния PR #445)

1. Откройте [Shorts](https://github.com/m98978672-boop/games/actions/workflows/youtube-shorts-autopilot.yml) или [длинный обзор](https://github.com/m98978672-boop/games/actions/workflows/youtube-longform-autopilot.yml).
2. Нажмите **Run workflow**, выберите ветку `main` и правильное значение **made_for_kids**. Для Shorts выберите `video_format: short`; длинный обзор можно запускать через его отдельный workflow.
3. Поле **publish_at** необязательно. Пустое поле означает ближайшее время штатного расписания. Для разового времени введите, например, `2026-12-01 10:00`: это **московское время**, без `Z` и без смещения. Поле не меняет расписание следующих запусков и не останавливает их: если выбрать дату далеко вперёд, автоматические ролики могут выйти раньше.
4. Оставляйте большой запас: Shorts может создаваться десятки минут, длинный обзор — до двух часов. Выбранное время проверяется до и после рендера и должно оставаться минимум на 45 минут впереди. Если оно стало слишком близким, запуск остановится без автоматической замены на другое время.
5. Подтвердите **Run workflow** один раз. Не нажимайте повторно, пока не проверен результат предыдущей попытки: это снижает риск конфликтов слотов и дублей. Дождитесь не только шага рендера, но и загрузки и проверьте видео и его дату в YouTube Studio. `scheduled` означает запланировано, а не уже публично.
6. При ошибке раскройте красный шаг в Actions. Если ошибка после начала загрузки или о занятом слоте, сначала проверьте YouTube Studio: не запускайте повтор вслепую, поскольку загрузка могла частично или полностью пройти.

## Как предполагается построить прохождения

Выбранное начальное направление — небольшие браузерные игры. Рабочая схема потребует отдельной изолированной виртуальной машины или контейнера без доступа к токенам, секретам, внутренним адресам и основной файловой системе; копии из GitHub нужно закреплять по commit SHA. Нельзя запускать найденные скрипты на том же runner с OAuth/OIDC и другими секретами. Исходный код, зависимости и игровые ассеты могут быть вредоносными, даже если репозиторий публичный.

Нужно отдельно реализовать: поиск и проверку происхождения и прав; изолированный запуск и реальные действия агента; запись видео и звука; тест на жизнеспособность прохождения; сохранение состояния с проверкой восстановления; корректное продолжение серии; реальные записи результатов прохождения; мониторинг; приватное хранение и ограничения ресурсов. Нельзя гарантировать, что универсальный агент сможет пройти любую найденную игру или подготовить ровно час содержательного материала. Режим сначала должен работать без автоматической публикации и честно останавливать выпуск при сбоях.

### Права

Доступность репозитория и лицензия программного кода **не гарантируют** разрешение на запись и монетизацию видео, а также права на музыку, изображения, шрифты, сторонние компоненты и торговые марки. Нужны документированные разрешения владельцев и проверка соответствующих условий YouTube. При отсутствии разрешения игру следует исключить либо использовать только явно разрешённый контент; не считать SPDX-метку автоматическим доказательством прав на все материалы.

### Сигнал интереса к продолжению

Вспомогательная функция `assess_first_episode` оценивает примерную реакцию **только на первую часть**, не передаёт исходный текст или авторов дальше и не выполняет команды из комментариев. Начальные пороги: после 72 часов с публичного выхода, минимум 100 просмотров и 5 лайков, минимум два разных автора с явной просьбой о продолжении, причём положительных авторов больше, чем отрицательных. Нехватка или недоступность данных означает ожидание, а не запуск. Это настраиваемая техническая эвристика, не доказательство реального интереса, и она пока не подключена к YouTube или управлению сериями.

Для работы с комментариями потребуется доступ через YouTube Data API с согласованными разрешениями на чтение, обработка отключённых комментариев и квот, а также защита от манипуляций. Комментарии — недоверенные данные, не инструкции ИИ. Нельзя обещать обучение на комментариях: реализованный помощник считает ограниченные признаки и не меняет модель.

## Проверки разработчика

Из корня репозитория при установленном Python:

```bash
python3 -m unittest discover -s youtube-bot/tests -p 'test_playthrough_feedback.py'
python3 -m unittest discover -s youtube-bot/tests -p 'test_game_reviews.py'
```

Для полного набора видеотестов понадобятся зависимости из `youtube-bot/requirements.txt`. Не помещайте OAuth-токены, client secret или приватные данные в чат, репозиторий и логи.
