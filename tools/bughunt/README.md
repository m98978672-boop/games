# 🤖 Бот-багоискатель

Бот обходит **весь репозиторий** — все 25 проектов — и складывает находки в отчёт:
`report.md` для человека, `report.json` для машины (или для меня, когда нужно
раздать находки на исправление).

Ни одной зависимости: только Node 22 и файлы репозитория.

```bash
node tools/bughunt/bughunt.mjs               # полный прогон: статика + игры + тесты
node tools/bughunt/bughunt.mjs --static      # только чтение файлов, ~30 с
node tools/bughunt/bughunt.mjs --only 1in8b  # один проект
node tools/bughunt/bughunt.mjs --codes       # таблица кодов 000–999
node tools/bughunt/bughunt.mjs --code 400    # одна сотня кодов
node tools/bughunt/tests/selftest.mjs        # проверить самого бота
```

Код выхода `1`, если нашлось что-то важнее мелочи (порог меняется `--fail-on`).

## Таблица кодов 000–999

У каждой находки есть номер: по нему видно и категорию, и что именно сломалось.
Сотня — подсистема, внутри сотни 0–19 — именованные проверки (**у большинства
есть живой детектор**), 20–99 — слоты аудита «аспект × типичный дефект»:
их либо закрывает точечный тест проекта, либо они ждут своей очереди.

## Что он делает

### 1. Читает код (всегда)

| Правило | Что ищет |
|---|---|
| `синтаксис` | файл не компилируется (`node --check` для модулей, `vm.Script` для браузерных) |
| `ссылка` / `ссылка-md` | `src`/`href`/`url()`/`@import`/ссылка в Markdown ведёт на несуществующий файл |
| `дубль-id` | один и тот же `id` в разметке дважды — `getElementById` найдёт только первый |
| `нет-узла` | код ищет `#что-то`, чего нет ни в разметке, ни среди создаваемых узлов |
| `кириллица-в-коде` | в одном имени смешаны кириллица и латиница (`стaрт` с русской «а») |
| `json-разбор` / `дубль-ключа` / `нечисло-в-json` | данные не читаются или ключ задан дважды — часть данных теряется |
| `внешний-запрос` | игра из каталога тянет что-то из сети, хотя обязана работать офлайн |
| `дубль-функции` | функция объявлена дважды в одной области видимости |
| `присваивание-в-условии` | `if (x = 1)` вместо `if (x === 1)` |
| `сравнение-с-NaN` | `x === NaN` — всегда ложь |
| `случайность-без-зерна` | `Math.random()` в игре со своим генератором по зерну: повтор и сохранение разойдутся |
| `пустой-catch`, `разбор-без-защиты`, `хранилище-без-защиты` | ошибки глотаются молча; `JSON.parse` и `localStorage` без `try` |
| `отладчик` | забытый `debugger` |
| `файл-не-подключён`, `тяжёлый-файл`, `разметка` | мёртвые файлы, многомегабайтные ассеты, непарные теги, нет `viewport` |

| `тавтология`, `самоприсваивание`, `alert`, `отладочный-лог` | сравнение и присваивание «сам с собой», модальные окна, незакрытая отладка |
| `секреты`, `eval`, `внешний-скрипт`, `noopener` | ключи и токены в дереве, исполнение строки как кода, сторонний скрипт |
| `ассет-из-кода`, `двойник-ассета`, `манифест-ассет` | картинка или звук, на который ссылается код, отсутствует; два одинаковых файла |
| `workflow-шаг`, `тест-в-ci`, `код-выхода-теста`, `тест-only` | CI — это тоже часть игры: шаг в никуда, тест, который никто не запускает, провал, посчитанный успехом |
| `дубль-id-данных`, `регистр-ключа`, `число-строкой` | данные, которые молча перекрывают друг друга |

Чужие собранные библиотеки (`*.bundle.js`, `*.min.js`, `three`, `vendor`)
проверяются только на синтаксис и ссылки: придираться к минификации бессмысленно.

### 2. Играет в игры (`--play`)

`lib/dom.mjs` — мини-браузер на ~400 строк: `document`, элементы, события,
`canvas`, звук, `localStorage`, кадры анимации, таймеры, `<select>` со
значением по умолчанию. Бот грузит `index.html` проекта, выполняет его
скрипты, прокручивает кадры, **нажимает все кнопки**, жмёт клавиши
(WASD, стрелки, пробел, Esc, цифры), двигает мышь и колесо, прокручивает
ещё сотню кадров — и записывает каждое падение с файлом и строкой.

После прогона бот обходит состояние игры и ищет `NaN` и `Infinity`:
нечисло в расчётах всегда расползается дальше.

Чего мини-браузер не умеет (WebGL, Web Audio в полном объёме, воркеры),
он честно записывает в раздел «боту не хватило заглушек» — это не баги игр.
Если во время загрузки заглушек не хватило, последующие падения бот
понижает до «важно» с пометкой «проверить вручную».

### 3. Запускает тесты проектов (`--tests`)

Находит `tests/*.mjs` каждой игры, запускает их с таймаутом и собирает
падения: номер теста, первая строка с ✗ и команда для повтора.
Тесты, которым нужен настоящий браузер, видеокарта или `npm i`
(`browser`, `render`, `shot`, `perf`, `view`…), помечаются как пропущенные.
Если у игры есть свой играющий бот (`tests/bot.mjs`, как у `1in8b`),
он запускается отдельно и с запасом жизней.

## Отчёт

```
tools/bughunt/report.md     таблица по важности, находки по проектам, свод по правилам
tools/bughunt/report.json   то же самое машиночитаемо: находки, заглушки, пропущенное
```

Находки делятся на три уровня:

- 🔴 **критично** — игра сломается у игрока (не компилируется, падает, битая ссылка);
- 🟡 **важно** — очень похоже на ошибку, надо посмотреть;
- ⚪ **мелочь** — так жить можно, но лучше поправить.

Повторы одного правила в одном файле сворачиваются: в отчёте остаётся
три штуки и строка «и ещё находки того же правила».

## Самопроверка

`tools/bughunt/tests/selftest.mjs` собирает в песочнице две игры.
В первой нарочно сделаны девять ошибок — бот обязан найти каждую.
Вторая написана в стиле репозитория: русские имена функций и ключей,
регулярки с кириллицей, шаблонные строки, собранная чужая библиотека,
проверенный на `null` узел, свой генератор по зерну — здесь бот обязан
промолчать. Так ловится и слепота бота, и его придирчивость.

```bash
node tools/bughunt/tests/selftest.mjs
```

## Флаги

| Флаг | Что делает |
|---|---|
| *(без флага)* | полный прогон: статика + запуск игр + тесты проектов |
| `--static` | только чтение файлов, ~30 с |
| `--codes`, `--code 412` | напечатать таблицу кодов и выйти |
| `--fail-on критично\|важно\|мелочь` | порог, при котором прогон считается провальным |
| `--play` | статика + запуск игр |
| `--tests` | статика + тесты проектов |
| `--only <проект>` | проверить одну папку, например `--only 1in8b` |
| `--level критично\|важно\|мелочь` | что показывать и что считать провалом |
| `--lives <N>` | сколько жизней просить у играющих ботов игр |
| `--test-timeout <с>` | сколько ждать один тест (по умолчанию 300) |
| `--out <путь>` | куда писать отчёт (по умолчанию `tools/bughunt/report`) |
| `--quiet` | только отчёт, без подробностей в консоли |

## Как добавить своё правило

Правила живут в `lib/rules.mjs`. Правило — это функция
`(root, project) => находки[]`, где находка:

```js
{ rule: 'моё-правило', severity: 'важно', project: p.name,
  file: 'игра/src/код.js', line: 42,
  msg: 'что не так', hint: 'что с этим делать' }
```

Готовую функцию добавьте в список `STATIC_RULES` внизу файла и допишите
проверку в `tests/selftest.mjs`: подсадная игра должна её ловить,
честная — нет.
