# 🧲 Games Torrent — настоящая P2P-раздача игр в браузере

Вкладка **«Торрент»** на витрине Games (`../index.html` → «🧲 Торрент») и отдельная
страница [`index.html`](./index.html).

Это не имитация: у каждой игры есть отпечаток раздачи (`info_hash`), «торрент-файл»
со списком файлов и хешами кусков, magnet-ссылка, обмен кусками между браузерами по
WebRTC и проверка каждого куска по SHA-256. Сервер — свой: трекер, сигналинг и
резервный сид в одном процессе.

```
┌─────────────┐   WebRTC DataChannel    ┌─────────────┐
│ браузер A   │ ◄─────────────────────► │ браузер B   │
│ (раздаёт)   │   куски + проверка      │ (качает)    │
└──────┬──────┘   sha256 по .torrent     └──────┬──────┘
       │                                       │
       └──────────►  свой сервер  ◄────────────┘
                 трекер · сигналинг · резервный сид
```

## Быстрый старт (свой сервер)

```bash
node tools/p2p-server/server.mjs
# → API трекера:     http://localhost:8787/api/p2p
# → Вкладка «Торрент»: http://localhost:8787/torrent/
# → Витрина:          http://localhost:8787/
```

Сервер раздаёт и сам сайт, поэтому играть и качать можно целиком на своём
компьютере без GitHub — интернет не нужен.

Нужен доступ с другого устройства? Посмотрите адрес «В сети» в выводе сервера
(например `http://192.168.1.10:8787/`) или впишите его во вкладке в поле
**«Свой сервер»** — адрес запомнится.

## Как это работает

| Шаг | Что происходит |
|---|---|
| 1 | `tools/torrent/build-catalog.mjs` обходит папки игр, гоняет **автоудаление плохих файлов**, считает sha256 каждого файла и собирает `site/torrent-catalog.json` с `info_hash` |
| 2 | Вкладка читает каталог и находит сервер (`shared/p2p/config.js`): свой на этом хосте, сохранённый, из `?p2p=` или публичный |
| 3 | Перед загрузкой берётся `.torrent` (`/torrent/<gameId>.torrent`) — в нём хеши **каждого куска** |
| 4 | Куски качаются у пиров по WebRTC, а если их нет — у резервного сида (`/chunk/<gameId>/<i>`) |
| 5 | Каждый кусок сверяется по SHA-256: несовпадение — кусок отбрасывается |
| 6 | Из кусков собираются файлы **бит-в-бит**, затем каждый файл проходит автоудаление вредоносного |
| 7 | Чистый набор упаковывается в один HTML — игра открывается двойным щелчком. Скачанное раздаётся дальше (вы становитесь сидом) |

Если сервера нет (например, на GitHub Pages) вкладка честно работает через
**HTTPS-сид**: файлы идут напрямую с хостинга, но автоочистка и проверка файлов
работают так же. Режим всегда виден в интерфейсе: «пиры», «сервер» или «HTTPS».

## Автоудаление плохих файлов

`shared/p2p/sanitize.js` решает судьбу каждого файла:

* **block** — удалить: исполняемые `.exe/.bat/.ps1/.dll/.apk/.sh`, майнеры
  (`stratum+tcp://`, Coinhive, cryptonight), похитители ключей (`seed_phrase`,
  `private_key`), обфусцированный автозапуск, скрипты PowerShell;
* **strip** — почистить: мета-редирект, `<base>`-подмена, скрытый iframe,
  BiDi-символы;
* **allow** — оставить: `.js/.mjs/.wasm/.json/.html/.css/.png/.jpg/.webp/.glb/.ogg/.mp3`
  и сохранения.

**Игровые файлы не удаляются никогда** — это проверяется тестом
`tools/torrent/test.mjs` на всех 16 играх: каждая собирается из кусков бит-в-бит,
и автоочистка не отнимает ни одного нужного файла.

Два важных предохранителя, найденных тестами:

1. Бинарные файлы (EXR/PNG/звук) не декодируются как текст — иначе случайные байты
   выглядели как «BiDi-символы», а «очистка» меняла размер файла
   (`dawn.exr`: 182 КБ → 329 КБ, игра ломалась).
2. Слово `stratum` в математике (гауссов шум в шейдерах) **не** считается майнером:
   ловятся только настоящие пулы вида `stratum+tcp://host:port`.

## Тесты

```bash
node tools/torrent/test.mjs        # каталог ↔ диск ↔ куски, сборка, автоочистка
node tools/p2p-server/test.mjs     # трекер, сигналинг, .torrent, Range, защита путей
node site/tests/portal.mjs         # вкладка подключена к витрине
```

Оба первых теста входят в `.github/workflows/validate.yml`.

## Безопасность сервера

* отдаются только файлы из каталога раздач (белый список путей);
* выход за папку игры и за корень сайта закрыт (`..`, `%2e%2e`, абсолютные пути);
* служебные файлы (`tools/`, `.github/`, `package.json`, скрипты) наружу не отдаются;
* сигналы и куски ограничены по размеру и проверяются на допустимые значения.
