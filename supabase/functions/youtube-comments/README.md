# Comment OAuth foundation — NOT deployed or scheduled

This isolated function requests `youtube.force-ssl` for reading and posting comments. It deliberately uses a **different Web OAuth client and encryption key** from the upload function. It never calls the uploader or modifies its token tables. It checks that the authorized channel owns the independently verified public anchor video before storing an encrypted refresh token in its separate service-role-only table. If the anchor is unavailable, it fails closed. Confirm the anchor and permissions again before deployment.

The OAuth callback is `https://cuhfnzgytndyntpbnbda.supabase.co/functions/v1/youtube-comments/oauth/callback`. A separate Google Web client must register that exact redirect. The deployment would require these Supabase environment variables: `YOUTUBE_COMMENTS_CLIENT_ID`, `YOUTUBE_COMMENTS_CLIENT_SECRET`, `YOUTUBE_COMMENTS_ENCRYPTION_KEY` (64 hex characters, independently generated random bytes). Do not put values in Git, logs, issues or chat. The service role key and URL are standard Supabase runtime environment variables.

**Not yet deployed or enabled.** The separate scheduled workflow `youtube-comments-autopilot.yml` requests a short-lived token through an OIDC-verified worker endpoint, passes bounded comment samples to local Qwen, and uses only fixed safe replies for a few simple reactions. The database reservation is atomic, permanent on uncertainty, and capped at 20 attempts per channel per UTC day; the runner sends at most 5 per run. AI-generated text is never auto-posted and summaries are not saved or printed. The worker is disabled unless both the GitHub repository variable and the Supabase secret `YOUTUBE_COMMENTS_AUTO_ENABLED` are set to `true`; turn either off to stop future cycles. An in-flight request may still complete. Never use the local SQLite reply ledger in ephemeral cloud runners.

Before enabling: add upstream IP-based rate limiting to the public OAuth start route (the database caps outstanding states globally but can still be denial-of-serviced), deploy and configure the separate client/key, verify Google scope/owner and redirect, exercise real OAuth and YouTube permissions, verify OIDC from the exact main-branch workflow, and test the end-to-end worker in a no-post mode before enabling either switch. Three isolated migrations were applied to Supabase. RLS and privileges were checked; duplicate, daily-cap and outstanding-state-cap behavior were tested inside rolled-back transactions, but concurrent reservation behavior has not been tested live. No real consent or post has been tested. Monitor API errors and quota without logging sensitive data.

Run offline mocked tests: `node youtube-bot/tests/test-comments-oauth.mjs`.
